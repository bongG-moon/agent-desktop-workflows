1새 폴더에 전체 압축을 풉니다

Windows용 ZIP을 회사에서 허용한, 동기화되지 않는 로컬 디스크의 새 폴더에 풉니다. 기존 CUA 또는 Agent Desktop Local 폴더를 덮어쓰지 마세요. ZIP 안에서 바로 실행하거나 EXE만 따로 옮기지 않습니다.

agent-desktop-workflows
├─ Start.cmd               ← 녹화/편집 화면 시작
├─ SKILL.md                ← Claude Code에 읽힐 스킬
├─ 사용가이드.html
├─ bin
│  └─ agent-desktop.exe    ← 이전과 동일한 실행 엔진 1개
├─ scripts
│  ├─ cli.py               ← 작업 단위 명령
│  ├─ py_helper.py         ← Python 도우미 시작점
│  ├─ win_bridge.py        ← 창 조회와 영역 입력
│  └─ recorder.py          ← Python 녹화 화면
└─ references
Main의 Download ZIP 또는 소스 ZIP을 사용하는 경우

소스 ZIP에는 agent-desktop.exe가 없습니다. 이전에 받은 Agent Desktop Local 0.2.0의 bin/agent-desktop.exe를 새 제품 폴더의 같은 위치로 직접 복사하세요. 이전 폴더는 그대로 두면 됩니다. 자체 도우미를 추가로 빌드할 필요는 없습니다.

복사한 파일의 SHA-256이 UPSTREAM.json의 binary_sha256과 일치하는지 확인합니다. 일반 요소를 실행할 때도 프로그램이 해당 해시를 검사합니다. 이 제품은 기존 설치나 설정을 자동 검색하지 않으며 새 실행 파일을 생성하거나 내려받지 않습니다.

Start.cmd를 더블클릭하면 작업 화면을 엽니다. Python을 찾지 못하거나 tkinter가 없으면 설치 확인 안내가 표시됩니다.

Python 준비 상태를 직접 확인하려면

탐색기에서 이 폴더를 열고 주소창에 powershell을 입력합니다.

python --version
python -c "import struct, tkinter; print('Python bits:', struct.calcsize('P') * 8); print('Tk:', tkinter.TkVersion)"

Python 비트 수는 64여야 합니다. Python이 경로에 없다면 회사에서 승인한 python.exe의 전체 경로를 사용합니다. 도구가 자동 설치나 회사 보안 정책 변경을 수행하지는 않습니다.

기본 작업 저장소는 %LOCALAPPDATA%\AgentDesktopWorkflows입니다. 이 제품의 녹화 원본, 수정본과 실행 기록을 보관하며 기존 CUA 저장소와 공유하지 않습니다.

Windows 10 1809 이상 x64의 현재 사용자 세션을 사용합니다. Python과 tkinter는 ZIP에 포함하지 않습니다. 회사 정책에서 실행 파일이 차단되면 우회하지 말고 승인된 실행 환경을 확인하세요.

2대상 창을 선택하고 업무를 녹화합니다

01업무 창 선택
02새 작업 녹화
03직접 시연
04단계 검토/저장
  1. 실제로 사용할 FX 업무 화면을 열어 둡니다.
  2. 위쪽 대상 업무 창 목록에서 창 제목과 실행파일을 확인합니다. 같은 앱의 여러 업무 창을 구분하세요.
  3. 새 작업 녹화를 누릅니다. 별도 녹화창에서 시작을 누른 뒤 평소처럼 직접 업무를 수행합니다.
  4. 조건 선택, 조회, 표 우클릭과 메뉴 선택을 순서대로 수행합니다. 녹화창에 현재 단계의 인식 상태가 표시됩니다.
  5. 녹화를 마치면 작업 화면으로 가져옵니다. 이름을 정하고 보완 표시가 있는 단계를 확인합니다.
녹화는 실제 동작을 기록합니다. 녹화 중 사용자가 누른 조회/저장/내보내기는 실제 앱에 적용됩니다. ‘인식되지 않음’은 그 동작이 실행되지 않았다는 뜻이 아니라, 이후 자동 재생을 위한 근거가 부족하다는 뜻입니다.

녹화 도우미는 녹화하는 동안만 동작을 기록합니다. 다른 앱의 키 입력이나 비밀번호를 작업 입력값으로 수집하지 않으며, 기록할 수 없는 입력은 보완이 필요한 단계로 남깁니다.

3인식되지 않은 부분을 바로 확인합니다

단계마다 대상 인식, 조작 방식, 결과 확인을 따로 봅니다. 요소 후보가 잡혔다는 것과 재생에 성공했다는 것은 다릅니다. 아래는 상태 안내의 예시입니다.

녹화 단계 — 안내 예시
1Family 변경요소 후보 확인값 설정 후 현재 값 확인
2조회 버튼 클릭버튼 후보 확인조회 완료 조건 지정 필요
3표 우클릭조작 ref 없음녹화 영역 재확인 또는 수동 보완
4Export 메뉴메뉴 인식 미확인이 단계 다시 녹화 또는 직접 수행

표의 영역은 보이지만 엔진의 ref가 없을 수 있습니다. 이 경우 녹화한 표 컨테이너와 현재 영역을 다시 찾는 지역 입력 경로를 사용합니다. 아무 창의 중앙이나 과거의 전역 좌표를 대신 클릭하지 않습니다.

영역 기준 단계는 단계 수정에서 기록한 대상 영역과 내부 위치를 확인하고 확인란을 체크해 저장하세요. 검토되지 않은 영역은 입력을 보내지 않고 멈춥니다. 확인한 이후에도 실행 시 현재 창과 영역의 일치 여부를 다시 검사합니다.

특정 행을 조작하려면 현재 행 키와 선택 상태가 확인되어야 합니다. 표 영역에 우클릭할 수 있다는 사실이 같은 행/셀을 찾아낼 수 있다는 뜻은 아닙니다.

콤보 목록은 선택한 업무 창과의 관계와 실제 선택 근거를 확인해 값으로 기록합니다. 부모 값이 비어 있으면 선택된 항목이나 하위 편집기 값을 확인하며, 읽을 수 없으면 요소 확인 / 선택값 보완 필요로 남깁니다. 제출 전 값을 확인할 시간이 없었던 단계도 임의로 채우지 않습니다. 콤보 값 보완 안내를 확인하세요.

4전체를 반복하지 않고 한 단계만 보완합니다

버튼할 수 있는 일
단계 수정단계 이름, 동작, 입력 변수와 완료 조건을 바꿉니다.
이 단계 다시 녹화필요한 부분만 짧게 시연하고, 방금 녹화한 단계 중 하나로 선택 단계를 교체합니다. 단계 ID는 유지합니다.
직접 수행 단계로 전환자동 인식 근거가 부족한 단계를 수동으로 남깁니다. 실행할 때 이 지점에서 멈춥니다.
수정본으로 이어하기실행되지 않은 실패 단계를 보완한 뒤 새 수정본으로 이어갑니다. 이미 전달됐을 수 있는 동작은 다시 실행하지 않습니다.

변경은 새 수정본으로 저장하며 이전 녹화와 원본은 보존합니다. 보완 녹화 자체도 별도 작업과 원문으로 남습니다. 진행 중인 실행은 시작 당시 수정본을 유지합니다.

이전 버전에서 콤보 선택이나 입력 동작이 누락된 기록은 업데이트만으로 복원되지 않습니다. 기존 작업을 열어 해당 단계를 확인하고 이 단계 다시 녹화로 보완하세요.

조건값을 입력 변수로 만들기

예를 들어 Family 단계의 입력 변수 이름에 Family, 기본값에 Hybrid를 넣습니다. Status 단계에는 Status와 N을 지정합니다. 그러면 작업 화면 위쪽에서 실행할 때마다 값만 바꿀 수 있습니다.

입력 변수를 쓰는 ‘현재 값 일치’ 조건은 해당 실행에 전달한 값을 따릅니다. 표시 이름과 내부 코드가 다르면 현재 관찰된 의미를 확인해야 합니다.

입력 변수를 사용하는 값 설정 단계는 실행 시 변수값을 확인합니다. 그 외에는 입력값을 완료 기대값으로 사용을 체크하면 동작 입력값을 확인합니다. 체크하지 않으면 기대값 입력란을 그대로 사용합니다. 빈칸도 명시적인 빈 문자열이므로 입력 지우기 이후의 빈 상태를 확인할 수 있습니다.

5작업 이름과 조건으로 실행합니다

UI에서는 대상 창과 변수 값을 확인하고 작업 실행을 누릅니다. Claude Code에서는 이 제품의 SKILL.md 전체 경로를 알려 준 뒤 요청합니다.

과거 실행 기록을 보고 있을 때는 새 작업 실행이 비활성화됩니다. 최신 수정본 보기로 전환해 단계와 입력 조건을 확인한 뒤 실행하세요. 표시된 수정본이 실행 직전에 바뀌면 입력을 보내기 전에 멈춥니다.

아래 경로의 Agent Desktop Workflows 0.1.4 SKILL.md를 읽고 따라 줘.
D:\LocalTools\agent-desktop-workflows\SKILL.md

저장한 ‘Device 조회 후 Excel 내보내기’를 Family=Hybrid, Status=N으로 실행해 줘. 대상 업무 창을 먼저 확인하고, 결과가 불명확한 단계는 멈춰서 알려 줘.

경로는 실제 설치 위치로 바꿉니다. 사내 모델이 로컬 파일과 명령을 실행할 수 있는 Claude Code 환경이어야 합니다. 채팅 전용 모델에 ZIP을 첨부하는 것만으로 PC 실행 도구가 생기지는 않습니다.

프로젝트 스킬로 등록하려면

프로젝트의 .claude/skills/agent-desktop-workflows/에 제품 폴더 내용 전체를 복사합니다. 최종 경로가 .claude/skills/agent-desktop-workflows/SKILL.md가 되게 합니다. 새 대화에서 /agent-desktop-workflows를 호출할 수 있습니다.

기존 CUA 스킬이나 개인 Claude 설정을 덮어쓰지 않습니다. 스킬 설치 방식은 Claude Code 공식 문서를 따릅니다.

이전 agent-desktop-local과 다른 제품입니다. 녹화와 작업 단위 실행을 요청할 때는 agent-desktop-workflows의 새 경로를 사용하세요. 모델 주소, API 키, MCP와 전역 권한을 이 제품 때문에 바꿀 필요는 없습니다.

실행기는 각 단계 직전에 현재 요소를 다시 찾습니다. 모델이 ref를 복사하거나 120초 안에 명령을 조립하지 않아도 됩니다. 이미 요청한 작업의 클릭마다 기계적으로 다시 허락을 요구하지 않지만, 기존 Claude Code 도구 권한과 회사 정책은 그대로 적용됩니다.

Excel 내보내기는 메뉴가 닫힌 것보다 새 출력 파일이나 Workbook과 요청한 범위가 확인되어야 합니다. 활성 시트 전체와 선택 범위는 다를 수 있으며, 상단 Excel 버튼과 우클릭 메뉴가 같은 결과라고 가정하지 않습니다.

‘전달 확인 후 계속’은 다음 단계로 진행하기 위한 조건입니다. 업무 결과를 확인했다는 뜻이 아닙니다. 조회/저장/내보내기 완료를 확인해야 하는 지점에는 실제 조건 또는 사람 확인을 지정하세요.

7멈춘 부분부터 이어갑니다

일시정지 / 중단은 이미 전달된 입력을 되돌리지 않습니다. 결과를 모르는 상태에서 처음부터 새 실행을 시작하면 같은 저장이나 내보내기가 반복될 수 있습니다.

  1. 실행 기록 / 이어하기에서 중단된 실행을 선택합니다.
  2. 현재 화면과 단계 결과를 확인합니다. 자동 재확인으로 이어갈 수 있으면 그 상태로 진행합니다.
  3. 해당 단계를 직접 처리했거나 결과를 직접 확인했다면 현재 단계 직접 확인 후 계속을 선택합니다. 이 단계의 입력은 반복하지 않습니다.
  4. 아직 실행되지 않은 단계의 인식만 잘못됐다면 단계 보완 후 수정본으로 이어하기를 사용합니다. 완료한 앞부분의 의미가 바뀌거나 입력 여부가 불확실하면 자동으로 진행하지 않습니다.

사람 확인은 실제 확인이 필요한 단계에서만 받습니다. 모델이 사용자의 확인을 추정하거나 미확인 상태를 성공으로 바꿔서는 안 됩니다.

8파일과 실행 환경은 로컬에 유지합니다

이 제품은 외부 모델/API, JEV, 원격 로그, 자동 업데이트, npm 설치와 상시 감시 서비스를 포함하지 않습니다. 기존 CUA 파일, 계정, 모델 설정과 보안 정책을 변경하지 않습니다. 기존 실행 엔진과 Python 녹화 도우미가 회사에서 승인한 사용자 세션에서 동작합니다.

0.1.4도 자체 도우미 EXE 없이 Python 소스로 동작합니다. 실행 중 EXE/DLL을 빌드하거나 다운로드하지 않으며 Python 표준 라이브러리로 Windows 기본 API를 호출합니다. 녹화와 지역 입력의 기능은 유지하므로 회사의 Python 실행 및 입력 관찰 정책은 그대로 적용됩니다. 다운로드 차단 해제를 보장하는 변경은 아닙니다.

녹화와 실행 기록에는 창 제목, 입력값과 업무 화면 구조가 포함될 수 있습니다. 저장소 전체를 업무 자료로 취급하고, 회사가 승인한 사내 모델 환경에서만 읽으세요. OS 네트워크 차단 도구는 아니며 호스트 모델의 전송 경로와 폴더 동기화 정책은 별도 관리 대상입니다.

실제 회사 FX/FxMenuAgent, 컨트롤 버전과 DPI별 동작은 현장 검증이 필요합니다. 합성 화면에서의 검사를 실제 업무 인수 시험으로 표현하지 않습니다. 메뉴나 셀을 현재 읽을 수 없으면 해당 단계의 한계를 표시하며, 회사 보안 정책을 우회하지 않습니다.

처음 실행할 때 자주 확인할 부분
  • 화면이 열리지 않음: Start.cmd의 Python/tkinter 안내를 확인합니다. 승인된 Python 경로로 scripts/cli.py ui를 실행할 수 있습니다.
  • 목록에 업무 창이 없음: 실제 앱이 현재 사용자 세션에 열려 있는지 확인하고 창 새로고침을 누릅니다.
  • 녹화된 단계가 미인식: 해당 단계만 다시 녹화하거나 수동 단계로 남깁니다. 단순히 녹화 시간이 길다고 해결되지는 않습니다.
  • 영역 우클릭이 차단됨: 대상 창의 복원/전경/가림과 현재 영역을 확인합니다. 임의 좌표로 대체하지 않습니다.
  • 계속 읽기 전용이라고 답함: 이전 Agent Desktop Local 스킬을 읽고 있지 않은지 확인하고 새 제품의 전체 경로를 명시합니다.
  • 실행이 회사 정책에 의해 차단됨: UAC, 백신, 방화벽과 관리자 권한을 임의로 변경하지 않습니다.

9FX 실습: 녹화부터 Claude Code 실행까지

처음 한 번은 UI에서 업무를 녹화하고 단계를 검토합니다. 이후에는 Claude Code에 저장한 작업 이름과 조건만 요청합니다. 아래 예시는 Family=Hybrid, Status=N으로 조회한 뒤 표를 우클릭해 EXPORT → EXPORT TO EXCEL을 실행하는 흐름입니다.

실제 회사 FX는 아직 현장 검증하지 않았습니다. 메뉴 이름, 저장 대화상자와 완료 신호는 현재 FX 화면에서 확인하세요. 처음에는 조회 결과를 사람이 확인하는 흐름으로 시작합니다.

① 프로그램과 FX를 준비합니다

  1. 0.1.4 Windows x64 ZIP 전체를 새 로컬 폴더에 풀고 Start.cmd를 실행합니다. 64비트 Python 3.10 이상과 tkinter가 필요하며 CUA Driver는 필요하지 않습니다. 소스 ZIP을 받았다면 1번의 실행 엔진 복사 안내를 먼저 확인합니다.
  2. FX에 로그인하고 Family와 Status가 있는 업무 화면을 엽니다. 창은 최소화하지 않고 복원해 둡니다.
  3. Workflows의 대상 업무 창에서 현재 업무 화면의 제목과 실행파일을 확인해 선택합니다. 다른 FX 화면과 구분하세요.

② 실제 업무를 한 번 녹화합니다

새 작업 녹화 → 녹화 시작을 누르고 아래 순서대로 직접 조작합니다. 각 동작이 화면에 반영된 것을 확인한 뒤 다음 동작을 진행하세요.

  1. Family 콤보를 열고 Hybrid를 선택합니다.
  2. Status 콤보를 열고 N을 선택합니다.
  3. 조회를 누르고 결과가 나타난 것을 확인합니다.
  4. 조회된 표의 데이터 영역에서 우클릭합니다.
  5. EXPORT → EXPORT TO EXCEL을 선택합니다.
  6. FX가 저장 대화상자를 띄우면 필요한 경로와 저장 동작까지 수행하고, 각 단계가 녹화됐는지 확인합니다. 별도 Excel 창만 열린다면 결과를 확인하고 녹화를 마칩니다.
  7. 녹화창의 마치고 검토를 누릅니다.
값이 이미 Hybrid/N이어도 녹화할 때는 콤보를 열고 해당 값을 명시적으로 다시 선택하세요. 녹화 중 수행한 조회와 내보내기는 실제 앱에 이미 적용됩니다. 조회 결과를 기다린 시간 자체가 자동 대기 조건으로 저장되지는 않습니다.

대상 콤보가 맞는데 값만 비었다면 아래 보완 절차로 실제 값을 지정합니다. 대상 자체가 다르게 잡혔다면 이 단계 다시 녹화로 실제 대상을 보완합니다. 표 우클릭의 영역 확인은 사용자가 화면과 대조해 수행해야 하며 Claude Code에 확인란을 대신 체크하도록 요청하지 않습니다.

표 영역 우클릭을 인식했다고 특정 행이나 내보내기 범위까지 확인된 것은 아닙니다. 메뉴나 저장 대화상자가 미인식 단계로 남았으면 그 단계를 보완하거나 직접 수행 단계로 설정합니다. 단계 자체가 없으면 필요한 흐름을 포함해 새로 녹화합니다. 이 단계 다시 녹화는 기존 한 단계를 대체하며 없는 단계를 추가하는 기능은 아닙니다.

콤보 이름은 맞는데 선택값이 비어 있다면

0.1.3까지의 녹화에서는 gcboStatus나 gcboFamily라는 대상은 찾았어도, 부모 값이 항상 비어 있는 커스텀 콤보를 set-value ""로 저장할 수 있었습니다. 0.1.4는 실제 선택 근거를 확인하고, 없으면 대상 이름을 유지한 보완 단계로 남깁니다. 기존에 저장된 빈 값은 업데이트만으로 N이나 Hybrid로 복원되지 않습니다.

  1. 작업을 선택해 최신 수정본 보기로 현재 수정본을 확인합니다.
  2. 실제 Status 콤보의 단계 수정에서 동작 set-value, 입력 변수 이름 Status, 값 / 변수 기본값 N, 완료 조건 value로 정하고 새 수정본 저장을 누릅니다.
  3. 실제 Family 콤보도 같은 방법으로 입력 변수 이름 Family, 기본값 Hybrid를 지정합니다. 녹화 순서에 따라 단계 번호가 다를 수 있으므로 대상 이름으로 구분하세요.
  4. 이전 실행이 있다면 먼저 입력 전달 여부를 확인합니다. 입력하지 않은 단계는 보완한 수정본으로 이어갈 수 있습니다. 이미 전달됐거나 불명확한 단계는 현재 결과부터 확인하고, 조회나 내보내기를 처음부터 반복하지 않습니다.
{Status}나 {Family}를 값 칸에 쓰지 마세요. 이 제품은 그 문자열을 변수로 치환하지 않습니다. 변수 이름과 실제 기본값을 각각의 칸에 입력합니다. 입력 변수를 지정하면 이번 실행의 변수값으로 완료 여부를 확인하므로 추가 확인란은 필수가 아닙니다.

콤보 값이 비어 있으면 편집 저장과 실행 전에 보완 안내가 표시됩니다. 일반 텍스트 입력창을 의도적으로 비우는 동작은 계속 사용할 수 있습니다. 콤보 목록의 항목을 다시 클릭해 녹화해도 부모 콤보 값으로 합쳐질 수 있으므로, 같은 조작의 재녹화만으로 값 판독 문제가 해결되지는 않습니다.

실제 값을 지정한 뒤에도 반영되지 않으면 실행 기록의 선택값 확인 결과를 보세요. 설정 호출이 성공해도 실제 선택값이 다르거나 읽히지 않으면 멈추며 자동 반복하지 않습니다. 값 미관찰을 빈 값과 같다고 판정하지 않습니다. 이 보완은 모든 FX 커스텀 콤보의 자동 실행을 보장하지 않으므로 첫 실행에서 화면 결과를 확인하세요.

④ Excel 내보내기의 실제 결과에 맞춰 완료 조건을 정합니다

현재 FX의 동작권장 설정
실제 파일을 저장함파일을 만드는 최종 단계의 완료 조건을 file로 지정합니다. 기대값 또는 출력 파일에는 실제 로컬 전체 경로를 입력합니다. 예: D:\FX_Export\device_result.xlsx. 예시 경로를 그대로 쓰지 말고 FX에서 저장하는 경로와 맞추세요.
저장 대화상자가 추가됨경로 입력과 저장 단계가 제대로 녹화됐는지 확인합니다. EXPORT TO EXCEL의 조건은 none, 경로 값 설정 단계는 value, 실제 마지막 저장 단계는 file 또는 manual로 둡니다. 메뉴를 누른 직후부터 아직 저장하지 않은 파일을 기다리지 않도록 합니다. 대화상자가 미인식 단계로 남으면 직접 수행 단계로 보완하고, 단계 자체가 빠졌다면 필요한 흐름을 포함해 다시 녹화합니다.
별도 Excel 창만 열림내보내기 단계의 완료 조건은 manual로 둡니다. 사용자가 Excel의 내용과 범위를 확인하고, 필요하면 직접 저장합니다. 별도 Excel 프로세스의 조작은 FX 창에 묶인 녹화 범위 밖입니다.

file 조건은 파일의 새 생성 또는 변경을 확인합니다. 파일 내용이나 내보낸 범위까지 검증하지는 않습니다. 마지막 결과까지 모두 none으로 두고 업무 완료로 해석하지 마세요. 중간 메뉴에 none이 있으면 마지막 파일 확인에 성공해도 전체 상태는 completed_unverified일 수 있으므로 단계별 결과를 확인합니다.

⑤ UI에서 처음 한 번 실행해 확인합니다

  1. FX를 녹화 시작 때와 같은 업무 화면에 둡니다. 이전 실행 기록을 보고 있다면 최신 수정본 보기로 전환합니다.
  2. 저장한 작업을 선택하고 입력 변수 Family=Hybrid, Status=N을 확인한 뒤 작업 실행을 누릅니다. 물리 입력 중에는 마우스나 키보드를 함께 조작하지 않습니다.
  3. 조회 단계에서 확인 대기로 멈추면 FX의 실제 조회 결과를 확인합니다. 완료됐다면 현재 단계 직접 확인 후 계속을 누릅니다. 조회 버튼은 다시 누르지 않습니다.
  4. 표 우클릭과 메뉴 선택이 이어지는지 확인합니다. Excel 단계가 사람 확인이면 내보낸 내용과 범위를 확인한 뒤 같은 버튼으로 이어갑니다.
  5. 실행 기록에서 어느 단계가 자동 확인됐고 어느 단계가 사람 확인인지 확인합니다. 인식 문제가 있으면 해당 단계만 보완합니다.

전달 여부가 불명확하거나 중단됐다면 처음부터 새 실행을 시작하지 말고 실행 기록 / 이어하기에서 현재 결과를 먼저 확인하세요. 자동화가 이미 누른 조회나 내보내기를 반복하지 않도록 합니다.
