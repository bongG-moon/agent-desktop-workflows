# 회사 PC에서 시작하기

Windows x64와 64비트 Python 3.10 이상이 필요합니다. 녹화 창에는 Python의 Tkinter가 필요합니다. **0.4.10에서는 목록의 버튼을 일반 녹화하거나 행 순번을 문장으로 지정할 수 있습니다.** 녹화 중에는 기록된 단계와 인식 상태를 확인하고, 검토 화면에서는 실제로 실행할 문장을 수정합니다. `--background-only`를 선택하면 도구가 물리 입력과 창 전면화를 제한합니다. 제한 모드에서는 UIA의 자동 포커스도 끄고 설정값을 확인합니다. 기존 Python 실행안의 조회, 결과 표 우클릭, 내보내기 창, Excel 파일 확인은 유지합니다. 처음 위치와 동작을 정리해 등록하면 다음부터는 선택값과 입력값만 바꿔 실행할 수 있습니다. 이름 없는 입력란도 실제 상위 영역과 상대 위치로 찾을 수 있습니다. 0.4.0 기반 실행과 프로젝트별 저장은 유지합니다. ZIP에는 소스와 문서만 있고 추가 EXE나 CUA 드라이버는 없습니다. 0.5/0.6의 intent 형식 작업은 이 버전에서 변환하거나 실행하지 않으며 해당 버전으로 사용해야 합니다.

0.4.21은 기존 실행 경로를 유지하면서 새 녹화에서 빠지던 입력값, Enter, 목록 선택과 새 창 연결을 보완한 버전입니다. 추가 모델이나 백그라운드 서비스, 의존 프로그램 설치는 필요하지 않습니다. DBeaver에서 처음 녹화한 9단계를 수작업으로 고치지 않고 등록해 12.439초에 실행했고, 우클릭 위치 보정은 다음 실행에도 유지됐습니다. 실행 전 읽기 검사는 한 번입니다. 다만 첫 녹화 대상 포착은 9.225초가 걸려 개선 여지가 남아 있습니다. 실제 Claude Code CLI 및 회사 FX 시험과는 구분하며, [검증 범위와 단계별 실측](https://github.com/bongG-moon/agent-desktop-workflows/blob/main/docs/desktop-select-0421-validation.md)에서 확인할 수 있습니다.

### 등록한 업무를 한 번에 실행하기

이미 등록한 업무는 AX Workspace 또는 Claude Code에 **“/device-setup-export 실행해줘”**라고 요청하세요. 필수 변수로 등록했다면 “Family는 Hybrid로”처럼 이번 값도 말해 주세요. 실제 마우스가 필요한 업무에서는 호스트가 어느 창에서 무슨 동작을 할지 알립니다. 현재 요청이나 앞선 대화에서 해당 실행을 승인했다면 다시 묻지 않고 이어가며, 승인이 없을 때만 한 번 묻습니다. 접근성으로 처리할 수 있는 업무는 바로 실행합니다.

실행할 때는 아래 명령 하나를 사용합니다. 실행기가 첫 입력 전에 Windows 접근성 API(UIA)로 대상 창의 최상위 요소를 한 번 읽습니다. 읽을 수 있으면 같은 호출에서 업무를 이어가고, 실패하면 첫 입력 전에 멈춥니다. 창 목록 조회, 전체 단계의 `--read-only` 점검, `--input-plan`, 수동 전면화는 따로 실행할 필요가 없습니다.

```powershell
python -X utf8 -B .claude/skills/device-setup-export/scripts/run.py --summary
```

이번 실행의 실제 입력을 승인했다면 호스트가 같은 명령에 `--allow-physical`을 붙입니다. 승인하지 않으면 마우스나 키보드가 필요한 등록 업무는 시작하지 않습니다. 이 옵션은 다음 실행에 자동으로 이어지지 않습니다.

`readability_check.status`는 실행 직전의 창 확인 결과입니다. `scope=window_root`는 확인 범위가 업무 창의 최상위 요소였다는 뜻입니다. 조회 버튼이나 메뉴는 해당 단계에서 확인하며, 각 동작의 결과는 `steps`에 남습니다.

종료 코드 0과 `outcome=workbook_verified`는 마지막 단계에서 새로 생성되거나 변경된 통합 문서를 확인했다는 뜻입니다. 경로는 `verified_outputs`에 표시됩니다. 파일 내용의 정확성은 별도 검토 대상입니다. 전달만 확인한 실행은 종료 코드 3을 유지하므로 같은 입력을 반복하지 마세요.

**기존 업무 스킬의 안내를 갱신하려면** 본체 ZIP을 교체한 뒤 프로젝트 폴더에서 다음 명령을 한 번 실행하세요. 0.4.17에서 등록한 업무 스킬도 공유 엔진을 사용합니다. 이 명령은 녹화 원본, 실행안, 변수, 사용자 설명을 유지하면서 실행 안내를 갱신합니다. 휴대용 설치에서는 첫 경로의 `.claude/skills/desktop-select`를 `desktop-select`로 바꾸세요.

```powershell
python -X utf8 -B .claude/skills/desktop-select/scripts/python_workflow.py refresh-guide --skill .claude/skills/device-setup-export
```

**처음 실행안을 만들 때** `register` 한 번으로 현재 대상도 검사합니다. 표 우클릭 다음 문장이 “Export to excel > Active sheet버튼 눌러줘”처럼 경로 전체를 담고 있으면 `recover`가 알려주는 메뉴 경로와 단계를 확인하고 연결하세요. 파일 위치를 모르면 `python_workflow.py discover-output --exe "<파일명.exe>" --window "<창 제목>"`으로 앱 설치 위치 주변의 로컬 폴더 후보를 확인하세요. 후보 경로는 실행안의 `output`에 저장하고, 첫 실행에서 실제 새 통합 문서가 생성됐는지 확인합니다. 기존 실행안에 경로가 있으면 바로 사용합니다. 드라이브 전체를 검색할 필요가 없습니다.

### 새 프로젝트에 처음 설치하기

다음 절차로 설치한 뒤 여러 창을 오가는 작업은 아래의 **관리창과 기기창을 한 작업으로 녹화하기**를 따라 하세요.

1. FX 운영용 또는 시험용으로 사용할 프로젝트 폴더를 정하고 Claude Code에서 그 폴더를 여세요. 서로 분리할 업무는 서로 다른 프로젝트 폴더를 사용합니다.
2. Windows ZIP을 풀고 `desktop-select` 폴더 전체를 프로젝트의 `.claude/skills/` 바로 아래에 복사하세요. 별도의 전역 설치나 저장 방식 선택 질문 없이 프로젝트별 저장이 기본으로 적용됩니다.
3. 프로젝트 폴더의 PowerShell에서 아래 명령으로 실제 저장 위치를 확인하세요. 경로만 확인하며 아직 녹화 폴더를 만들지는 않습니다.

```powershell
python -X utf8 -B .claude/skills/desktop-select/scripts/desktop_select.py storage
```

4. Claude Code에 “desktop-select로 이 업무 창을 녹화해 줘”라고 요청하면 됩니다. 저장할 때 필요한 데이터 폴더가 만들어집니다.

ZIP을 프로젝트 바로 아래의 `desktop-select` 폴더에 풀어 휴대용으로 쓰는 경우, 첫 요청에서 AX Workspace나 Claude Code에 **“이 폴더의 desktop-select/SKILL.md를 읽고, 방금 녹화한 작업을 실행해 줘”**라고 알려 주세요. 등록 절차와 화면을 읽는 방법은 ZIP 안의 그 파일에 있습니다. 프로젝트별로 별도 `CLAUDE.md`를 작성할 필요는 없습니다.

### 녹화창 열기

AX Workspace나 Claude Code에 **“이 창에서 새 작업을 녹화해 줘”**라고 요청하세요. 0.4.22부터 호스트는 작업명과 정확한 창 제목을 JSON 파일로 전달합니다. “녹화창이 열렸습니다”라는 안내가 오면 창에서 **시작**을 누르세요. 저장하거나 취소하면 같은 실행에서 최종 결과가 나옵니다.

다음은 프로젝트 폴더에서 실행하는 PowerShell 스크립트(`.ps1`) 예제입니다. Windows PowerShell 5.1에서 한글 예제를 저장할 때는 UTF-8 BOM을 선택하세요. `exe`와 `window`에는 실제 실행 파일명과 창 제목 전체를 넣습니다. 같은 제목의 창이 여러 개면 선택한 창의 숫자 `hwnd`도 넣습니다.

```powershell
$ErrorActionPreference = 'Stop'
$scriptPath = (Resolve-Path -LiteralPath '.claude/skills/desktop-select/scripts/desktop_select.py').Path
$request = @{ command = 'record'; task = '조건 조회'; exe = 'Example.exe'; window = '업무 창 "시험" [A & B]' }
$requestFile = [IO.Path]::GetTempFileName()
try {
    [IO.File]::WriteAllText($requestFile, ($request | ConvertTo-Json -Compress), [Text.Encoding]::UTF8)
    & python -X utf8 -B $scriptPath recorder --request $requestFile
    $recorderExit = $LASTEXITCODE
} finally {
    Remove-Item -LiteralPath $requestFile
}
exit $recorderExit
```

녹화창이 표시되면 `recorder_ready`가 한 줄 출력되고, 저장이나 취소 후 최종 JSON이 출력됩니다. 먼저 종료됐다면 최종 응답의 `diagnostic` 또는 표준 오류를 확인하세요. 기존 `record` 직접 명령은 종료할 때 최종 JSON 한 건을 출력합니다.

### 저장한 녹화 이어서 실행하기

0.4.21에서는 이름 없는 입력란도 고유한 상위 영역과 그 안의 상대 위치, 입력값을 함께 기록합니다. 같은 입력란에서 Enter로 적용한 동작은 별도 적용 단계로 남습니다. 목록에서 고른 파일 형식과 그 뒤에 열린 창도 같은 녹화 순서에 포함됩니다.

예를 들어 DBeaver에서 필터 입력 → Enter → 결과 표 우클릭 → Export data → XLSX 선택 → Next → Directory 입력 → Proceed 순서로 시연한 뒤 저장하세요. AX Workspace 또는 Claude Code에 **“방금 녹화한 대로 실행 시험하고, 보정이 필요하면 현재 화면에서 고친 뒤 반복할 업무 스킬로 정리해 줘”**라고 요청하면 됩니다. 이름을 읽을 수 있는 항목은 설명 초안을 자동으로 붙입니다. 고정값이나 실행 시 받을 값은 검토 화면에서 정할 수 있습니다.

호스트는 저장 응답의 작업 이름과 실행안을 먼저 사용합니다. 실행안이 준비됐으면 그 작업을 등록하고 같은 등록 스킬로 첫 시험을 진행합니다. 시연 후 닫힌 내보내기 창은 해당 단계에서 다시 열리면 확인합니다. 검증된 보정 위치는 등록한 실행안에 저장합니다. 값이나 목적이 이미 기록돼 있으면 다시 묻지 않고, 현재 화면에서도 구별되지 않는 대상이나 아직 받지 않은 변수만 확인합니다.

**사용자가 할 일**은 평소 순서대로 시연하고 단계 옆에 원하는 동작을 적는 것입니다. ‘결과 표를 우클릭’, ‘Export to excel 누르기’, ‘Active sheet 선택’처럼 나눠 적어도 됩니다. 저장 후 **“방금 녹화를 그대로 테스트하고, 잘 된 위치를 다음 실행에도 써 줘”**라고 요청하세요. 위치나 바인딩 파일을 직접 작성할 필요가 없습니다.

**호스트의 첫 실행 절차**

1. 저장 응답에 준비된 실행용 작업이 있으면 그대로 씁니다. 이전 버전 녹화라면 `python -X utf8 -B scripts/desktop_select.py recover --task "FX 업무 녹화" --prepare --save-as "FX 조회 내보내기"`를 호출합니다. 녹화 원본과 단계 설명이 보존됩니다.
2. 실행용 사본이 준비되면 그 이름으로 `python_workflow.py register --task "FX 조회 내보내기" --out <프로젝트의 새 업무 스킬 폴더>`를 실행합니다. 같은 업무가 이미 등록돼 있으면 해당 스킬에서 시험합니다. 창과 실제 입력 범위를 설명하고 승인받은 뒤 등록된 스킬의 `scripts/run.py --summary --allow-physical`을 사용합니다.
3. 메뉴 두 항목을 실제 팝업에서 순서대로 선택했는지 영수증을 확인합니다. 파일 확인 단계도 등록한 경우 새 Excel 파일 경로까지 보고합니다. 일반 실행마다 전체 사전 검사를 반복할 필요가 없습니다.

### 첫 시험에서 우클릭 위치를 보정할 때

표를 찾은 것과 녹화한 지점이 지금도 데이터 셀에 닿는 것은 별도로 확인합니다. ‘결과 표에서 우클릭’은 같은 표 안의 확인된 데이터 셀로 보정할 수 있습니다. 특정 행이나 셀을 지정한 업무에서는 해당 대상의 의미를 유지해야 합니다.

표는 보이지만 지점에 다른 요소가 있으면, 실행기는 우클릭을 보내기 전에 멈출 수 있습니다. 응답에 `menu_repair.ticket`이 있는 경우 호스트가 아래 순서로 이어갑니다. 이때 이미 전달된 조회를 반복하지 않습니다.

1. 해당 표를 로컬로 캡처하고 실제 마우스로 메뉴를 선택하는 범위까지 이번 실행에서 승인받았는지 확인합니다. 승인이 필요하면 **“결과 표 화면을 확인한 뒤 실제 마우스로 우클릭해 내보내겠습니다. 잠시 마우스와 키보드 사용을 멈춰 주실 수 있나요?”**라고 묻고 답을 기다립니다.
2. 등록 업무의 `scripts/run.py --repair-frame <티켓> --allow-physical`로 현재 이미지와 프레임 식별자를 받습니다. 호스트가 그 이미지에서 지시와 맞는 데이터 셀을 찾습니다.
3. `scripts/run.py --resume-menu <티켓> --frame <프레임> --point X Y --allow-physical --summary`로 이어갑니다. 좌표는 반환된 이미지의 왼쪽 위가 기준입니다. 변수를 사용한 실행은 같은 값을 전달합니다. 성공한 위치가 해당 업무의 `workflow.json`에 반영되면 다음 실행이 이를 읽습니다. 메뉴 전달이 불확실한 경우에는 열린 메뉴 또는 산출물을 먼저 확인합니다.

이미 우클릭을 보낸 뒤 다음 메뉴 이름을 찾지 못하면 `menu_recovery.remaining_items`를 확인하세요. 이름이 빈 메뉴는 같은 항목의 다른 접근성 이름과 표시 텍스트도 대조합니다. 글자가 픽셀로만 그려져 식별할 수 없는 경우에는 현재 열린 팝업과 남은 항목을 보고합니다. 이 경우에는 같은 표를 다시 우클릭하지 않습니다.

### 자동 준비에 남은 단계가 있을 때

평소처럼 시연하고 단계에 원하는 일을 적으세요. 예를 들어 **“MES Setup에 'N'을 선택해줘”**, **“Family에 입력받은 변수를 넣어줘”**, **“조회 버튼을 누르고 5초 기다려줘”**, **“결과 표를 우클릭해 Export to excel에서 Active sheet를 선택해줘”**라고 적을 수 있습니다. 고정값을 원하면 **“Family에 'Hybrid'를 선택해줘”**라고 적으세요.

AX Workspace 또는 Claude Code에 **“방금 녹화한 설명과 현재 FX 화면을 확인해서 실행안을 완성해 줘”**라고 요청하세요. 실제 실행도 원하면 **“Family는 Hybrid로 해서 녹화한 경로 그대로 실행해 줘”**라고 하세요. 호스트는 초기 설정이나 파일을 직접 고치는 대신 다음 명령을 사용합니다. 아래 예시는 스킬 폴더에서 실행합니다.

1. `python -X utf8 -B scripts/desktop_select.py recover --task "FX 업무 녹화"`로 입력 없이 현재 창을 관찰합니다. 각 단계의 원문, 현재 컨트롤, 표시 라벨과 ID, 보이는 소유 팝업을 대조합니다. 녹화 결과에 이미 `live_recovery`가 있고 화면이 같으면 그 관찰을 사용합니다.
2. 이전 녹화에 우클릭 위치까지 빠졌으면 `recover --task "FX 업무 녹화" --only 4 --image`로 해당 창의 현재 이미지를 확인합니다. 화면을 직접 읽어 데이터 셀 위치를 이미지 기준으로 고릅니다. 역할이 `group`인 표도 연결할 수 있습니다. 새 녹화에서 상대 위치를 확보했으면 그 위치를 현재 표에서 다시 확인합니다.
3. 호스트는 관찰 응답의 `bindings_template`을 로컬 JSON의 초안으로 사용합니다. 여기에는 현재 창에서 한 곳으로 식별되고 원문에서 고정값이나 변수, 버튼 동작을 확인할 수 있었던 항목이 들어갑니다. 각 `target`과 `argument`를 단계별 원문 및 `live_scopes`와 대조하고, 필요한 대기와 메뉴 경로를 보완합니다. 아래 ID와 프레임, 좌표는 예시입니다. `source_fingerprint`는 방금 읽은 원본을 가리키며 `through`는 메뉴 경로에 포함할 마지막 원본 단계입니다.

```json
{
  "source_fingerprint": "<recover 결과값>",
  "steps": [
    {"number": 1, "mode": "fixed", "target": "statusCombo", "role": "combobox", "argument": "N"},
    {"number": 2, "mode": "required", "target": "familyCombo", "role": "combobox", "argument": "Family"},
    {"number": 3, "mode": "recorded", "target": "queryButton", "role": "button", "wait_after": 5},
    {"number": 4, "through": 6, "mode": "context-menu", "target": "resultGrid", "role": "group",
     "frame": "<4단계 이미지 영수증>", "point": [220, 310], "path": ["Export to excel", "Active sheet"]}
  ]
}
```

4. `recover --task "FX 업무 녹화" --bindings bindings.json --save-as "FX 조회 내보내기"`로 대상을 다시 관찰해 별도 작업으로 저장합니다. 녹화 위치가 있으면 메뉴 연결의 `frame`과 `point`를 생략할 수 있습니다. `source_steps`에서 원본 단계가 어떻게 합쳐졌는지 확인하세요. `execution_plan.status`가 `saved`이고 실행을 요청받았다면 호스트가 새 이름으로 재생합니다. 고정값과 필수 변수를 유지하므로 다음 실행에는 같은 Family 변수에 다른 값을 줄 수 있습니다.
5. 사용자가 추가 시연을 원하면 `continue-recording --task "FX 업무 녹화" --from-step 4`로 기존 1~3단계를 보존한 보완 녹화를 엽니다. 추가 녹화를 이미 저장했다면 같은 명령에 `--supplement "FX 업무 녹화 - 내보내기 보완"`을 붙여 다시 시연하지 않고 합칩니다. 원본과 보완 녹화는 각각 유지됩니다.

메뉴 전달 후 통합 문서 생성까지 확인하려면 앱이 실제로 사용하는 로컬 출력 경로를 확인하고 메뉴 연결에 `"output":{"kind":"file","path":"C:\\Reports\\result.xlsx"}`를 추가합니다. 파일명이 매번 바뀌면 전용 폴더를 `"kind":"directory"`와 해당 폴더의 `path`로 지정합니다. 출력 위치를 지정하지 않은 실행은 메뉴 전달까지만 확인합니다.

### 초안 저장과 다시 열기

1. **마치고 검토**를 누르고 각 단계에 원하는 동작을 적으세요. 한 단계라도 남아 있으면 저장할 수 있습니다. 연결할 창이나 변수 이름이 미정이어도 해당 단계를 지울 필요가 없습니다. 현재 입력란에 쓰던 문장, 별칭, 고정값이나 필수 변수도 함께 저장됩니다.
2. **초안 저장**을 누르세요. 파일을 쓰는 데 실패하면 검토 창에서 원인과 입력 내용을 확인하고 다시 저장할 수 있습니다. 저장한 이름은 같은 프로젝트의 `tasks` 목록에 나타납니다.
3. Claude Code에 **“작업 이름의 초안을 열어서 이어서 수정해 줘”**라고 요청하세요. `show` 결과에 `draft: true`가 있으면 아래 명령으로 편집창을 엽니다. 업무 앱을 닫은 상태에서도 설명과 변수를 수정하거나 단계를 삭제할 수 있습니다. 실제 화면을 다시 가르치려면 앱을 열고 원래의 `record` 명령을 같은 이름으로 실행하세요.

```powershell
python -X utf8 -B .claude/skills/desktop-select/scripts/desktop_select.py review --task "작업 이름"
```

편집용 초안을 재생했을 때 `needs_review`가 나오면 AX Workspace나 Claude Code가 `live_recovery`에서 화면 증거를 읽고 위의 `recover` 절차를 이어갑니다. 특정 단계에 `diagnostic`이 있으면 해당 단계와 소속 창부터 확인합니다. 창이 아직 열리지 않은 경우에는 `opener_step`과 현재 상태를 보고, 요청받은 실행에서 그 창이 열린 뒤 관찰합니다. 실행용 사본을 저장해도 `execution_plan`에 미해결 단계가 남을 수 있습니다. 이때는 화면에서 확인 가능한 범위를 더 조사하고, 이미 전달한 조회나 내보내기를 반복하지 않습니다.

### 조건이 섞인 문장을 녹화할 때

각 동작을 평소처럼 시연하세요. **작업 창** 열로 관리창과 새로 열린 창을 구분할 수 있습니다. 검토 화면에서 한 단계에 “10초 기다렸다가 광고가 있으면 광고의 X를 눌러 닫아 줘. 광고가 있든 없든 포켓몬 카드 게임을 열어 줘”라고 적어도 됩니다. 두 기기에서 수행하려면 각 기기창의 단계에 같은 문장을 적으세요.

Claude Code에 “원래 녹화 이름으로 실행해 줘”라고 요청하세요. 녹화 뒤에 조건을 보충했다면 그 설명도 함께 사용합니다. 첫 등록 때 Claude Code가 조건문을 해석해 해당 녹화에 연결된 실행안을 만듭니다. 이후 같은 이름으로 재생하면 각 기기창에서 10초를 기다리고, 광고가 보일 때에만 광고 안의 X를 한 번 누른 다음, 게임을 엽니다. 기기 홈이 보이면 바로 게임 아이콘으로 진행합니다. 10초는 각 기기에서 별도로 셉니다.

Windows에서 광고나 아이콘 이름이 보이지 않으면 Claude Code가 해당 창의 현재 화면으로 판단합니다. 광고를 닫은 후에는 화면을 다시 확인합니다. **녹화창의 X, 기기창 전체를 닫는 X, 광고 안의 X**는 서로 다른 대상입니다. 아이콘 모양이 전에 녹화된 경우에도 게임 아이콘이 배경에 보인다는 이유만으로 광고가 없다고 판단하지 않습니다. 현재 화면에서 대상을 구분할 수 없으면 해당 단계와 이유를 알려줍니다.

### 같은 버튼이 여러 행에 보일 때

각 행에 ▶가 하나씩 있어도 **“이름이 A.로 시작하는 기기 켜 줘. 그다음 B.도 켜 줘”**라고 말하면 됩니다. “현재 목록 위에서 두 번째”라고 적으면 목록의 순서가 기준이고, “B.로 시작하는”이라고 적으면 목록에서 보이는 이름이 기준입니다. 한 창의 버튼을 눌러 다른 창에서 이어서 작업하는 경우에는 녹화 검토 화면의 **작업 창**에서 어느 행이 어느 창을 열었는지 확인하세요.

AX Workspace나 Claude Code에서 **“녹화한 거 실행해 줘”**라고 요청하세요. 처음에는 호스트가 원문과 후속 창 제목을 보고 목록에서 해당 행의 이름 또는 ID와 버튼을 한 쌍으로 연결합니다. 화면에 같은 버튼이 여러 개라는 이유만으로 다시 녹화할 필요는 없습니다. 이 연결은 원래 녹화 이름에 저장되고 각 창의 조건문도 유지됩니다. 같은 이름의 행이 두 개 보이면 둘을 구별할 표시 이름을 알려 주세요.

| 화면에서 확인된 상태 | 재생 동작 |
| --- | --- |
| 해당 행이 멈춰 있고 실행 버튼이 보임 | 현재 행에서 ▶ 또는 이름이 확인되는 실행 버튼을 한 번 누르고 녹화에 연결된 창이 열렸는지 확인합니다. |
| 해당 행과 녹화에 연결된 기기창이 이미 열려 있음 | 실행 버튼을 다시 누르지 않고 그 기기창에서 작업을 이어갑니다. |
| 창에서 조건 판단을 기다리는 중 | 호스트가 그 창의 현재 이미지를 보고 광고가 있으면 광고 안의 X를 누릅니다. 닫은 뒤 화면을 다시 보고, 광고가 없거나 닫혔으면 게임을 엽니다. |

반복하려면 **“이 흐름을 이 프로젝트의 Python 업무 스킬로 등록해 줘”**라고 요청하세요. 등록된 명령을 실행하면 같은 Desktop Select 엔진을 사용합니다. 화면을 보고 눌러야 하는 단계에서는 실제 마우스를 사용합니다.

### 관리창과 기기창을 한 작업으로 녹화하기

1. MuMu 관리창을 지정해 녹화를 시작하세요. 첫 번째 기기의 실행 버튼을 누르고, 새 기기창이 앞으로 오면 녹화기에 그 창의 제목이 표시되는지 확인하세요. 그 안에서 필요한 동작을 시연합니다.
2. 기기창이 이미 열려 있다면 **시작 → 열린 창 선택**을 누르세요. 첫 동작을 하기 전에도 고를 수 있습니다. 목록에서 기기창 제목을 고른 뒤 **이 창 선택**을 누르거나 제목을 두 번 클릭하세요. 녹화기에 선택한 창 제목이 표시되면 그 창에서 작업하세요. 녹화 중 자동 연결되지 않은 창도 같은 방법으로 선택합니다.

   방금 연 창이 안 보이면 **새로 고침**을 누르세요. 다른 앱에서 작업을 이어가려면 **다른 프로그램의 창도 보기**를 켜세요. 별도로 열어 선택한 앱은 다음 재생 전에도 열어 두세요. 창이 최소화되어 있다면 선택한 뒤 직접 복원해 시연하세요.
3. 관리창으로 돌아가 두 번째 기기를 실행하고 그 창에서도 작업하세요. 이미 연결한 창은 다시 선택할 필요가 없습니다. 검토할 때 창과 단계별 지시를 확인하고 저장하세요. 이름 없는 버튼은 화면에서 구분할 수 있는 단서를 문장에 적으세요.
4. 두 기기의 실행 버튼을 연달아 눌러 어느 버튼이 창을 열었는지 불분명하면, 검토 화면에서 그 창의 단계를 고르고 **창을 연 단계 지정**을 누르세요. 예를 들어 둘째 기기창에는 ‘두 번째 행 실행’ 단계를 지정합니다. 같은 기기창에서 기록한 단계에 함께 반영됩니다.
5. Claude Code에 “이 녹화를 Python 업무 스킬로 등록해 줘”라고 요청하세요. 반복 실행 시 새로 열도록 녹화한 창은 해당 단계를 실행한 뒤 기다리고, 처음부터 열려 있던 창은 실행 전에 열어 두어야 합니다. 같은 프로그램에 동일한 제목의 창이 둘이면 어느 창인지 정할 수 없어 멈춥니다.

이전에 저장한 녹화에 새 기기창 내부 동작을 넣으려면 해당 동작도 포함해 새 작업으로 녹화하세요. 녹화와 재생 중에는 처음 지정한 관리창을 열어 두세요. 기기창 자체를 구분할 수 있어도 Android 앱이나 게임 안에 그려진 버튼은 Windows에 개별 요소로 표시되지 않을 수 있습니다.

### 설명만 남은 단계와 화면 아이콘 재생하기

녹화 중 기기창에서 아이콘을 누르고 단계에 “카드게임 아이콘 눌러서 열어줘”처럼 적으세요. Windows에 버튼 이름이 없어도 클릭 직전 아이콘의 모양을 구분할 수 있으면 해당 창과 함께 저장합니다. 재생할 때는 저장한 이미지와 일치하는 곳을 다시 찾습니다. 화면에서 실제로 클릭하는 단계이므로 실행 중에는 잠시 마우스를 비워 주세요.

이전 버전에서 설명만 저장된 경우에는 Claude Code에 **“이 녹화를 실행해 줘. 설명만 남은 단계는 현재 기기창을 보고 찾아서 연결해 줘”**라고 요청하세요. 화면에서 대상이 구분되면 Claude Code가 실행용 복사본을 만듭니다. 원본 녹화는 보존되며 다음 실행부터는 그 복사본을 사용할 수 있습니다. 버튼을 누른 결과와 앱이 실제로 열린 결과는 각각 확인합니다.

처음 대상을 찾을 때 필요한 창 이미지는 이 PC의 임시 폴더에 저장합니다. 같은 창과 단계에 10분 동안 쓸 수 있고 연결하면 삭제됩니다. 사용하지 않은 이미지는 다음 화면 연결 명령에서 만료 여부를 확인해 정리합니다. 작업 파일에는 실행에 쓰는 아이콘 주변의 작은 이미지만 남습니다.

#### 두 기기에서 같은 앱을 여는 녹화 예시

MuMu 관리창에서 두 기기의 실행 버튼을 차례로 누른 뒤, 각 기기의 홈 화면에서 앱 아이콘을 한 번씩 누릅니다. **마치고 검토**를 누르고 각 단계의 설명을 편집하세요.

| 단계 | 녹화할 곳 | 입력할 문장 예시 |
| --- | --- | --- |
| 1 | 관리창에서 첫 대상 기기의 실행 버튼 | “이름이 04.로 시작하는 기기를 켜 줘.” |
| 2 | 관리창에서 둘째 대상 기기의 실행 버튼 | “이름이 05.로 시작하는 기기도 켜 줘.” |
| 3 | 04 기기 홈 화면의 앱 아이콘 | “04 기기 홈 화면에서 포켓몬 카드 게임 아이콘을 눌러 열어줘.” |
| 4 | 05 기기 홈 화면의 같은 앱 아이콘 | “05 기기 홈 화면에서 포켓몬 카드 게임 아이콘을 눌러 열어줘.” |

각 문장을 편집한 뒤 **적용하고 다음 단계**를 누릅니다. 3단계 창이 1단계에서 열렸고 4단계 창이 2단계에서 열렸는지 확인한 뒤 **저장**하세요. 기기 이름은 자기 화면에 맞춥니다.

Claude Code에서 “이 녹화를 이 프로젝트의 `/mumu-pocket` 스킬로 등록해 줘”라고 요청합니다. 등록 후 같은 프로젝트에서 `/mumu-pocket`을 입력하면 네 단계가 순서대로 실행됩니다. 관리창을 열어 둔 상태에서 시작하세요. 기기가 이미 실행 중이면 기록된 행의 상태를 확인하고 그 기기창에서 이어갑니다. 아이콘 단계는 홈 화면에 표시된 그림을 다시 찾습니다. 이 방식은 사용자의 실제 마우스를 잠시 사용합니다.

설치 후의 구성은 다음과 같습니다.

```text
프로젝트/
  .claude/skills/desktop-select/   실행 스킬
  .desktop-select/tasks/         녹화 작업
    execution-plans/             녹화에서 만든 실행안
```

저장 위치는 **스킬이 설치된 프로젝트**로 정해집니다. 명령을 다른 폴더에서 실행해도 바뀌지 않으며, 프로젝트 A와 B의 같은 작업명도 서로 섞이지 않습니다. 아래 안내에서 `scripts/...`로 시작하는 명령은 `desktop-select` 폴더 안에서 실행하는 예시입니다.

프로젝트에 설치하지 않고 압축을 푼 `desktop-select` 폴더에서 바로 사용하면 그 폴더 안의 `.desktop-select/tasks`에 저장합니다. 이 방식에서는 프로그램 폴더를 지우면 데이터도 함께 지워질 수 있으므로 보관 범위를 확인하세요. 나중에 버전을 교체할 때는 일부 파일만 덮어쓰지 말고 기존 프로그램 폴더를 보관한 뒤 새 폴더 전체를 넣으세요. 프로젝트 설치의 `.desktop-select` 데이터 폴더는 프로그램 폴더 밖에 있으므로 함께 교체하지 않습니다.

이전 `%LOCALAPPDATA%\DesktopSelect\tasks`의 공용 녹화는 자동으로 읽거나 옮기거나 삭제하지 않습니다. 새 프로젝트는 독립된 작업 목록으로 시작합니다. 프로젝트를 Git에 올린다면 `.gitignore`에 `.desktop-select/`를 추가하여 녹화의 창 제목, 지시와 입력값이 함께 게시되지 않도록 하세요. 도구가 `.gitignore`를 자동 변경하지는 않습니다.

### 공용 저장을 직접 선택하려면

여러 프로젝트가 같은 작업 목록을 사용해야 하는 경우에만 명시적으로 지정하세요. 아래 설정은 **현재 PowerShell과 여기서 새로 시작한 프로그램에만** 적용됩니다. 이 PowerShell에서 Claude Code를 시작해야 같은 설정을 사용합니다. 이미 실행 중인 Claude Code에는 적용되지 않습니다.

```powershell
$env:DESKTOP_SELECT_TASK_DIR = Join-Path $env:LOCALAPPDATA 'DesktopSelect\tasks'
python -X utf8 -B .claude/skills/desktop-select/scripts/desktop_select.py storage
```

다른 로컬 폴더의 절대경로를 지정해도 됩니다. 지정한 폴더에 기존 녹화가 있다면 그 작업 목록을 사용하며 자동 복사하거나 합치지 않습니다. 프로젝트별 기본값으로 돌아가려면 현재 PowerShell에서 아래 설정만 해제하세요. 저장된 파일은 지우지 않습니다.

```powershell
Remove-Item Env:DESKTOP_SELECT_TASK_DIR -ErrorAction SilentlyContinue
```

사용자 홈의 `.claude/skills/desktop-select`에 전역 설치한 경우에는 홈 전체를 프로젝트로 취급하지 않습니다. 프로젝트의 `.claude/skills`에 설치하거나 `DESKTOP_SELECT_TASK_DIR`에 사용할 저장소를 명시해야 합니다. 시스템 전역 환경변수를 설정할 필요는 없습니다.

### 마우스와 키보드를 계속 쓰면서 실행하려면

Claude Code에 **“이 작업이 내 마우스나 키보드를 쓰는지 먼저 확인해 줘. 내가 다른 일을 할 수 있는 방식으로만 실행해 줘.”**라고 요청하세요. 먼저 저장된 작업의 입력 방식을 확인하고, 실제 마우스나 키보드 또는 창 전면화가 필요한 단계가 있으면 실행 전에 알려 줍니다.

| 단계 | 기본 실행의 입력 방식 | `--background-only` |
|---|---|---|
| 일반 콤보 선택, 입력란 값 설정, 버튼/메뉴 호출 | 앱이 제공하는 UIA 기능 사용 | 지원되는 현재 대상이면 실행 |
| 표 우클릭, 행 버튼 | 실제 마우스 사용과 대상 창 전면화 | 첫 입력 전에 요청 전체 차단 |
| Enter로 조건 적용(`submit`) | 실제 키보드 사용과 대상 창 전면화 | 첫 입력 전에 요청 전체 차단 |
| 이름 없는 입력란의 위치 기반 대상(`anchor`) | 대상 확인을 위해 창을 앞으로 가져옴 | 첫 입력 전에 요청 전체 차단 |
| 대기, 생성 파일 확인 | 읽기 또는 대기 | 허용 |

다음은 저장된 녹화의 입력 방식만 확인하는 예입니다. 프로그램 이름과 창 제목은 저장한 작업에 맞추세요. **업무 앱을 실행할 필요가 없고, 필수 변수값도 아직 넣지 않아도 됩니다.** 화면 관찰, 창 복원, 클릭과 값 변경을 하지 않습니다.

```powershell
python -X utf8 -B scripts/desktop_select.py replay --task "조건 조회" --exe "Example.exe" --window "업무 창 제목" --input-plan
```

등록된 Python 업무 스킬도 확인할 수 있습니다. 다음 예는 desktop-select와 같은 skills 폴더에 `fx-query`가 등록된 경우입니다.

```powershell
python -X utf8 -B ../fx-query/scripts/run.py --input-plan
```

`--input-plan`은 저장한 동작에서 입력 방식을 분류합니다. 지금 앱에 그 대상이 있는지, 실제 값이 맞는지 또는 조회가 끝났는지를 확인한 결과는 아닙니다. `plan --task`는 녹화 지시를 실행안으로 저장하는 다른 명령이고, Python 실행기의 `--read-only`는 현재 창을 관찰하는 다른 기능입니다.

입력 방식을 확인한 뒤 사용자 입력을 쓰지 않는 실행은 다음처럼 요청합니다. 값은 실제 업무에서 지정한 값으로 바꾸세요.

```powershell
python -X utf8 -B scripts/desktop_select.py select --exe "Example.exe" --window "업무 창 제목" --target "Family" --value "Hybrid" --background-only
python -X utf8 -B scripts/desktop_select.py replay --task "조건 조회" --exe "Example.exe" --window "업무 창 제목" --set "Family=Hybrid" --background-only
python -X utf8 -B ../fx-query/scripts/run.py --set "Family=Hybrid" --background-only
```

`fill`과 `open`에도 같은 옵션을 붙일 수 있습니다. 요청한 전체 단계에 우클릭, Enter, 위치 기반 대상 또는 행 버튼이 하나라도 있으면 **첫 값 변경이나 조회 버튼 호출 전에 전체 요청이 멈춥니다.** 앞쪽의 일반 입력 단계만 먼저 실행하지 않습니다. 한 단계만 `--only`로 요청했다면 그 요청 범위를 기준으로 확인합니다. 차단됐다고 옵션을 자동으로 제거하거나 실제 클릭으로 재시도하지 않습니다.

이 모드에서는 도구가 실제 마우스나 키보드 입력을 보내거나 창을 앞으로 가져오거나 최소화된 창을 복원하지 않습니다. 최소화된 창은 사용자가 복원한 후 다시 요청해야 합니다. **UIA를 쓴다고 자동 포커스 이동이 없는 것은 아닙니다.** Windows UIA는 값 설정이나 버튼 호출 전에 대상에 포커스를 줄 수 있으므로, `--background-only`는 실제 조작에 쓰는 UIA 클라이언트의 `AutoSetFocus`를 `False`로 설정하고 같은 클라이언트에서 그 설정값을 다시 읽어 확인한 뒤 조작합니다. [Microsoft의 AutoSetFocus 설명](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomation2-get_autosetfocus)

다만 버튼을 호출했을 때 **앱 자체가 새 대화상자를 띄우거나 포커스를 바꾸는 동작**까지 막는 기능은 아닙니다. 다른 작업과 동시에 사용 가능한지는 해당 앱의 실제 반응도 확인해야 합니다. 옵션을 생략하면 UIA의 자동 포커스 설정을 포함해 이전 실행 방식대로 동작합니다.

원래 agent-desktop의 별도 커서는 조작 위치를 보여 주는 표시입니다. CUA Driver에는 대상 창으로 메시지를 보내 실제 사용자 커서를 움직이지 않는 별도 입력 경로도 있지만, Desktop Select가 그 Driver를 사용하는 것은 아닙니다. 둘 다 독립된 Windows 화면과 키보드를 만들어 주는 기능으로 해석하면 안 됩니다. Desktop Select는 현재 UIA 기능을 우선 사용하고 위 옵션으로 도구가 사용할 수 있는 입력 방식을 제한합니다. [원본 커서 설명](https://github.com/vercel-labs/agent-desktop/blob/v1.1.0/skills/agent-desktop-windows/references/shell-and-overlay.md#cursor-overlay), [CUA Driver의 입력 방식](https://github.com/trycua/cua/blob/cua-driver-rs-v0.28.2/libs/cua-driver/rust/Skills/cua-driver/WINDOWS.md#the-no-foreground-contract--read-this-first)

### 녹화 위치 + 자연어 지시 + 저장된 실행안

이 세 가지를 함께 사용할 수 있습니다. 녹화로 콤보, 일반 입력란, 조회 버튼의 위치를 알려 주고 각 단계 옆에 문장을 적습니다. 아래 Search는 검색어 입력란이 있는 프로그램의 예이며 현재 화면의 이름에 맞추세요.

| 단계 | 지시 예 | 저장되는 동작 |
|---|---|---|
| MES Setup | `MES Setup을 N으로 설정해 줘` | 고정값 N |
| Family | `입력받은 변수를 Family 조건에 입력해 줘` | 실행 시 필요한 변수 Family |
| Search 입력란 | `입력받은 변수를 Search 입력란에 입력해 줘` | 실행 시 필요한 변수 Search. 편집에서 변수명을 SearchText로 바꿀 수 있음 |
| 조회 | `조회 버튼을 눌러 줘` | 실제 조회 버튼 호출 |

**저장하면 원문과 실행안을 함께 보관합니다.** 다음에는 “저장한 작업을 Family=Hybrid로 실행해 줘”라고 요청하면 됩니다. 지원되는 전체 작업은 한 번의 Python 실행과 UIA 연결로 재생합니다. 이미 식별된 대상은 ID 또는 정확한 이름과 역할로 찾고 상위 영역을 확인합니다. 녹화 때 놓친 대상은 실행할 때 문장의 이름으로 현재 화면을 다시 살펴봅니다. 원본 지시가 바뀌면 이전 실행안을 버리고 다시 만듭니다.

**위치를 가리키면 설명 초안도 들어갑니다.** 읽힌 Family 값이 Hybrid이면 `Family 조건을 Hybrid로 설정해줘`, 콤보 값은 못 읽고 Family라는 대상만 알면 `입력받은 변수를 Family 조건에 입력해줘`, 조회 버튼이면 `조회 버튼을 눌러줘`가 초안입니다. 일반 입력란은 읽힌 문자열을 따옴표로 보존하고, 값을 읽지 못했으면 필수 변수 초안을 넣습니다. 값을 모르는 상태에서 N이나 Hybrid를 임의로 넣지 않습니다. 원하는 동작으로 고친 뒤 **적용하고 다음 단계**를 누르세요. 수정하지 않은 초안도 저장되며, 잘못된 단계는 목록에서 삭제할 수 있습니다.

**녹화에서 대상을 못 찾았어도 문장을 적을 수 있습니다.** 그 단계에 `MES Setup 조건을 N으로 해줘`처럼 실제 화면의 이름과 동작을 적으세요. 저장 후 재생할 때 직접 명령처럼 현재 화면에서 MES Setup을 찾습니다. 원래 녹화가 성공해야만 실행할 수 있는 구조가 아닙니다. 현재 화면에서도 대상이 없거나 같은 이름이 여러 개이면 그 단계에서 알려줍니다.

평소 쓰는 표현대로 저장한 뒤 Claude Code에 **“내가 적은 문장과 지금 화면을 확인해서 실행해 줘”**라고 요청하세요. 호스트가 `recover`로 실제 창과 단계를 함께 읽고, 분명하게 지정한 값이나 변수, 버튼을 실행용 작업으로 정리합니다. 일반 작업에서 이미 확인한 단일 대상만 편집할 때는 다음과 같이 `instruct`를 사용할 수도 있습니다.

```powershell
python -X utf8 -B scripts/desktop_select.py instruct --task "조건 조회" --only 1 --text "이전 시험 설정을 참고해서 공정 조건을 맞춰줘" --target "MES Setup" --role combobox --mode fixed --argument N --save-as "조건 조회 수정"
```

위 명령의 N은 사용자가 이전에 명시한 고정값이라는 전제의 예시입니다. 보호된 입력은 보존된 중단 사유를 확인합니다. 표 우클릭은 현재 표와 이어지는 메뉴 경로를 `recover`로 연결합니다.

로컬 편집란이 이해하지 못하는 자유로운 문장은 Claude Code에 **“녹화한 2단계는 Family 값은 실행할 때 받은 값을 넣으라는 뜻이야. 이 문장을 원문 그대로 두고 필수 변수 Family로 저장해 줘.”**라고 요청하세요. 현재 사용하는 모델이 의미를 한 번 해석해 구조화된 값과 함께 저장합니다. 스킬 자체가 외부 모델을 호출하지 않습니다. 예를 들어 아래 명령은 기존 작업을 보존하고 수정한 새 작업을 만듭니다.

```powershell
python -X utf8 -B scripts/desktop_select.py instruct --task "조건 조회" --only 2 --text "Family 값은 실행할 때 받은 값을 넣어줘" --mode required --argument Family --save-as "조건 조회 수정"
python -X utf8 -B scripts/desktop_select.py plan --task "조건 조회 수정"
```

문장에 나온 이름만 다르면 실제 녹화 대상을 확인한 뒤 이름을 연결할 수 있습니다. 새로운 이름을 연결한다는 이유로 다른 컨트롤을 추측해 고르지는 않습니다. UI의 고정값/필수 변수 지정과 다음 단계 이동, 삭제 기능도 그대로 사용할 수 있습니다.

**조회 뒤 내보내려면 대기 또는 완료 조건을 지정하세요.** 비동기 조회 뒤 바로 Excel을 호출하지 않도록, 처음에 “조회하고 5초 기다린 뒤 내보내기”라고 요청하면 조회 단계에 그 시간을 저장합니다. 대기를 지정하지 않은 중간 버튼은 기존 방식처럼 호출 전달에서 멈춥니다. 아래는 이미 내보내기 단계까지 녹화한 작업의 3단계에 대기를 지정하는 예입니다.

```powershell
python -X utf8 -B scripts/desktop_select.py instruct --task "조회 내보내기" --only 3 --text "조회한 뒤 5초 기다려" --mode recorded --wait-after 5 --save-as "조회 내보내기 실행"
python -X utf8 -B scripts/desktop_select.py replay --task "조회 내보내기 실행" --exe "Example.exe" --window "업무 창 제목" --set "Family=Hybrid"
```

고정 대기는 지정한 시간만 기다립니다. 최신 조회 결과 자체를 확인해야 하면 실제 완료 표시를 이용하는 표 메뉴 단계를 구성할 수 있습니다. 녹화로 확보하거나 현재 창에서 복구한 `result-menu`는 Python 실행안에 포함됩니다. 미해결 수동 단계가 남으면 전체 작업의 준비 상태와 해당 단계 번호를 먼저 확인하세요. 이미 전달된 입력을 확인한 뒤 필요한 다음 동작부터 이어갑니다.

원하면 녹화한 작업을 Python 업무 스킬로 만들 수 있습니다. 이 경우 `source-task.json`에 원문 녹화를, `workflow.json`에 실행할 동작을 저장합니다. 생성한 업무 스킬은 등록 당시의 복사본이므로 이후 원본 녹화를 바꿨다면 새 이름으로 다시 등록하세요.

```powershell
python -X utf8 -B scripts/python_workflow.py register --task "조회 내보내기 실행" --out ../fx-query
python -X utf8 -B ../fx-query/scripts/run.py --summary --set "Family=Hybrid"
```

실행안은 선택한 녹화 저장소의 `execution-plans`에 저장합니다. 기본 프로젝트 설치에서는 `<프로젝트>/.desktop-select/tasks/execution-plans`입니다. `storage`로 실제 위치를 확인할 수 있습니다. 원본 작업 파일은 그대로 남습니다. 저장 공간 문제로 실행안을 만들지 못해도 이미 저장한 녹화는 없어지지 않습니다.

### 한 번 등록하고 선택값과 입력값만 바꿔 Python으로 실행

Claude Code에 **“이 녹화를 Python 업무 스킬로 만들어 줘. MES Setup은 N으로 고정하고 Family와 검색어는 매번 입력받게 해 줘. 검색어 변수명은 SearchText로 해 줘.”**라고 요청하세요. 콤보와 일반 입력란, 버튼, 대기로 구성된 작업이면 처음에 지시를 정리하고 현재 대상의 ID 또는 정확한 이름과 역할, 상위 영역을 확인해 등록합니다. 다음에는 **“등록한 조회 업무를 Family=Hybrid, SearchText=00123으로 실행해 줘”**라고 요청합니다. 검색어 입력란이 없는 업무라면 그 부분은 제외하세요.

고정값은 매번 같은 값을 쓰고, 필수 변수는 매번 받은 값을 씁니다. 고정값으로 등록한 MES Setup=N을 실행 때 다른 값으로 덮어쓰지는 못합니다. 바꾸어 받아야 한다면 해당 지시를 필수 변수로 바꾼 뒤 새 업무 스킬로 등록하세요. 필요한 값이 여러 개 빠졌다면 실행을 시작하기 전에 한 번에 묻습니다. 녹화 당시의 값을 대신 쓰지 않습니다.

등록은 동작을 실행하지 않습니다. 콤보와 일반 입력란은 값을 한 번 쓰고 현재 값을 확인하며, 버튼은 한 번 호출합니다. 실행할 때 문장을 다시 해석하거나 전체 화면을 반복 분석하는 비용을 줄이는 방식입니다. 업무 앱의 서버 조회 시간까지 줄어드는 것은 아닙니다. 조회 후 5초는 결과를 기다리는 시간일 뿐 조회 완료의 증명은 아닙니다. 버튼 전달은 `delivered_unverified`, 전체는 `completed_unverified`일 수 있습니다. 결과 표와 Excel 창 또는 생성 파일은 따로 확인하세요. 값 확인 실패나 불확실한 호출 뒤에는 다음 버튼을 누르지 않습니다.

초기 등록을 직접 확인하려면 아래 순서를 사용합니다. 다음 예의 ID는 예시이므로 **현재 PC에서 찾은 실제 ID**로 바꿔야 합니다. 안정적인 ID 없이 이름으로 식별되는 대상은 `"selector": {"name": "Find what:", "role": "combobox"}`처럼 정확한 현재 이름과 역할을 사용할 수 있습니다. 녹화에서 등록하면 확인된 상위 영역도 보존합니다. ID를 추측해서 채우지 마세요. 프로그램 이름과 창 제목도 현재 값으로 넣습니다.

```powershell
python -X utf8 -B scripts/python_workflow.py discover --exe "Example.exe" --window "업무 창 제목"
```

아래 내용을 회사 PC에 `query-recipe.json`으로 저장합니다. 바꾸어 받을 Family와 SearchText에는 `value`를 넣지 않고 `parameter`만 넣습니다. 예의 `txtSearch` 입력란이 실제 업무에 없다면 그 단계를 제외하세요.

```json
{
  "schema": 1,
  "name": "조건 조회 후 Excel",
  "exe": "Example.exe",
  "window": "업무 창 제목",
  "steps": [
    {"action": "set-value", "selector": {"automation_id": "gcboStatus", "role": "combobox"}, "value": "N"},
    {"action": "set-value", "selector": {"automation_id": "gcboFamily", "role": "combobox"}, "parameter": "Family"},
    {"action": "set-value", "selector": {"automation_id": "txtSearch", "role": "textfield"}, "parameter": "SearchText"},
    {"action": "invoke", "selector": {"automation_id": "btnSearchData", "role": "button"}},
    {"action": "wait", "seconds": 5},
    {"action": "invoke", "selector": {"automation_id": "btnExportExcel", "role": "button"}}
  ]
}
```

desktop-select 폴더에서 첫 명령으로 등록하면 같은 skills 폴더에 새 업무 폴더가 생깁니다. 실행할 때는 아래 두 `run.py` 예시 중 이번 조건에 맞는 명령 하나를 사용하세요.

```powershell
python -X utf8 -B scripts/python_workflow.py register --recipe query-recipe.json --out ../fx-query
python -X utf8 -B ../fx-query/scripts/run.py --summary --set "Family=Hybrid" --set "SearchText=00123"
python -X utf8 -B ../fx-query/scripts/run.py --summary --set "Family=DRAM" --set "SearchText=00987"
```

직접 등록하면 `SKILL.md`, `workflow.json`, `scripts/run.py`가 생성되고 녹화에서 등록하면 `source-task.json`도 보존합니다. 실행기는 저장한 JSON의 동작을 수행하는 Python 소스이며 일반 값/버튼 단계의 UIA 연결을 재사용합니다. 자연어를 임의의 코드로 실행하거나 외부 모델을 호출하지 않습니다. 추가 EXE나 CUA 드라이버 설치도 없습니다. 업무 스킬은 옆의 desktop-select 실행기를 사용합니다. `--out`으로 지정한 폴더에 생성되며 녹화 저장소 변경으로 위치가 바뀌지 않습니다. 같은 이름으로 등록하면 덮어쓰지 않습니다.

일반 입력란의 변수는 따옴표, 한글, 앞자리 0을 그대로 전달합니다. `--set "SearchText="`를 명시하면 입력란을 비웁니다. 빈 콤보값은 허용하지 않으며 변수 누락이나 잘못된 값은 첫 조작 전에 알려 줍니다. 비밀번호 입력, 콤보 내부 편집창, 값을 읽고 쓸 수 없는 특수 위젯에는 일반 입력 기능을 적용하지 않습니다.

위 예는 **엑셀 버튼**을 요청했을 때의 동작입니다. 표에서 `EXPORT → EXPORT TO EXCEL`을 선택하라는 지시에는 표의 우클릭과 메뉴 경로를 사용하세요. 일반 녹화가 확보했거나 `recover`로 보완한 `result-menu`는 `register --task`로 등록할 때 Python 실행안에 함께 들어갑니다. 우클릭 뒤에 저장 대화상자가 별도로 열리면 아래 예처럼 팝업 처리 단계와 파일 확인을 이어 붙일 수 있습니다.

### 조회 우클릭 내보내기 창을 Python 실행안으로 연결하기

Claude Code에는 다음처럼 요청하면 됩니다.

> MES Setup은 N으로 고정하고 Family는 실행할 때 받아 줘. 조회한 뒤 결과 표를 우클릭해서 EXPORT → EXPORT TO EXCEL을 실행해 줘. 내보내기 창에서 파일 경로를 넣고 완료 버튼을 누르는 단계와 새 Excel 파일 확인까지 한 Python 업무 스킬로 등록해 줘. 처음에는 현재 화면에서 각 대상을 확인하고, 등록만으로 실제 실행을 했다고 보고하지 마.

처음 한 번은 실제 표 영역, 메뉴 경로, 내보내기 창의 제목과 입력란/버튼, 저장할 로컬 경로를 확인합니다. 이후에는 등록된 순서를 사용합니다. 앱마다 내보내기 창이 다르므로 아래 이름을 그대로 회사 앱에 적용하지 말고 확인된 이름으로 바꿉니다. 메뉴 뒤 바로 파일을 만드는 앱은 팝업 단계를 생략합니다.

| 실행안 동작 | 용도 |
|---|---|
| `set-value` | 고정값 또는 실행 변수로 콤보/일반 입력란 설정 후 다시 읽기 |
| `invoke` | 확인된 버튼 한 번 호출 |
| `submit` | 확인된 콤보/입력란에 포커스를 확인하고 Enter 한 번 전송 |
| `wait` | 등록한 시간만큼 대기. 조회 완료를 증명하지 않음 |
| `context-menu` | 가르친 표 내부 위치를 다시 찾아 우클릭하고 메뉴 경로 실행 |
| `popup` | 해당 `set-value`/`invoke`/`submit`을 정확한 제목의 소속 팝업 안에서 실행 |
| `verify-file` | 전체 작업 시작 전과 비교해 새로운 로컬 Excel 통합 문서 확인 |

예를 들어 기존 조건 설정과 조회 단계 뒤에 다음 단계들을 넣을 수 있습니다. `Results`, `Export data`, `File name`, `Finish`는 형식 설명용 이름입니다. `point`는 실제 시연 위치를 표 너비/높이의 비율로 기록한 값입니다.

```json
[
  {
    "action": "context-menu",
    "spec": {
      "target": {"role": "table", "name": "Results"},
      "point": [0.5, 0.3],
      "path": ["EXPORT", "EXPORT TO EXCEL"]
    }
  },
  {
    "action": "set-value",
    "popup": {"title": "Export data", "timeout": 3},
    "selector": {"role": "textfield", "name": "File name"},
    "value": "C:\\Work\\Exports\\result.xlsx"
  },
  {
    "action": "invoke",
    "popup": {"title": "Export data", "timeout": 3},
    "selector": {"role": "button", "name": "Finish"}
  },
  {
    "action": "verify-file",
    "output": {"kind": "file", "path": "C:\\Work\\Exports\\result.xlsx"},
    "timeout": 26
  }
]
```

완성된 recipe는 앞 절과 동일하게 `register --recipe ... --out ../<업무명>`으로 등록합니다. 등록과 `--read-only`는 클릭하거나 저장 창을 열지 않습니다. 아직 열리지 않은 팝업 단계는 `pending_scopes`/`deferred`로 남습니다. 이는 **실행 때 확인할 대상이 남아 있다는 뜻**입니다. 같은 제목의 팝업이 여럿이거나 다른 창에 속하면 실행하지 않습니다. 팝업 대기는 최대 10초이며 다음 페이지가 필요하면 실제 확인한 버튼 단계를 순서대로 추가합니다.

입력한 필터를 Enter로 적용하는 앱은 같은 입력란을 가리키는 `{"action":"submit","selector":...}`를 값 설정 뒤에 추가합니다. `set-value`가 실패했을 때 키보드로 다시 입력하는 기능은 아닙니다. `submit`은 Enter만 지원하고 임의 단축키나 명령을 실행하지 않습니다. 우클릭은 실제 마우스, Enter 적용은 실제 키보드를 사용하므로 해당 단계 동안 다른 입력을 하지 마세요.

`verify-file`은 요청한 로컬 경로의 `.xlsx`/`.xlsm`이 새로 생성되거나 변경됐는지와 통합 문서 구조를 확인합니다. 디렉터리 감시는 새 파일이 하나일 때만 확인합니다. 파일 확인은 저장 경로를 입력하는 동작과 별개이며 셀 내용, 결과 행 수, 업무 저장 완료를 증명하지 않습니다. 첫 실행에서는 파일을 열어 선택 조건에 맞는 결과인지 확인하세요. 전체 실행이 `completed_unverified`여도 마지막 단계의 `file_verified: true`는 별도로 확인할 수 있습니다. 버튼 호출과 파일 확인 상태를 나눠 보고합니다.

### 화면에 이름이 없는 입력란을 등록할 때

ID나 이름이 보이면 현재의 정확한 이름/ID와 역할을 먼저 사용합니다. 이름과 라벨이 모두 없는 입력란은 그 입력란이 있는 **고유한 상위 영역**과 시연 위치를 기록할 수 있습니다. 예시 selector 형식은 다음과 같습니다. 실제 클래스와 위치는 현재 화면에서 읽어야 합니다.

```json
{
  "anchor": {"role": "group", "name": "Device form"},
  "point": [0.5, 0.06],
  "role": "textfield",
  "class_name": "Edit"
}
```

실행 때 상위 영역을 다시 찾고 현재 위치의 UIA 대상이 같은 역할/클래스이며 그 영역 안에 있는지 확인합니다. 이 대상 찾기 자체는 클릭하지 않습니다. 숫자 HWND나 옛 절대좌표를 저장하지 않으며 창 위치가 바뀌면 현재 영역 기준으로 계산합니다. 역할이나 클래스가 달라지거나 가려져 있으면 알려 주고 멈춥니다. 같은 종류의 입력란끼리 자리가 바뀐 경우에는 이 검사만으로 구별할 수 없으므로 화면 배치가 바뀌면 지정 위치를 다시 확인하세요. 이 방식은 창이 보여야 하므로 실행할 때 앞으로 가져옵니다. 등록은 화면을 복원하거나 앞으로 가져오지 않으므로 사용자가 해당 영역을 보이게 해 두어야 합니다.

실제 앱 시험과 시간 측정 기록은 [0.4.8 검증 문서](https://github.com/bongG-moon/agent-desktop-workflows/blob/desktop-select-v0.4.8/docs/desktop-select-048-validation.md)에 별도로 기록합니다. 회사 PC의 FX/FarPoint 동작을 이 PC의 시험으로 확인했다고 볼 수는 없습니다.

### 녹화 없이 일반 입력란에 바로 입력하기

Claude Code에 “Search 입력란에 00123을 입력해 줘”라고 요청하거나 아래 명령을 사용하세요. `--value=`는 명시적으로 입력란을 비우는 명령입니다. 입력 후 현재 값이 정확히 일치하는지 확인하며, 확인되지 않으면 재입력하지 않습니다.

```powershell
python -X utf8 -B scripts/desktop_select.py fill --exe "Example.exe" --window "업무 창 제목" --target "Search" --value "00123"
```

### 0.4.0에서 보완한 실행 문제

0.4.7은 실제 Notepad++ 8.8.8의 바꾸기 대화상자에서 확인한 두 문제도 보완합니다.

- 창이 보이는데 `inspect`가 비어 있던 문제: 표준 Windows 대화상자가 보호 여부 속성을 생략하면서 창 전체가 제외되었습니다. 이제 실제 창과 프로세스, 클래스, 편집 기능이 없는 창 외곽인지 확인한 경우 내부를 읽습니다. 비밀번호 입력이나 보호 여부를 알 수 없는 입력란까지 허용하는 변경은 아닙니다.
- 녹화는 되었는데 Python 등록이 거부되던 문제: `Find what:`, `Replace with:`, `Replace All`처럼 이름으로 기록된 대상도 정확한 이름과 역할, 상위 영역으로 등록합니다. 숫자 ID를 임의로 저장하거나 예전 좌표를 누르지 않습니다. 같은 범위에 같은 후보가 여럿이면 그 단계에서 알려줍니다.

확인에는 별도 설정으로 실행한 Notepad++와 시험용 문서를 사용했습니다. Windows에 클릭과 키 입력 이벤트를 보내 실제 녹화 경로를 확인했으며, 사람이 물리 마우스와 키보드로 시연한 시험과는 구분합니다. 회사 FX에서의 동작을 대신 확인한 것은 아닙니다. 배포 ZIP에는 Python 호환 코드만 추가되며 새 EXE나 CUA 드라이버는 포함하지 않습니다.

| 증상 | 0.4.7 처리 |
|---|---|
| 화면에 있는데 `IsOffscreen=None` | 값 누락과 화면 밖을 구분하고, 현재 창 표시와 유효한 내부 좌표로 판단 |
| 편집 요소 두 개가 같은 값인데 충돌 | 동일 값은 일치 근거로 사용하고 서로 다른 값만 충돌 처리 |
| 옵션 좌표 0×0, 펼침 상태 미갱신 | 쓰기 가능한 부모 콤보에 SetValue 1회 후 읽기 확인 |
| 최소화 상태의 좌표 0×0 | 실제 조작 전 복원하고 다시 관찰. 읽기 전용은 창을 복원하지 않음 |
| 호환 코드 수정 시 `skill_incomplete` | 호환 처리를 핵심 브리지 밖에 분리하고 핵심 파일 검증은 별도 manifest로 유지 |
| 직접 명령 때 반복되는 전체 탐색 | 최초 라벨 탐색 후 같은 ID 또는 정확한 이름과 역할, 현재 상위 영역으로 재검사 |

직접 명령과 등록 실행의 콤보 값은 실제 입력 문자열입니다. 표시 이름과 저장 코드가 다른 경우 실제 코드를 확인해서 사용하세요. 입력 후 확인이 안 되면 펼치기나 클릭으로 자동 재시도하지 않습니다. 콤보와 버튼의 접근성 호출은 마우스를 움직이지 않지만 옵션 없는 기본 실행에서는 최소화된 창이 복원됩니다. `--background-only`는 최소화된 창을 복원하지 않고 중지합니다. 행 버튼과 우클릭 메뉴의 물리 입력은 실제 마우스를 사용합니다.

### 한 번 가르쳐 두고 값만 바꿔 실행하기

1. FX 업무 창을 열고 Claude Code에 **“desktop-select로 이 창의 조건 설정을 ‘장비 조건’이라는 작업으로 녹화해 줘”**라고 요청하세요. 녹화 창에서 **시작**을 누른 후 실제 업무 창에서 MES Setup과 Family 콤보를 차례로 선택하세요.
2. **마치고 검토**를 누르면 단계 목록을 볼 수 있습니다. 각 행을 선택하고 그 옆의 **실행할 동작**을 적으세요. 1단계에는 `MES SETUP조건을 N으로 해줘`, 2단계에는 `입력받은 변수를 FAMILY조건에 입력해줘`라고 씁니다. **적용하고 다음 단계**로 다음 단계에 이동하세요. 미리보기에 첫 값이 **N**, 둘째 값은 실행할 때 받을 **Family**로 표시되는지 확인하고 저장하세요. 잘못 녹화한 행은 검토 중 **선택 단계 삭제**로 지울 수 있습니다. 같은 단계에 `패밀리 조건`처럼 짧은 별칭도 붙일 수 있습니다.
3. 다음에는 **“장비 조건을 Family=Hybrid로 실행해 줘”**라고만 요청하세요. Family를 주지 않으면 먼저 값을 물어봅니다. **“장비 조건의 패밀리 조건 단계만 Family=Hybrid로 실행해 줘”**처럼 한 단계만 실행할 수도 있습니다.

| 각 단계의 ‘실행할 동작’에 입력할 문장 | 실행 미리보기와 실제 동작 |
|---|---|
| `MES SETUP조건을 N으로 해줘` | **지정한 값으로 선택: N**. 시연한 값이 달라도 재생할 때는 N을 선택하고 다시 읽습니다. |
| `입력받은 변수를 FAMILY조건에 입력해줘` | **실행 시 입력할 변수: Family**. 실행 요청에서 받은 값을 선택합니다. 값이 빠지면 첫 단계도 실행하지 않습니다. |

녹화는 **위치를 가리키고 실제 동작은 문장으로 지정**할 수 있습니다. 예를 들어 녹화창에 `gcboStatus`만 표시돼도 “MES Setup에 ‘N’을 선택해 줘”라고 적고 저장하세요. 호스트가 현재 화면의 라벨, 컨트롤 ID와 역할을 읽고 어느 필드인지 대조합니다. 직접 편집하고 싶으면 **상세 설정 → 문장의 이름을 이 대상에 연결**에서 별칭을 지정할 수도 있습니다.

저장 후에는 “패밀리 조건 근처의 조회 버튼을 찾아 줘”처럼 주변 요소를 따로 지시할 수도 있습니다. 녹화에서 확인한 같은 업무 영역 안에 대상이 하나만 있을 때 사용할 수 있습니다.

녹화 검토에서 대상 이름이 다르거나 우클릭 위치가 빠졌다고 표시되면 작성한 문장을 그대로 저장하세요. 호스트가 현재 창의 표와 기록된 메뉴 순서를 대조하고, 위치가 없으면 해당 창의 이미지를 관찰합니다. 조회 버튼 호출만 확인된 경우에는 현재 표의 상태를 살펴보고 다음 동작을 정합니다.

프로젝트 설치의 기본 저장 위치는 `<프로젝트>/.desktop-select/tasks`입니다. 작업 파일에는 대상 프로그램과 창 제목, 단계별 요소 식별 정보, 직접 지정한 지시 및 값이 들어갑니다. 녹화는 시작부터 마치기까지 선택한 업무 창의 조작을 관찰하며 화면 영상과 원시 키 입력을 작업 파일에 담지 않습니다. 시연 중에는 사용자가 직접 마우스를 사용합니다. 재생은 현재 창에서 Windows 접근성 기능으로 대상을 선택합니다.

### FX: MES Setup=N, Family는 매번 입력해서 조회부터 Excel 내보내기까지

**기본 녹화**에서는 MES Setup과 Family 선택, 조회, 결과 표 우클릭, 메뉴 선택을 순서대로 시연하세요. [저장한 녹화 이어서 실행하기](#저장한-녹화-이어서-실행하기)에 따라 원문과 현재 화면을 연결합니다. 조회 완료를 판별할 글자나 표 안의 표시, 결과 파일 조건까지 직접 가르치고 싶으면 다음 절차를 사용합니다.

1. **시작**을 누른 후 MES Setup과 Family를 한 번씩 선택하세요. **마치고 검토**에서 첫 행에는 `MES SETUP조건을 N으로 해줘`, 둘째 행에는 `입력받은 변수를 FAMILY조건에 입력해줘`라고 적습니다. 고정값 **N**과 필수 변수 **Family**가 각각 표시되는지 확인하세요. 아직 작업을 저장하지 않습니다.
2. **단계 추가 → 조회 후 우클릭 메뉴 가르치기 → 조회 버튼 가리키기 (3초)**를 누른 뒤 실제 폼 안의 조회 버튼에 포인터를 올립니다. 업무 화면에서 직접 조회해 결과가 나타나도록 하세요. 조회 버튼은 이번 단계에 포함되므로 별도 클릭 단계로 두지 마세요.
3. 메뉴 이름에 **첫 줄 `EXPORT`, 둘째 줄 `EXPORT TO EXCEL`**을 실제 표시와 같게 입력합니다. **데이터가 있는 지점 가리키기 (3초)**를 누르고 결과 표의 데이터 본문 안쪽을 가리키세요. 제목, 열 머리글, 스크롤 막대는 피합니다. 셀이 접근성 목록에 없어도 이름이나 ID로 같은 표를 다시 찾을 수 있으면 사용할 수 있습니다. 특정 레코드나 선택한 행만 내보내는 메뉴라면 이 위치만으로 레코드 일치까지 보장하지 않습니다.
4. **상태 글자 가리키기 (3초)**로 실제 조회가 끝났을 때의 상태 요소를 지정하고 기대 글자를 확인하세요. 글자를 읽을 수 없으면 **표 안의 완료 모양 고르기**에서 조회 중에는 사라졌다가 완료 시 나타나는 작은 표시를 지정합니다. 표 테두리, 항상 켜진 버튼, 매번 달라지는 데이터 값은 적합하지 않습니다. 조회 전부터 같은 표시라면 재생 중에 그 표시가 사라졌다 다시 나타나는 것도 관찰해야 진행합니다.
5. 파일 생성까지 확인하려면 **앱이 실제로 저장하는** 로컬 `.xlsx` 또는 `.xlsm` 파일 경로를 지정하세요. 파일명이 매번 바뀌면 이 작업만 사용하는 로컬 폴더를 지정하세요. 폴더 모드에서는 새 통합 문서가 정확히 하나 생겨야 합니다. **단계에 추가 → 저장**을 누릅니다. 파일을 지정하지 않아도 메뉴를 실행할 수 있지만 파일 생성은 확인되지 않습니다.

**다음부터는 한 문장이면 됩니다.** Claude Code에 **“FX 조회 내보내기를 Family=Hybrid로 실행해 줘”**라고 하세요. 변수 없이 요청하면 값을 먼저 받아야 하며, 그전에는 첫 단계도 실행하지 않습니다. 결과를 읽지 못하면 다음 단계로 넘어가지 않습니다. 표와 메뉴는 실제 마우스를 쓰므로 FX 창을 표시하고 재생 중에는 마우스나 키보드를 움직이지 마세요.

파일 확인은 256 MiB 이하의 `.xlsx`와 `.xlsm`을 대상으로 합니다. FX가 ‘다른 이름으로 저장’을 띄우면 [내보내기 창을 Python 실행안으로 연결하기](#조회-우클릭-내보내기-창을-python-실행안으로-연결하기)에 따라 현재 팝업의 입력과 완료 단계를 등록할 수 있습니다. Excel이 새로 열린 경우에는 업무 앱과 별도인 Excel 창 및 생성 파일을 확인합니다. 이전 버전에 수동으로 남은 우클릭도 [저장한 녹화 이어서 실행하기](#저장한-녹화-이어서-실행하기)에서 보완할 수 있습니다. 회사 PC에서 처음 실행할 때는 통합 문서가 생성됐는지와 선택한 Family의 데이터가 들어 있는지를 각각 확인하세요.

### 목록에서 첫 번째와 두 번째 실행 버튼 누르기

1. 두 행이 보이는 창을 열고 Claude Code에 **“이 창에서 기기 두 대를 실행하는 작업을 녹화해 줘”**라고 요청하세요. **시작**을 누르고 목록에서 첫 번째 행과 두 번째 행의 실행 버튼을 차례로 한 번씩 누릅니다. 녹화 창에서 단계와 인식 상태를 볼 수 있습니다.
2. **마치고 검토**를 누릅니다. 선택한 단계 아래의 첫 입력칸에 실행할 동작을 적습니다. 첫 단계에는 `첫번째 요소 실행버튼 누르기`, 둘째에는 `두번째 요소 실행버튼 누르기`처럼 쓸 수 있습니다. **적용하고 다음 단계** 또는 Enter를 누르면 다음 단계로 이동합니다. 별칭과 변수는 **상세 설정**에 있습니다.
3. 원하지 않은 클릭은 **선택 단계 삭제**로 지우고, 빠진 동작은 **단계 추가 → 직접 설명 입력**으로 더하세요. 해석된 문장은 **준비됨**으로 표시됩니다. 자유롭게 쓴 문장은 **초안 저장**을 누른 뒤 Claude Code에 **“이 초안에 내가 적은 문장을 읽고, 현재 목록의 실행 동작으로 정리해 줘”**라고 요청하세요. 원문을 보존한 수정본을 저장할 수 있습니다.
4. 문장을 확인했으면 **저장**을 누르고 **“기기 두 대 실행을 재생해 줘”**라고 요청하세요. 화면에 보이는 목록에서 요청한 순번의 행과 실행 버튼을 찾아 한 번 누릅니다. 같은 행의 실행 버튼과 상태 표시가 바뀌었는지 확인합니다. 기기 내부 서비스가 준비됐는지는 별도로 확인해야 합니다. 이 흐름은 실제 마우스를 사용합니다.
5. 같은 작업을 반복하려면 **“이 녹화를 프로젝트의 Python 업무 스킬로 등록해 줘”**라고 요청하세요. 등록된 작업은 주 실행기를 재사용합니다. 콤보나 입력란이 함께 있다면 등록할 때 필수 변수로 지정하고 실행 때 값을 바꿀 수 있습니다.

녹화 없이 **“지금 보이는 목록의 두 번째 기기를 실행해 줘”**라고 할 수도 있습니다. 먼저 대상을 살펴보려면 **“입력 없이 대상만 확인해 줘”**라고 요청하세요. 예전 녹화에서 별칭에 실행 문장을 입력했다면 해석 가능한 단계는 재사용됩니다. 안내문만 남은 단계는 Claude Code에 그 단계와 새 지시를 함께 알려 주세요.

### 특정 항목과 완료 표시를 직접 가르치기

목록 순서가 바뀌어도 시연한 이름이나 번호로 찾으려면 그 행의 표식을 직접 지정하세요. 이 기능은 선택한 단계의 **행 버튼으로 지정** 또는 **단계 추가 → 행 버튼 가르치기**로 열 수 있습니다.

예를 들어 목록의 세 기기를 실행한다면, 먼저 관리자를 열고 실행할 세 행의 번호와 현재 상태를 확인하세요. 창 크기와 화면 배율은 시연할 때와 같게 두고 세 행이 화면에 보이게 하세요.

1. Claude Code에 **“이 창의 목록에서 행 버튼을 가르치는 녹화를 시작해 줘. 이름은 ‘기기 세 대 실행’이야.”**라고 요청합니다. 녹화 창에서 **단계 추가 → 행 버튼 가르치기 → 행 가져오기 (3초)**를 누르고 업무 창의 대상 행 위에 마우스를 둡니다.
2. 행 미리보기에서 세 곳을 지정하세요. **행을 구별하는 표시**에는 번호나 고유 이름, **클릭할 버튼**에는 ▶ 전체, **상태**에는 ‘부팅되지 않음’ 같은 현재 상태 글자를 담습니다. 다른 행에서도 계속 달라지는 숫자, 경과 시간, 포인터가 놓일 때만 나타나는 아이콘은 피하세요.
3. **실행 전 상태 기록**을 누른 뒤 업무 창에서 직접 버튼을 누르세요. 같은 행에 원하는 **최종 상태**가 보일 때 **완료 상태 가져오기 (3초)**를 누릅니다. ‘부팅 중’에서 기록하면 다음 실행부터 ‘부팅 중’을 완료로 판정하게 됩니다. **이 행에서 실행할 동작**에 `첫 번째 기기의 시작 버튼을 눌러 실행 중인지 확인`처럼 적고, 미리보기를 확인한 뒤 **단계에 추가**를 누르세요. 두 번째와 세 번째 행은 같은 버튼과 시작 상태라면 **이전 행의 완료 표시 사용**으로 시연을 줄일 수 있습니다. 행을 모두 추가하고 저장하세요.
4. **“기기 세 대 실행을 재생해 줘.”**라고 요청합니다. 재생은 가르친 행을 현재 화면에서 다시 찾고 마우스로 버튼을 한 번 누릅니다. 해당 행에서 완료 표시를 확인하면 다음 행으로 진행합니다. 이미 완료된 행은 클릭을 건너뜁니다. 중간에 멈추면 **“이 작업의 각 행 상태만 다시 확인해 줘.”**라고 요청하세요.

같은 이름의 버튼이 여러 줄에 있어도 행 번호나 이름이 구분되면 사용할 수 있습니다. 목록의 정렬 순서가 바뀌면 녹화한 번호나 이름을 따라갑니다. 담당자가 새로 상위에 올라온 행을 실행하고 싶다면 그 행을 다시 지정하세요. Windows가 목록의 행 경계를 제공하고, 버튼과 상태 표시를 화면에서 구분할 수 있어야 합니다. 작업 파일에는 직접 지정한 행 표식, 버튼, 전후 상태의 작은 화면 표본이 로컬에 저장됩니다. 행을 구별하는 데 필요한 부분만 담으세요.

### 녹화 없이 바로 지시하기

**처음에는 읽기만 해 보세요.** 회사 PC에서 실제 업무 화면을 연 뒤 다음처럼 요청합니다.

> desktop-select로 Device Setup Standard 업무 창에서 MES Setup과 Family가 각각 어느 콤보인지 보여 줘. 아직 값을 바꾸지 마.

대상이 맞으면 **“같은 창에서 MES Setup을 N으로, 확인되면 Family를 Hybrid로 선택해 줘”**라고 요청하세요. 쓰기 가능한 부모 콤보에 요청한 문자열을 한 번 설정한 뒤 값을 다시 읽습니다. 선택을 전달한 후에도 선택값을 읽을 수 없으면 거기서 멈춥니다. 화면에 있는 옵션 목록만으로 선택됐다고 판정하지 않습니다.

**조회나 메뉴**는 대상이 나타난 실제 영역을 확인합니다. “업무 폼 안의 조회를 눌러 줘”라고 하면 호스트가 `commands`(바깥 도구 모음), `content`(안쪽 업무 폼), `conditions`(조회 조건), `condition-commands`(조건 영역 명령), `grid`, `properties`에서 해당 버튼을 찾습니다. 표가 이름 있는 `group`으로만 보이면 현재 화면에서 데이터 셀을 확인하고 그 표의 상대 위치에 연결합니다. 재생 때는 막 열린 메뉴에서 부모와 자식을 차례로 찾아 선택합니다. 파일 생성 확인은 실제 출력 경로나 지정 폴더에 맞춰 추가합니다.

**마우스 사용 여부**는 단계에 따라 다릅니다. 일반 콤보 값 설정과 버튼/메뉴의 패턴 호출은 Windows 접근성 기능을 사용합니다. 행 버튼과 표 우클릭 메뉴는 창을 앞으로 가져오고 실제 포인터를 이동해 클릭합니다. `submit`은 입력란에 실제 Enter 키를 보내며, 상위 영역과 위치로 이름 없는 입력란을 찾을 때도 창을 앞으로 가져옵니다. 이런 단계가 끝날 때까지 마우스와 키보드를 사용하지 마세요.

**콤보에서 어디까지 읽히나:** 특정 콤보를 확인하면 현재 접근성에서 읽히는 옵션 값과 이름을 보여 줍니다. 닫힌 콤보는 목록이나 현재값이 비어 보일 수 있습니다. SetValue를 지원하면 옵션 목록이나 펼침 상태에 의존하지 않고 요청한 실제 문자열을 씁니다. 표시명과 내부 코드가 다르면 실제 코드를 사용하세요. SetValue를 지원하지 않는 콤보만 필요한 경우 펼쳐서 현재 항목을 선택합니다. 해당 경로에서 항목의 소속이나 표시명이 모호하면 임의로 고르지 않습니다. 검색 전용 별도 대화상자는 추가 지시가 필요할 수 있습니다.

문제가 생겼을 때는 다음만 구분하면 됩니다.

| 표시 | 의미와 다음 행동 |
|---|---|
| `verified` | 해당 단계의 기대값 또는 상태가 일치했습니다. 파일 조건을 지정한 내보내기에서는 새로 생성되거나 변경된 Excel 통합 문서를 확인했습니다. |
| `blocked` | 명령을 완료하지 못했습니다. 창/필드 중복, 읽을 수 없는 옵션, 비활성 컨트롤 등을 확인하세요. `expanded: true`이면 목록만 펼쳤을 수 있습니다. |
| `delivered_unverified`, `mismatch`, `uncertain` | 호출 결과를 성공으로 단정하거나 다시 누르지 마세요. 화면을 보거나 같은 대상에 `inspect`로 읽기만 하세요. |

PowerShell에서 직접 시험할 때는 스킬 폴더에서 실행합니다. 아래 제목은 **첫 명령이 돌려준 실제 제목 전체**로 바꾸세요.

```powershell
Get-Process -Name '*MenuAgent*' | Select-Object -ExpandProperty ProcessName -Unique
$fx = '<위에서 확인한 MenuAgent 프로세스 이름>.exe'
python -X utf8 -B scripts/desktop_select.py windows --exe $fx
$screen = '<실제 업무 창 전체 제목>'
python -X utf8 -B scripts/desktop_select.py inspect --exe $fx --window $screen --target 'MES Setup' --role combobox
python -X utf8 -B scripts/desktop_select.py select --exe $fx --window $screen --target 'MES Setup' --value N
python -X utf8 -B scripts/desktop_select.py select --exe $fx --window $screen --target Family --value Hybrid
```

마지막 두 줄은 한 줄씩 실행해 결과를 확인하세요. 스킬은 해당 PC에서 동작하며, 출력은 명령을 실행한 Claude Code 세션에 보입니다.
