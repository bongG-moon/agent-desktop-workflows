# 반복 행과 여러 창

[관찰 순서](host-details.md#관찰-순서)에 따라 현재 요소와 행 단서, 후속 창의 검증 결과를 먼저 사용한다. 아래 이미지 보정은 아직 해결되지 않은 단계에만 적용한다.

## 더블클릭으로 상세 창을 열 때

사용자가 가리킨 항목을 더블클릭하면 녹화기는 첫 클릭 직전의 화면 표식을 동작과 함께 보관한다. 재생은 현재 창에서 그 표식을 다시 찾은 뒤 실제 마우스로 더블클릭한다. 실행 영수증에 입력이 전달됐으면 현재 소유 팝업이나 사용자가 지정한 다음 창을 확인한다. 조회가 이미 끝났으면 결과 표가 보이는 상태에서 보정한 단계만 시험한다.

조회 전부터 같은 행이 보였다면 새 결과인지 구분이 필요하다. `query_result_freshness_unproven`이면 호스트가 현재 결과의 식별값이나 완료 표시를 확인하고 더블클릭 단계만 시험한다. 사용자가 방금 확인해 준 결과도 활용한다. 화면에서 이전 결과와 새 결과를 구분할 수 없을 때만 확인을 요청한다.

상세 창에서 값을 읽어 달라는 지시는 창이 열린 다음 처리한다. 같은 앱의 소유 팝업이라면 `inspect`가 반환한 `owned_popups`에서 해당 창을 고르고, `inspect --exe <프로그램.exe> --window <원래 창 제목> --popup <현재 HWND> --target <실제 필드> --role textfield`로 읽는다. 표시된 값까지 확인한 뒤, 닫기 요청이 있으면 그 팝업에 속한 실제 닫기 버튼을 `open --popup`으로 한 번 실행한다. 원래 창 복귀까지 요구되면 해당 팝업이 닫혔는지도 확인한다.

## 반복되는 행과 그림 버튼

목록 안에 이름 없는 버튼이 있으면 녹화기는 누른 행의 식별 표식과 그 행 안에서 누른 버튼의 위치와 모양을 함께 저장한다. 같은 버튼을 가리키는 설명은 검토 화면에서 고쳐도 된다. 재생 때 행의 위치가 바뀌면 현재 목록에서 원래 행을 찾아 버튼을 대조한다. 행 안에 결과 변화가 없는 일반 버튼은 클릭 전달까지 보고한다. 클릭 직전의 모양을 확보하지 못했으면 행 번호와 행 안의 위치를 보정 단서로 남긴다.

이전 녹화가 `1번째 행 버튼을 눌러줘` 같은 문장만 담고 있어도, 사용자가 그 행의 실행 버튼을 확인해 주었다면 `instruct --task "<작업>" --only 1 --row 1 --text "1번째 행 실행 버튼을 눌러줘" --save-as "<보정한 작업>"`으로 연결한다. 같은 창과 순번에서 이미 확인한 ▶ 표식이 있으면 보정본에 포함한다. 이 명령은 입력을 보내지 않는다.

**같은 모양의 버튼이 목록에 반복될 때.** “A.로 시작하는 기기 켜 줘”에서는 `A.`가 행 이름의 앞부분이다. “위에서 두 번째 켜 줘”처럼 **현재 순서**를 지정한 문장에만 서수를 사용한다. `target_missing`, `visual_target_ambiguous`, `row_ordinal_not_visible`, `named_window_row_identity_required`가 나오면 같은 영수증의 요소와 행 단서로 해결 가능한지 먼저 확인한다. 단서가 부족한 단계만 관리창에서 `ground`하고 반환된 이미지를 한 번 읽는다. 화면의 행 이름 또는 ID와 **그 행 안에 있는 버튼**을 함께 식별한다. 녹화 뒤에 열린 창의 제목과 프로그램도 대조한다.

1. 그 행의 실행 버튼으로 새 창을 여는 단계에는 `desktop_select.py bind-row --task <원래 이름> --only <단계> --frame <이번 ground 영수증> --row-point <행 이름이나 ID의 X> <Y> --point <같은 행 버튼의 X> <Y>`를 사용한다. 두 지점 모두 방금 본 PNG 원본 기준이다. 이미 실행 중인 행도 같은 방식으로 식별할 수 있다. 연결 명령은 버튼을 누르지 않는다.
2. 대상 행이 더 있으면 같은 원본 녹화 이름으로 해당 단계의 `ground`와 `bind-row`를 반복한다. 이후 원래 이름으로 `plan`과 `replay`를 사용한다. 기존 조건 해석은 함께 유지된다. 재생에서는 행의 식별 표식과 정확한 기기창을 확인하고, 이미 열린 기기는 종료 버튼에 손대지 않고 다음 단계로 진행한다. 입력을 보냈는데 결과가 불확실하면 현재 창과 행의 상태부터 관찰한다.
3. 사용자가 반복 실행을 요청하면 `scripts/python_workflow.py register --task <녹화 이름> --out <프로젝트>/.claude/skills/<업무-이름>`으로 업무 스킬을 등록한다. 다음 요청에는 이 스킬의 `scripts/run.py`를 사용한다. 같은 행에서 편집하거나 값을 선택하는 업무는 해당 컨트롤의 역할과 동작을 확인해 `fill`, `select` 등으로 연결한다. 현재 화면의 정보만으로 두 후보를 구별할 수 없을 때만 두 이름을 제시해 묻는다. [같은 버튼이 여러 행에 보일 때](../사용가이드.md#같은-버튼이-여러-행에-보일-때)

1. `replay`가 `needs_grounding`을 반환하면 `grounding_steps`의 원문과 창을 사용한다. 의미가 명확한 버튼은 현재 화면의 정확한 이름을 먼저 찾는다. 이름 검색이 실패하면 `ground --task <작업> --only <원본 단계>`를 호출하고 반환된 로컬 `image`를 읽는다. 원래 지정한 프로그램/창의 이미지만 사용하고 외부 서비스로 전송하지 않는다.
2. 창에 한 번만 나타나는 아이콘은 원본 크기 이미지에서 중앙을 골라 `bind-visual --task <작업> --only <단계> --frame <영수증> --point X Y --save-as <새 작업명>`으로 연결한다. 두 명령은 클릭하지 않는다. 여러 단계면 **방금 만든 작업**에서 다음 단계를 연결한다. 같은 ▶가 반복되면 앞의 행 이름과 버튼을 함께 식별하는 절차를 사용한다. 창이 닫혀 있으면 저장된 창 열기 동작과 사용자의 실행 요청 범위를 확인한다. `replay --only <원본 단계>`로 필요한 열기 동작만 실행할 수 있다. 이미 전달된 동작을 다시 보내기 전에 영수증과 현재 상태를 확인한다.
3. 준비된 작업을 `replay` 또는 Python 등록으로 이어간다. `visual_click_dispatched`는 클릭 전달을 뜻한다. 앱 실행 확인을 요청받으면 영수증의 후속 창 확인 결과를 먼저 사용한다. 그 근거가 없고 접근성으로도 확인할 수 없을 때만 해당 단계의 `ground`로 새 화면을 읽어 앱 이름이나 시작 화면을 확인한다. 창이 달라졌거나 화면에 후보가 여럿일 때는 모호한 지점만 질문한다.

**목록의 행을 실행해 달라는 요청.** 사용자가 “첫번째 요소 실행버튼 누르기”처럼 현재 목록의 순번을 명시하면 `row-launch --exe <프로그램.exe> --window <제목> --ordinal 1 --preview`로 현재 보이는 행과 버튼을 입력 없이 확인한다. 사용자가 실제 실행을 요청할 때 `--preview`를 빼고 한 번 수행한다. 실행 확인의 범위는 같은 행의 버튼과 상태 변화다. 비정형 문장이 초안에 남으면 호스트가 의도와 순번을 확인해 `instruct --task <이름> --only <단계> --text <사용자 원문> --row <순번> --save-as <새 이름>`으로 구조화하고 원문을 보존한다. 사용자가 문법을 다시 작성하도록 요구하지 않는다. 별칭에만 실행 문장이 남은 옛 미인식 단계는 지원하는 표현이면 읽을 때 복구한다. 안내문만 남은 단계는 임의로 실행하지 않는다.

**행 표식과 완료 상태를 직접 지정할 때**는 검토 화면의 ‘단계 편집 → 행 버튼으로 지정’ 또는 ‘단계 추가 → 행 버튼 가르치기’를 사용한다. 사용자가 한 행 안에서 고유한 번호나 이름, 클릭할 버튼, 실행 상태가 표시되는 부분을 각각 지정한다. 사용자가 버튼을 시연하고 화면에 원하는 최종 상태가 나타나면 같은 위치의 완료 표시를 기록한다. 숫자나 이름은 목록 순서가 바뀌어도 같은 항목을 식별할 수 있어야 한다. 이 방식은 시연한 항목을 따라간다. 현재 보이는 상위 세 행을 매번 고르는 지시는 순번을 쓰는 행 실행으로 저장한다.

이 단계의 재생은 실제 마우스를 사용한다. 창을 표시하고 버튼이 있는 행을 보이게 한다. 같은 행의 완료 표시가 이미 보이면 입력 없이 확인한다. 입력 뒤 상태를 확인할 수 없으면 읽기 전용 `row-status --task <작업명> --exe <프로그램.exe> --window <제목>`으로 다시 확인한다. 완료 근거는 가르친 행의 상태 표시다. 화면에서 읽을 수 있는 고유 표시나 완료 표시가 없는 행에는 이 방식을 적용할 수 없다.

## 조건 분기와 여러 창

**조건이 포함된 녹화.** 실행안에 조건 해석이 남아 있으면 저장 응답에서 단계 원문, 작업 창, 후속 설명을 확인한다. 이전 응답이 없으면 `show`에서 원문을 읽는다. `needs_review`나 `instruction_requires_structure`와 함께 `grounding_steps`가 오면 해당 단계의 실행안을 구성한다. 녹화 당시 알아보지 못한 요소가 있다는 이유로 앞 단계만 다시 녹화하도록 제안하지 않는다. “잠시 기다리고 광고가 있으면 닫고, 있든 없든 게임을 열어”는 **대기 → 광고가 있을 때만 닫기 → 게임 열기**다. 사용자가 마지막 동작을 양쪽 경우에 수행한다고 밝혔으면 다시 묻지 않는다. 두 창에 같은 문장이 있으면 각각의 창에 독립된 단계로 연결한다. [조건부 녹화 절차](../사용가이드.md#조건이-섞인-문장을-녹화할-때)를 따른다.

1. 호스트가 직접 아래 형식의 JSON 파일을 작성한다. `number`는 원본 녹화 순번이고 `text`에는 사용자 설명 및 해당되는 후속 정정을 반영한다. 그림을 붙일 때는 같은 창의 동일 대상임을 확인한 녹화나 등록 스킬의 단계만 참조한다. 참조가 없으면 `from_skill`과 `from_step`을 생략한다. 복합 문장의 단일 화면 힌트를 광고와 최종 버튼 양쪽에 쓰지 않는다.

   ```json
   {"schema":1,"steps":[{"number":3,"text":"10초 대기. 광고가 있으면 광고 안의 X로 닫고, 두 경우 모두 게임 열기","seconds":10,"when_present":{"name":"광고"},"dismiss":{"name":"X"},"always":{"name":"포켓몬 카드 게임"}}]}
   ```

2. 대상 단계들을 한 파일에 넣고 `scripts/desktop_select.py interpret --task <원래 이름> --plan-file <로컬 JSON>`을 실행한다. 같은 이름으로 `replay --task <원래 이름> --exe <관리창 실행 파일> --window <관리창 제목>`을 호출한다. 설치가 두 곳이면 원본을 보여 준 설치본의 저장소와 같은지 `storage`로 확인한다. 해석에 필요한 자료를 사용자가 직접 만들게 하지 않는다.
3. 재생 또는 등록된 Python 업무 스킬이 `needs_scene`을 반환하면 호스트가 해당 영수증의 `image`를 로컬에서 읽는다. `condition`에서 광고가 보이면 광고 안의 닫기 지점을 `present`로, 광고가 없고 요청한 아이콘이 보이면 그 아이콘 지점을 `absent`로 제출한다. `scripts/python_workflow.py scene --ticket <이번 ticket> --decision present|absent --point X Y`를 사용하며 좌표는 해당 이미지 원본 크기 기준이다. 등록된 업무에서는 그 업무의 `scripts/run.py scene`에 같은 인자를 준다. 광고를 닫고 받은 `after_dismiss`의 새 이미지에 게임 아이콘이 보이고 광고가 사라졌으면 새 티켓에 `absent`와 아이콘 지점을 보낸다. 장면을 판별할 수 없으면 `--decision unknown`으로 종료한다. 대기 중에는 같은 실행을 이어가고, 티켓 만료나 전달 불확실 시에는 어느 단계까지 입력이 갔는지와 현재 화면을 먼저 확인한다.

**여러 창에 걸친 녹화와 재생.** 녹화를 시작하면 첫 동작 전에도 **열린 창 선택**을 열 수 있다. 이미 열려 있는 기기창은 기본 목록에서 제목을 고르고 **이 창 선택**을 누른다. 별도 앱은 **다른 프로그램의 창도 보기**를 켜고 선택한다. 새 창이 방금 열렸으면 **새로 고침**을 누른다. 녹화한 동작으로 열린 관련 창이 앞으로 오면 녹화기가 자동으로 연결한다. 원래 창으로 돌아와 작업을 이어갈 수 있다. 단계의 창 정보는 자연어 편집, 저장, 재생, Python 등록에 함께 전달한다. 같은 프로그램에 같은 제목의 창이 여러 개면 사용자에게 구별할 제목을 요청한다. 하위 앱 내부 버튼은 실제로 인식하거나 상태 변화를 확인한 범위에서만 결과를 보고한다.
