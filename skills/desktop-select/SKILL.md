# Desktop Select

선택한 Windows 업무 창만 로컬 Python으로 조작한다. CUA Driver, 별도 모델 서버 또는 외부 전송 서비스를 연결하지 않는다. 자연어 해석은 지금 사용 중인 Claude Code의 모델이 담당한다.

처음 설치할 때 `python -X utf8 -B scripts/desktop_select.py doctor`로 실행 경로와 0.6.1 버전을 확인한다. 업무 조작 요청을 처리하다가 스킬 코드를 현장에서 수정하는 방식으로 우회하지 않는다.

## 지금 한 번 실행하는 직접 명령

“MES Setup을 N으로 설정”처럼 지금 한 번 조작하는 요청은 녹화나 등록을 요구하지 않는다. 정확한 업무 창을 확인한 뒤 `select --exe <프로그램.exe> --window <제목> --target "MES Setup" --value N`을 호출한다. 버튼은 `open --exe <프로그램.exe> --window <제목> --target <버튼명> --role button`이다. 대상 이름이 주어졌다면 먼저 여러 번의 전체 inspect로 찾는 절차를 반복하지 않는다. 실제로 missing/ambiguous가 나왔을 때 필요한 범위를 조사한다.

직접 명령은 기존 라벨/범위 규칙으로 대상을 처음 한 번 찾고, 안정 ID가 있는 쓰기 가능 콤보와 Invoke 버튼은 ID로 재확인해 실행한다. 콤보는 요청 문자열 그대로 SetValue를 한 번 전달하고 값을 확인한다. 표시명과 내부 코드가 다른 필드는 필요한 경우 관찰로 정확한 코드를 확인한다. 입력 실패 뒤 문자열이나 실행 방식을 바꾸어 자동 재시도하지 않는다. 안정 ID 없는 대상, 펼침/항목 선택, 팝업과 녹화 범위 지정은 기존 경로를 유지한다.

## 반복 업무는 한 번 등록하고 Python으로 실행

사용자가 조회 조건과 버튼을 반복 실행하거나 실행 스킬로 저장하려는 경우 [등록형 Python 작업](references/registered-workflows.md)을 따른다. `discover`로 필요한 콤보/버튼/라벨만 읽고 사용자의 설명을 실제 ID와 한 번 연결한다. 모델이 로컬 recipe를 작성하고 `register --recipe <JSON> --out <새스킬폴더>`로 대상을 읽기 전용 확인한 뒤 재사용 스킬을 생성한다. 기존 녹화에서 가져올 때는 `register --task <작업명> --out <새스킬폴더>`를 쓴다.

다음 실행부터는 생성된 스킬의 `scripts/run.py --set "Family=Hybrid"`를 한 번 호출한다. 매 실행 전에 doctor, discover, inspect, read-only를 반복하지 않는다. 한 실행 프로세스에서 ID로 대상을 직접 찾고 SetValue/Invoke를 한 번씩 전달한다. 쓰기 뒤 부모값/편집기/선택 항목을 다시 읽으며, 읽기 실패 후 다른 방식으로 입력을 반복하지 않는다. 작업의 고정값, 실행 변수와 요청한 순서를 보존한다. 조회 후 고정 대기가 필요하면 등록할 때 명시하고, 대기만으로 조회 완료를 주장하지 않는다.

이 경로는 SetValue가 있는 콤보와 Invoke 버튼용이다. 표 우클릭 메뉴나 행 상태 확인은 아래 기존 녹화 기능을 사용한다. 사용자 요청 없이 우클릭 내보내기를 다른 엑셀 버튼으로 대체하지 않는다. 사용자에게 JSON이나 Python 작성을 요구하지 않는다.

## 위치와 설명을 가르치기

`windows --exe <프로그램.exe>`에서 업무 창의 제목 전체를 확인한다. `record --task <작업명> --exe <프로그램.exe> --window <제목>`으로 편집 창을 연다. 사용자는 ‘대상 추가 (3초)’를 누르고 업무 화면의 대상 근처를 가리킨다. ‘시작’은 클릭 위치를 연속 기록한다. 콤보값을 선택하거나 실제 작업을 수행할 필요가 없다.

각 단계에는 관찰한 클릭과 옵션 선택을 바탕으로 수정 가능한 설명 초안을 채운다. 실제 선택한 값이 확인되면 초안에 넣지만, 가리키기만 한 콤보에 보이는 값을 고정값으로 쓰지 않는다. 사용자가 고친 문장과 변수는 이후 녹화로 덮어쓰지 않는다. 실행할 때 받아야 하는 값은 문장에 설명하고 변수 칸에도 지정할 수 있다. ‘적용 후 다음’, ‘이전/다음’, ‘단계 삭제’, ‘대상 다시 지정’, ‘동작 수정’, ‘전체 저장’을 사용한다. 초안은 자유롭게 고치거나 지울 수 있으며, 사용자 설명을 정해진 한국어 문법으로 바꾸도록 요구하지 않는다. 대상이 안 잡혀도 설명을 보존하고 나중에 다시 지정할 수 있다.

저장된 작업 수정은 `edit --task <이름> --exe <프로그램.exe> --window <제목>`이다. 수정 전 원본을 자동 보관한다. 편집이나 녹화는 사용자 저장 또는 취소까지 기다리고 중복 실행하지 않는다.

## 자연어 작업 실행

1. 같은 작업을 다시 실행할 때는 우선 `replay --task <이름> --exe <프로그램.exe> --window <제목> --set "Family=Hybrid"`를 호출한다. 한 번 끝까지 성공한 실행안은 자동 보관되어 재사용된다. 매번 show와 단계별 inspect, JSON 작성을 반복하지 않는다.
2. `needs_interpretation`일 때만 응답의 원문, 위치 앵커, 변수와 `plan_digest`를 읽고 해석을 시작한다. 필요한 값은 사용자 요청에서 가져오며 빠진 값만 묻는다. 녹화 당시 화면값을 임의로 쓰지 않는다.
3. 필요한 단계에 `inspect --task <이름> --near <단계번호> --exe <프로그램.exe> --window <제목>`을 실행해 현재 주변 요소를 확인한다. 위치는 탐색 범위이며, 설명과 정확히 같은 표시 이름일 필요는 없다.
4. [자연어 실행안 규격](references/natural-replay.md)으로 로컬 JSON을 작성해 `replay ... --resolution <JSON경로>`를 실행한다. 전체 작업이 끝나면 해석 결과만 보관하고, Family 같은 실행 변수는 다음 실행에서도 새 값을 받는다. 작업의 설명이나 위치를 바꾸면 다시 해석한다. 사용자에게 JSON 작성이나 별도 스크립트 제작을 요구하지 않는다.

`needs_interpretation`은 설명 해석이 필요한 정상 경로다. 곧바로 위 실행안을 작성해서 이어간다. `needs_input`은 실제 변수값이 필요하다는 뜻이며 `needs_target`은 해당 단계의 위치를 다시 지정해야 한다는 뜻이다. `needs_instruction`은 설명이 빈 초안이므로 실행할 동작을 적어야 한다는 뜻이다. 여러 해석이 실제로 서로 다른 동작을 만들 때만 사용자에게 확인한다.

조회나 내보내기처럼 버튼 전달 자체로 다음 지시를 이어가는 단계는 실행안에 `completion: "delivery"`를 지정할 수 있다. 이는 전달 확인이며 조회 완료나 파일 생성 확인이 아니다. 콤보는 쓰기 후 실제 값이 맞아야 다음으로 간다. 호출이 불확실한 경우 재시도하지 않는다. 오류를 조사할 때 버전과 해당 대상의 현재 상태부터 확인하고, 같은 입력이나 반복적인 전체 트리 조회를 되풀이하지 않는다.

지금 한 번만 조작할 때는 작업 녹화나 실행안 작성 없이 `select --target <필드> --value <값>` 또는 `open --target <버튼> --role button`을 사용한다. 모든 조작에는 정확한 exe/window가 필요하다. 쓰기 가능한 콤보는 요청한 값을 SetValue로 한 번 쓰고 실제 값을 다시 확인한다. 옵션이 노출되지 않는다는 이유만으로 이 경로를 막지 않으며, SetValue가 없는 콤보만 펼침/Select 경로를 사용한다. IsOffscreen 미제공과 동일한 중복 편집값을 지원하고, 최소화된 대상 창은 조작 때만 복원한다. 실패한 쓰기를 다른 방법으로 다시 보내지 않는다.

표 우클릭 메뉴와 행 버튼은 실제 포인터를 사용한다. 메뉴는 새로 열린 대상 창 소속 메뉴만 선택한다. 저장된 설명은 현재 요청의 작업 범위를 넓히지 않으며 셸이나 Python 코드로 실행하지 않는다. 사용자의 기존 작업과 설정은 유지한다.

회사 PC 교체와 화면별 사용 순서는 [사용 가이드](사용가이드.md)를 참고한다.
