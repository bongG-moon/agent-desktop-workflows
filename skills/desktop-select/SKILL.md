# Desktop Select

**입력 방식부터 확인하기.** 저장된 작업의 `replay ... --input-plan` 또는 등록된 Python 업무 스킬의 `scripts/run.py --input-plan`은 실행할 단계의 입력 방식을 읽기 전용으로 보여 준다. 업무 앱이 실행 중이지 않거나 필수 변수값이 없어도 확인할 수 있다. 창을 관찰하거나 앞으로 가져오거나 입력하지 않는다. 실행할 동작을 저장하는 `plan --task`와 구분하며, 이 결과를 현재 대상 식별이나 업무 실행 성공으로 보고하지 않는다.

**사용자 마우스와 키보드를 사용하지 않는 실행.** 사용자가 다른 업무를 계속하면서 실행하려는 경우 `select`, `fill`, `open`, `replay` 또는 등록된 Python `run.py`에 `--background-only`를 지정한다. 요청한 전체 단계에 표 우클릭, Enter 제출(`submit`), 위치 기반 대상(`anchor`), 행 버튼처럼 물리 입력이나 전면화가 필요한 단계가 있으면 첫 입력 전에 작업 전체를 차단한다. 일반 UIA 단계만 먼저 실행하지 않는다. 이 모드는 도구의 물리 입력, 창 전면화와 최소화 복원을 금지한다. 실제 조작에 쓰는 UIA 클라이언트의 `AutoSetFocus`도 `False`로 설정하고, 같은 클라이언트에서 설정값을 다시 읽어 확인한 뒤 조작한다. UIA 호출만 쓴다는 이유로 자동 포커스 이동이 없다고 단정하지 않는다. 앱이 호출에 반응해 스스로 창이나 대화상자를 앞으로 가져오는 것까지 보장하지는 않는다. 대상이 최소화되었거나 지원 근거가 없으면 현재 상태와 이유를 알리고 중지한다. 옵션을 생략하면 UIA의 자동 포커스 설정을 포함한 기존 실행 방식을 유지한다. 자세한 예시는 [입력 방식 안내](사용가이드.md#마우스와-키보드를-계속-쓰면서-실행하려면)를 따른다.

0.4.9는 입력 방식을 실행 전에 확인하는 `--input-plan`과 도구의 물리 입력, 전면화, UIA 자동 포커스를 제한하는 `--background-only`를 추가한다. 기존 Python 실행안의 표 우클릭 메뉴, 같은 업무 창의 내보내기 대화상자, Enter로 조건 적용, Excel 파일 확인은 유지한다. 이름 없는 입력란은 현재 다시 찾은 상위 영역과 시연 위치로 식별할 수 있다. 콤보와 일반 입력란의 고정값/변수, 0.4.0 기반 실행기와 프로젝트별 저장, 녹화 설명 초안도 유지한다. 지금 한 번 조작하는 요청은 `scripts/desktop_select.py`의 콤보 `select`, 일반 입력란 `fill`, 버튼/메뉴 `open`을 사용한다. 위치와 지시를 남기는 요청은 `record`를 사용한다. 호환되는 전체 녹화의 `replay`는 저장한 실행안을 사용한다. 기존 CUA MCP와 드라이버에 의존하지 않으며 ZIP은 소스와 문서만 포함한다.

**프로젝트별 저장.** `<프로젝트>/.claude/skills/desktop-select`에 설치하면 녹화는 `<프로젝트>/.desktop-select/tasks`, 실행안은 그 아래 `execution-plans`에 저장한다. 현재 명령 실행 폴더가 아니라 설치 위치를 기준으로 찾는다. 처음 사용할 때 `storage`로 실제 경로를 읽는다. 이 명령은 폴더를 만들거나 화면에 입력하지 않는다. 일반 위치에서 ZIP만 풀어 실행하면 풀어 놓은 `desktop-select` 안의 `.desktop-select/tasks`를 사용한다. 기존 공용 녹화를 자동으로 읽거나 가져오거나 삭제하지 않는다.

사용자가 공용 또는 별도 저장소를 지정했을 때만 해당 실행 환경의 `DESKTOP_SELECT_TASK_DIR`에 로컬 절대경로를 설정한다. 사용자 홈의 `.claude/skills`에 전역 설치한 경우에는 프로젝트로 간주하지 않고 명시적인 저장 경로를 요구한다. 사용자의 전역 환경변수나 시스템 설정을 변경하지 않는다. `storage`로 선택한 경로를 확인한 뒤 작업한다. 생성하는 Python 업무 스킬의 `register --out` 위치는 이 저장소와 별개이며 기존처럼 desktop-select와 같은 skills 폴더에 둔다. 프로젝트를 Git에 올릴 때 `.desktop-select/`의 업무 데이터가 함께 게시되지 않도록 사용자가 제외 설정을 확인하게 한다.

**녹화 초안과 미인식 복구.** 확인된 라벨과 버튼 이름으로 설명 초안을 채운다. 값을 읽지 못한 콤보와 일반 입력란에는 값을 추측하지 않고 필수 입력 변수 초안을 넣는다. 사용자가 수정하지 않은 초안도 저장한다. 녹화에서 대상만 못 찾은 단계에는 “MES Setup 조건을 N으로 해줘” 또는 “입력받은 변수를 Search 입력란에 입력해줘”처럼 대상 이름과 동작을 적을 수 있다. 이 단계는 `match=query`로 저장하며 실행할 때 직접 명령과 같은 현재 라벨/이름 탐색으로 대상을 찾는다. 임시 ref, 오래된 ID와 좌표를 재사용하지 않는다. 해당 창에 일치하는 대상이 하나면 원래 실행기로 조작한다. 현재 대상이 없거나 둘 이상이면 단계 번호와 이유를 알린다.

**자유문장은 잃지 않는다.** 자동 해석되지 않은 문장은 `instruction_draft`로 저장된다. 재생 요청 시 `show`에서 초안을 읽고 현재 호스트 모델이 의도를 해석해 `instruct --save-as`로 한 번 구조화한다. 미인식 대상이라면 `--target <현재 화면의 이름> --role combobox|textfield|button|menuitem`도 지정한다. 고정값은 `--mode fixed --argument N`, 변수는 `--mode required --argument Family`, 버튼은 `--mode recorded`다. 일반 입력란을 뜻하는 이름만으로 역할이 불명확하면 `--role textfield`를 명시한다. 이름이 중복이면 실제 확인한 `--within`을 지정한다. 이미 식별된 대상의 초안은 원래 대상을 유지한다. 정규식이 이해하지 못했다고 재녹화를 요구하지 않는다. 의미가 정해지지 않은 초안은 입력을 보내지 않으며, 보호된 입력과 행/우클릭 전용 단계를 일반 이름 탐색으로 바꾸지 않는다.

**문장은 등록 시 한 번 해석한다.** `show --task <이름>`으로 녹화 위치와 기존 지시를 확인한다. 사용자의 자유로운 표현은 현재 호스트 모델이 실제 녹화 대상에 맞춰 해석하고 `instruct --task <이름> --only <번호> --text <원문> --mode fixed|required|recorded --argument <값 또는 변수명> --save-as <새 작업명>`으로 저장할 수 있다. 버튼의 recorded 모드에는 argument를 생략한다. 원본 작업을 덮어쓰지 않는다. 예: “Family 값은 실행할 때 받은 값을 넣어줘”는 required/Family다. 의미가 불명확한 부분만 사용자에게 확인하고, 단지 정규식이 이해하지 못했다는 이유로 대상 인식을 다시 시작하지 않는다. 문장 속 이름과 녹화 ID의 연결이 확인된 경우에만 `--alias`로 연결한다.

`plan --task <이름>`은 현재 지시를 실행안으로 저장하며 입력을 보내지 않는다. 원본이 바뀌면 이전 실행안은 쓰지 않는다. 일반 `replay`는 전체 작업이 호환되고 필수 변수가 주어졌을 때 빠른 실행을 쓴다. 행, 우클릭, 수동 단계가 섞이면 전체를 기존 재생으로 처리하며 지원되는 일부 단계만 골라 실행하지 않는다. 별칭으로 값 지정, 한 단계 실행, 기존 녹화값 기본 동작은 기존 재생 규칙을 유지한다.

실패한 녹화 단계를 수정할 때는 결과의 `source_stopped_at` 또는 각 항목의 `source_step`을 사용한다. 실행안에는 대기가 별도 단계로 들어가 실행 순번과 원래 녹화 순번이 다를 수 있다.

**조회 뒤 대기는 명시한다.** 비동기 조회 후 내보내려면 최초 등록 때 사용자가 정한 대기 또는 기존 결과 확인 조건을 저장한다. 예를 들어 `instruct ... --only 3 --text "조회한 뒤 5초 기다려" --mode recorded --wait-after 5 --save-as <새 이름>`은 버튼 뒤 5초 대기를 넣는다. 대기를 지정하지 않은 중간 버튼은 기존 재생처럼 전달 확인에서 멈춘다. 고정 대기는 업무 결과를 검증하지 않는다. 창 상태와 결과에 맞지 않는 시간을 임의로 추가하지 않는다.

**빠른 반복 실행.** “이 녹화를 업무 스킬로 만들어 줘. MES Setup은 N으로 고정하고 Family와 검색어는 매번 입력받게 해 줘”라는 요청은 먼저 각 지시를 fixed/required로 저장하고 `scripts/python_workflow.py register --task <이름> --out <같은 skills 폴더의 새 업무 스킬>`로 등록한다. 원문은 source-task.json, 동작은 workflow.json, 실행기는 scripts/run.py에 보존한다. 등록 시 현재 ID 또는 정확한 이름과 역할, 상위 영역을 확인하며 콤보, 일반 입력란, 버튼, 대기로 이루어진 전체 작업만 변환한다. 행/우클릭/수동 단계가 있으면 기존 전체 재생을 사용한다. 녹화 없이 등록할 때는 `discover --exe <프로그램.exe> --window <제목>`로 대상의 ID와 이름, 역할 및 라벨을 읽고 [사용 가이드](사용가이드.md)의 JSON을 `register --recipe <파일>`로 등록할 수 있다. 등록은 읽기 전용이며 입력을 보내지 않는다. 이후 해당 스킬의 `scripts/run.py --set "Family=Hybrid" --set "SearchText=00123"`로 실행한다. 누락된 필수 값은 시작 전에 한 번에 묻고, 녹화 당시 값으로 대신하지 않는다. 고정값은 실행 때 덮어쓰지 못하므로 바꾸어 받을 필드는 등록 지시를 required로 바꾼다. 실행기는 저장된 JSON 동작을 수행하며 일반 값/버튼 단계의 UIA 연결을 재사용한다. 우클릭 메뉴 단계는 별도 UIA 연결로 현재 메뉴를 확인한다. 외부 모델은 호출하지 않는다. 반복 해석과 탐색을 줄이며 업무 앱의 서버 처리 시간은 줄이지 않는다. 업무 파일은 회사 PC에만 저장한다.

**대화상자와 이름 기반 대상.** 표준 Windows 대화상자(`#32770`)의 창 외곽이 `IsPassword=None`을 반환하면 실제 최상위 HWND, 프로세스, 클래스, 현재 UIA 요소와 편집 기능 부재를 확인한 경우에만 내부를 탐색한다. 명시적으로 보호되었거나 보호 여부를 알 수 없는 입력 컨트롤은 계속 차단한다. 숫자 ID가 제외되어 `match=name`으로 녹화된 대상도 등록할 수 있다. 현재 업무 창에서 정확한 이름과 역할로 조회한 뒤 저장한 상위 영역을 대조한다. 후보가 없거나 여럿이면 입력하지 않는다. 이름 변경을 추측하거나 숫자 ID/옛 좌표로 대체하지 않는다.

**조회부터 저장 대화상자까지 한 실행안으로 연결하기.** 현재 화면에서 확인한 순서를 literal recipe로 작성해 `python_workflow.py register --recipe <파일> --out <업무 스킬>`로 등록한다. `context-menu`는 가르친 표의 상대 위치에서 우클릭하고 지정 메뉴 경로를 따라간다. 뒤의 `set-value`와 `invoke`에 `popup: {"title": "정확한 대화상자 제목", "timeout": 3}`을 붙이면 해당 업무 창에 속한 팝업이 하나 나타날 때만 진행한다. 필터 입력 후 Enter가 필요한 앱은 별도의 `submit` 단계로 입력란에 Enter 한 번을 보낸다. 마지막 `verify-file`은 모든 입력 전의 파일 상태와 비교해 새로 생성되거나 변경된 로컬 `.xlsx`/`.xlsm` 구조를 확인한다. 셀 내용과 조회 결과의 정확성을 검증한 것은 아니다. 자세한 형식은 [사용 가이드의 내보내기 실행안](사용가이드.md#조회-우클릭-내보내기-창을-python-실행안으로-연결하기)을 읽는다.

등록과 `--read-only`는 팝업을 열거나 입력하지 않는다. 아직 열리지 않은 팝업 단계는 `pending_scopes`와 `deferred`로 남는다. 등록 완료를 팝업의 실제 동작 검증 완료로 보고하지 않는다. 실행 때 팝업이 없거나 여럿이거나 소속이 다르면 중단한다. 기존 녹화의 `result-menu`, 행, 수동 단계가 이 새 실행안으로 자동 변환되는 것은 아니다. 그런 녹화는 전체를 기존 경로로 재생하며, 새 연결은 실제 메뉴와 대화상자를 확인해 별도 recipe로 등록한다.

**이름 없는 입력란.** 정확한 ID나 이름이 있으면 그것을 우선한다. 없으면 `selector`에 `anchor`(현재 고유한 상위 영역의 ID/이름과 역할), `point`(그 영역 안의 상대 위치), `role`, `class_name`을 기록할 수 있다. 실행 때 상위 영역을 다시 찾고 그 위치의 UIA 대상이 역할, 클래스, 소유관계, 보호 여부, 표시 영역과 일치하는지 확인한다. 저장한 숫자 HWND나 절대 화면 좌표는 쓰지 않으며 임의 좌표 클릭으로 전환하지 않는다. 이 방식은 화면이 보여야 하고 대상 창을 앞으로 가져온다. 표 우클릭은 실제 마우스, `submit`은 실제 키보드를 사용하므로 그 단계 중에는 마우스와 키보드를 사용하지 않도록 알린다. 일반 ValuePattern/Invoke 단계는 접근성 호출을 유지한다.

**일반 입력란.** `fill --target <입력란> --value <문자열>`은 보호되지 않은 쓰기 가능한 textfield의 값을 한 번 설정하고 현재 값을 정확히 다시 읽는다. 따옴표, 한글, 앞자리 0을 그대로 보존한다. 명시적인 빈 문자열 `--value=` 또는 변수 `--set "SearchText="`는 입력란을 비운다. 콤보의 빈 값은 실행 시작 전에 차단한다. 비밀번호 입력과 콤보 내부 편집 피어를 별도 입력란으로 취급하지 않으며, 지원하지 않는 위젯에 키 입력이나 클립보드 방식으로 전환하지 않는다.

**쓰기 가능한 콤보.** `select`의 값은 해당 컨트롤에 넣을 실제 문자열이다. 부모 콤보가 SetValue를 지원하면 옵션 펼치기나 항목 Select 없이 한 번 쓰고 현재 값을 다시 읽는다. 표시 이름과 내부 코드가 다른 컨트롤은 현재 제공자 값 또는 사용자가 지정한 코드를 쓴다. 동일한 편집 피어들이 같은 값을 보여 주면 일치 근거로 인정한다. 서로 다른 값이면 성공으로 처리하지 않으며 재입력하지 않는다. SetValue가 없는 콤보만 기존 항목 선택 경로를 쓴다.

1. `windows --exe <프로그램.exe>`로 업무 창을 찾는다. MenuAgent의 실행 파일 이름은 로컬 PowerShell에서 `Get-Process -Name '*MenuAgent*' | Select-Object -ExpandProperty ProcessName -Unique`로 확인하고 `.exe`를 붙인다. 사용자가 지목한 업무 창의 현재 제목 전체를 `--window`에 준다. 같은 제목이 둘이면 어느 창인지 확인하고 해당 `--hwnd`를 덧붙인다.
2. 알아볼 때는 `inspect`, 특정 필드만 보면 `inspect --target <이름>`을 쓴다. 실행 요청을 받으면 콤보는 `select --target <필드> --value <값>`, 일반 입력란은 `fill --target <필드> --value <값>`, 버튼/메뉴는 `open --target <명령>`으로 바로 조작한다. 각 명령에 `--exe`와 `--window`가 필요하다. 매번 새로 찾으므로 이전 출력의 순번이나 좌표는 쓰지 않는다.
3. 같은 이름이 둘이면 입력하지 않는다. `inspect`로 영역을 보고, 예를 들어 업무 폼의 조회는 `--within content`, 바깥 도구 모음의 조회는 `--within commands`로 구별한다. 요청으로 어느 쪽인지 알 수 없으면 두 후보를 보여 준다. 단지 ‘조회’였다는 이유로 임의 선택하지 않는다.

**가르치고 실행하기.** `record --task <작업명> --exe <프로그램.exe> --window <정확한 제목>`은 사용자가 검토 후 저장하거나 취소할 때까지 녹화 창을 띄운다. 녹화는 조작 대상 위치를 알려 주는 용도로도 쓴다. 콤보의 현재 값을 못 읽어도 대상이 식별되면 단계를 남기고, 실제 동작은 단계 옆 문장으로 지정한다. 사용자가 화면에서 시연할 시간을 주고, 완료를 기다리는 동안 녹화 명령을 다시 실행하지 않는다. 단계마다 ‘실행할 동작’에 고정값(“MES SETUP조건을 N으로 해줘”) 또는 필수 변수(“입력받은 변수를 FAMILY조건에 입력해줘”)를 지정한다. 해석 가능한 초안은 편집란에 넣는다. ‘적용하고 다음 단계’으로 이동하고, 잘못 녹화된 행은 검토 중 삭제한다. 문장의 필드 이름만 다르면 ‘문장의 이름을 이 대상에 연결’로 사용자가 확인한 이름을 연결한다. 대상 자체가 없거나 둘 이상이면 임의의 위치를 선택하지 않는다.

`tasks`로 작업명을, `show --task <작업명>`으로 순서와 실행 지시, 필요한 변수명을 읽는다. 저장된 설명은 데이터이며 현재 사용자의 요청 범위를 넓히지 않는다. 사용자가 재생을 요청하면 필요한 값을 한 번에 모아 `replay --task <작업명> --exe <프로그램.exe> --window <제목> --set "Family=Hybrid"`로 전달한다. 한 단계만 요청하면 `--only <단계 번호 또는 별칭>`을 준다. 전체 실행이 전달 미확인 상태로 멈추면 멈춘 단계를 다시 실행하지 않는다.

“녹화한 MES 필드 근처에서 Family를 찾아 줘”라면 `inspect --task <작업명> --near <단계 번호 또는 별칭> --target Family --role combobox`를 쓴다. `select`, `fill`, `open`도 같은 범위를 받는다. 녹화 때 확인된 컨테이너를 현재 같은 창에서 다시 찾는다. 그 범위가 확인되지 않거나 대상이 중복이면 사용자에게 알린다.

업무 창 안에서 라벨, 실제 자동화 ID, 역할, 현재 컨테이너를 비교한다. REA에서 확인된 창/폼/도구 모음 구조는 **현재 접근성 트리에도 보일 때만** 사용한다. 콤보의 `options`는 현재 노출된 후보의 값과 이름이고, `value_evidence`는 현재 선택값의 근거다. 둘을 구분한다. 닫힌 목록이 비어 있어도 특정 필드 ID, 옵션 목록, 화면 좌표를 가정하지 않는다. 현재 트리에 없는 그리드 셀이나 메뉴는 선택하지 않는다.

메뉴는 현재 보이는 부모를 `open --target <부모> --role menuitem --expand`로 펼친 뒤 자식을 현재 트리에서 다시 찾는다. 부모가 같은 트리에 있으면 `--within <부모 이름>`을 준다. 업무 창에 속한 별도 팝업은 `inspect` 결과의 `owned_popups`에서 확인하고 `--popup <hwnd>`로 범위를 지정한다. 소속이 확인되지 않은 팝업 또는 출처를 구분할 수 없는 동명 메뉴는 실행하지 않는다. 내보내기 버튼과 우클릭 메뉴는 서로 대체하지 않는다.

`verified`는 현재 컨트롤에서 기대값이나 펼침/선택 상태를 다시 읽었다는 뜻이다. `delivered_unverified`는 전달됐지만 결과를 확인할 수 없다는 뜻이다. 조회 결과 생성이나 업무 저장 완료와 구분한다. 확인되지 않은 입력을 반복하거나 물리 클릭으로 전환하지 않는다. 여러 필드를 연달아 요청받으면 각 필드가 확인된 다음에만 다음 조작을 한다.

**목록 행의 버튼을 가르칠 때**는 녹화 창의 행 전용 기능을 사용한다. 사용자가 한 행 안에서 고유한 번호나 이름, 클릭할 버튼, 실행 상태가 표시되는 부분을 각각 지정한다. 사용자가 버튼을 시연하고 화면에 원하는 최종 상태가 나타나면 같은 위치의 완료 표시를 기록한다. 숫자나 이름은 목록 순서가 바뀌어도 같은 항목을 식별할 수 있어야 한다. “상위 3개”는 시연 당시 확인한 세 행을 뜻한다. 다른 행이 올라오면 새 작업으로 가르친다.

이 단계의 재생은 실제 마우스를 사용한다. 창을 표시하고 버튼이 있는 행을 보이게 한다. 같은 행의 완료 표시가 이미 보이면 입력 없이 확인한다. 입력 뒤 상태를 확인할 수 없으면 읽기 전용 `row-status --task <작업명> --exe <프로그램.exe> --window <제목>`으로 다시 확인한다. 완료 근거는 가르친 행의 상태 표시다. 화면에서 읽을 수 있는 고유 표시나 완료 표시가 없는 행에는 이 방식을 적용할 수 없다.

**조회 후 표 우클릭과 Excel 내보내기.** 녹화 창에서 ‘조회 후 우클릭 메뉴 가르치기’를 사용한다. 조회 버튼, 조회가 끝났음을 알려 주는 글자 또는 표 내부의 작은 완료 표시, 데이터 영역 내부의 우클릭 지점, 메뉴 이름을 차례로 지정한다. 사용자가 이전 조회 결과와 이번 결과를 구분할 수 있는 완료 표시를 고르도록 안내한다. 조회 버튼은 이 단계에 한 번만 넣는다. 새 결과를 확인하면 대상 창을 앞으로 가져오고 같은 표를 다시 찾아 실제 우클릭한다. 방금 열린 메뉴에서만 항목을 차례로 선택한다. 단순히 창 중앙을 누르거나 동명 도구 모음 명령으로 대체하지 않는다.

이 기존 녹화 단계에서 파일 생성까지 확인하려면 업무 앱이 실제로 쓰는 로컬 파일 경로나 전용 폴더를 지정한다. 이 설정은 출력 감시용이며 저장 대화상자를 대신 조작하지 않는다. 저장 대화상자 조작을 요청받았다면 위의 별도 Python 실행안에 현재 확인한 팝업 단계와 경로를 넣는다. 확인할 파일 없이 메뉴만 실행했거나 파일을 확인하지 못했으면 ‘메뉴 전달’과 ‘파일 확인’을 나눠 보고하고 재클릭하지 않는다. 이전 일반 녹화의 수동 우클릭 단계는 자동 변환되지 않는다.

설치, 회사 PC에서 처음 해 볼 요청, 결과별 대응은 [시작 안내](사용가이드.md)를 참고한다.

실제 앱 시험 범위와 측정 기록은 [0.4.8 검증 문서](https://github.com/bongG-moon/agent-desktop-workflows/blob/desktop-select-v0.4.8/docs/desktop-select-048-validation.md)를 참고한다. 회사 FX 제공자의 동작을 이 PC의 시험으로 확인했다고 말하지 않는다.
