# 이미지 사용과 호스트 응답 크기 점검

대상: Desktop Select 0.4.27 기반 로컬 수정본. 표 위치 보정 수정에 이어 불필요한 이미지 사용과 모델 응답 데이터의 중복을 점검했다. 회사 FX와 실제 Claude Code의 과금 토큰 수를 측정한 결과는 아니다.

## 확인한 경로

- 현재 값을 제공하는 UIA 표: 입력, 조회, 열의 값 비교, 현재 행 더블클릭, 상세값 읽기와 Exit는 캡처 없이 실행한다. 값이 없거나 중복이면 해당 판정을 보고하며 이미지로 대체하지 않는다.
- UIA가 값을 제공하지 않는 표: 등록 실행기는 현재 요소를 먼저 읽는다. 로컬 확인창을 허용받은 경우 PNG를 PC의 Tk 창에 표시한다. 확인 전후와 클릭 전의 픽셀 비교는 Python 내부 검사이며 정상 영수증에 이미지 경로를 반환하지 않는다.
- 모델의 시각적 판단이 필요한 조건 화면 또는 위치 보정: 해당 중단 응답의 이미지와 지점만 사용한다. 저장된 픽셀 표식은 Python 실행기가 읽으며 모델에 풀어 출력하지 않는다.
- `inspect-trial`은 요청 시 현재 화면을 새로 캡처한다. 같은 내용은 같은 프레임 키와 파일을 반환하고, 바뀐 내용은 새 키가 된다. 서버가 화면을 갱신할 수 있어 입력 시간이 같다는 이유로 오래된 캡처를 재사용하지 않는다.

## 추가로 수정한 낭비

1. `learned_tasks.summary`가 최상위 `visual`은 제외했지만 조건의 `when_present.visual`, `dismiss.visual`, `always.visual`과 `row_target.key`는 출력했다. 이 중첩 픽셀 데이터를 제외하고 이름, 위치 단서와 표식 유무만 반환한다. 저장된 녹화와 실제 실행용 표식은 변경하지 않는다.
2. 완료된 등록 실행과 로컬 결과 재개는 `host_action=report_execution_receipt`로 검증된 영수증을 보고하도록 안내한다. `delivered_unverified`를 성공으로 승격하지 않으며 중단된 실행의 복구 정보를 생략하지 않는다.
3. 조건 판단 뒤 입력 전 검사에 실패했을 때 같은 PNG, 창 경계, 조건 단계와 유효시간이면 이전 판단을 최대 한 번 재사용한다. 새 캡처와 입력 직전 검사는 유지한다. 같은 실패가 다시 나면 중단하고 같은 이미지를 반복 요청하지 않는다. 다른 화면, 창 위치, 단계와 만료는 새 판단이 필요하며 입력 여부가 불확실하면 재시도하지 않는다.
4. 조건 이미지 응답에 기존 검증 해시를 `image_sha256`으로 노출해 호스트가 같은 이미지인지 구분할 수 있게 한다. 티켓의 독립적인 일회성 처리와 만료 검사는 유지한다.
5. 메인 스킬과 기능별 참고 문서, 생성 업무 안내는 영수증과 요소 우선, 같은 프레임 중복 읽기 생략, 후속 단계가 검증한 결과의 추가 캡처 생략을 명시한다. 일반 실행에 별도 사전 점검 명령은 추가하지 않는다.

## 실제 Windows 시험

시험용 provider-grid는 문자를 제공하는 WPF 결과 표다. Python의 audit hook으로 `PrintWindow` 조회나 `local_result_review` 로딩을 시도하면 즉시 실패하게 했다. 서로 다른 현재 값과 행, 열 위치에서 다음을 확인했다.

| 경로 | 1회 | 2회 | 3회 | 이미지 호출 |
|---|---:|---:|---:|---:|
| 입력 → 조회 → 일치 행 → Comment → Exit | 1.486초 | 1.246초 | 1.249초 | 0 |
| 입력 → 조회 → 현재 값 비교 | 0.907초 | 0.773초 | 0.771초 | 0 |

두 경로 모두 값 없음과 중복 결과에서도 이미지 없이 중단했다. 전자는 각 실행마다 조회, 상세 창 열기, Exit 각 1회였고 잘못된 행이나 업무 실행 버튼 클릭은 0회였다. 후자는 실제 마우스 허용 없이 동작했고 상세 창을 열지 않았다. 측정에는 로컬 Python 실행 시간이 포함되며 LLM 추론과 네트워크, 사람의 확인 시간은 포함되지 않는다.

근거:

- `.build/image-budget-20261123/provider-no-image/measurements.json`
- `.build/image-budget-20261123/provider-verify-no-image/measurements.json`
- 각 폴더의 audit trace와 실행 영수증

추가 단위 테스트는 중첩 픽셀 데이터가 출력되지 않으면서 원본 녹화가 보존되는지, 완료 상태를 과장하지 않는지, 같은 프레임 키 재사용과 변경 감지, 동일 조건 이미지의 중복 요청 방지와 불확실 입력 재시도 금지를 확인한다. 테스트용 이미지 표식이 포함된 응답의 문자열 크기는 기존 원본의 6% 미만이다. 이는 응답 크기 검증이며 토큰 절감률을 뜻하지 않는다.

전체 Windows 회귀 검사: `python -X utf8 -B -m unittest discover -s tests -v` — **1,266개 통과, 36.010초**. 기록: `.build/image-budget-20261123/full-regression.log`.

이미지 사용을 전부 없애지는 않는다. 읽을 수 없는 화면의 실제 내용을 판단하거나 물리 입력 직전 같은 위치인지 확인하는 데 필요한 캡처는 유지한다. 내부 캡처 횟수를 실제 모델의 이미지 입력 횟수와 혼동하지 않는다.
