# 상세 창 연결과 현재 결과 행 실행 검증

대상은 Desktop Select 0.4.27 기반으로 검증한 수정본이며, 아래 변경을 0.4.28 배포에 포함한다. 회사 업무 앱의 녹화 파일이나 화면을 사용하지 않고, 실제 Windows 시험 앱과 회귀 테스트로 확인했다. 각 측정은 당시 시험 범위의 기록이며, 전체 변경과 최종 회귀 결과는 [0.4.28 릴리스 노트](desktop-select-v0.4.28-release.md)에 정리했다.

## 확인한 문제와 변경

- 입력하지 않고 클릭만 한 필드는 수동 단계가 되면서 알려진 필드 ID와 상위 영역을 잃었다. 이 정보를 읽기 대상의 단서로 유지한다. `Comment 내용 추출` 등의 문장은 입력 동작이 아닌 `read-value`로 만든다.
- 조회 후 더블클릭으로 열린 상세 창의 연결에 시간 간격과 문장 표현이 영향을 주었다. 기록한 조회, 더블클릭, 관련 창의 전후 관계를 사용하고, 읽기와 닫기를 해당 창이 열린 다음 처리한다. 독립 창의 모호성 검사는 유지한다.
- 더블클릭으로 교체된 단계가 알고 있던 표의 식별자를 잃었다. 표의 안전한 ID와 상위 영역만 `result_surface` 단서로 보존한다. 설명 수정과 저장 후에도 유지하며 셀의 업무 값은 식별자로 저장하지 않는다.
- 현재 결과를 여는 요청까지 과거 셀 이미지에 묶였다. 명시적인 `result_row: single|first` 실행을 추가했다. `single`은 한 행, `first`는 요청한 첫 행이다. 현재 UIA 행만 읽으며 값 비교와 녹화 이미지를 사용하지 않는다. 결과가 없거나 모호하면 입력하지 않는다. UIA가 행을 주지 않으면 현재 표를 한 번 확인한 뒤 재개한다.
- 값 비교 요청은 기존 `verify-value`를 유지한다. 지연된 결과를 기다리는 동안 같은 표를 전체 창에서 다시 찾지 않고, 이번 호출에서 확인한 표 식별자로 좁혀 읽는다. 빈 그리기 영역에서는 불필요한 헤더, 값, 행 검색을 생략한다.
- 물리 입력이 필요한 실행은 잠금 또는 보안 화면을 첫 입력 전에 판별한다. UIA만 사용하는 실행은 이 검사를 생략한다. 데스크톱을 전환하거나 잠금을 해제하지 않는다. 첫 시험의 무입력 중단은 잠금 해제 후 같은 요청으로 다시 시작할 수 있다.
- `storage` 응답에 임시 캡처 경로, 정리 시점, 녹화 JSON에 남는 작은 표식의 보관 정책을 추가했다. 이 조회는 캡처, 파일 검색, 삭제를 수행하지 않는다.

## 실제 Windows 시험

기존 조회/상세 시험 앱에 텍스트를 제공하지 않고 UIA 행만 제공하는 모드를 추가했다. 런타임 입력값 세 개와 열 위치를 바꿔 두 정책을 각각 실행했다. 화면 캡처 API가 호출되면 실패하도록 한 상태에서 등록과 실행을 시험했다.

| 정책 | 입력값 | 전체 실행 시간 | 행 관찰 시간 | 조회 / 상세 열기 / 닫기 | 캡처 |
|---|---|---:|---:|---|---:|
| single | LAB-42 | 1.276초 | 0.0287초 | 1 / 1 / 1 | 0 |
| single | LAB-73 | 1.067초 | 0.0279초 | 1 / 1 / 1 | 0 |
| single | PART-A | 1.149초 | 0.0268초 | 1 / 1 / 1 | 0 |
| first | LAB-42 | 1.231초 | 0.0286초 | 1 / 1 / 1 | 0 |
| first | LAB-73 | 1.245초 | 0.0322초 | 1 / 1 / 1 | 0 |
| first | PART-A | 1.162초 | 0.0264초 | 1 / 1 / 1 | 0 |

모든 실행에서 상세 Comment를 읽고 Exit로 닫았다. 잘못된 행이나 열, 별도 실행 버튼을 누른 횟수는 0이었다. 셀 값을 읽은 횟수도 0이었다. 정확한 행 관찰 수치는 `.build/current-result-20261123/native-b/measurements.json`에 기록되어 있다.

빈 표는 약 5초의 기존 결과 대기 한도 후 `result_row_missing`으로 중단했다. 다중 결과의 single 실행은 0.753초에 중단했다. 두 경우 모두 조회 1회, 상세 열기 0회, 이미지 0회였다. 첫 측정 시 실행은 완료됐으나 영수증 요약에서 새 행 관찰 항목을 빠뜨린 시험 도구 문제가 있었다. 요약을 수정한 후 위 8개 경우를 다시 실행했다.

이 시간은 Python 실행 및 시험 앱의 시간이다. Claude Code나 AX Workspace의 모델 응답 시간, 사용자의 로컬 확인 시간, 회사 FX의 소요 시간은 포함하지 않는다. 값 비교를 생략한 정책은 조회의 최신성이나 입력한 ID와 결과 ID의 일치를 검증했다고 보고하지 않는다.

## 복구 및 회귀 범위

전체 회귀 검사 1,316개가 38.100초에 통과했다. 명령은 `python -X utf8 -B -m unittest discover -s tests -q`이며, 결과는 `.build/current-result-20261123/full-regression-final.log`에 보관했다.

녹화 → 설명 수정 → 저장 → 실행안 생성에서 상세 창의 ID와 상위 영역, 더블클릭의 표 식별자가 유지되는지 검증했다. 현재 행 확인이 필요한 첫 시험은 같은 티켓과 프레임에서 상세 단계만 재개하며 앞선 조회를 반복하지 않는다. 등록 업무도 같은 방식으로 재개한다. UIA가 다시 행을 제공하면 이미지 없이 재개한다.

임시 확인 화면은 알려진 표 영역만 표시하고, 행 전용 정책에서는 열 제목 드래그와 글자 재입력을 요구하지 않는다. 다른 셀을 선택하면 확인 체크가 초기화된다. 같은 프레임과 원본 표 경계, 입력 직전 대상 소속, 티켓의 일회성 검사는 유지한다. 확인 후 임시 PNG가 성공과 오류 모두에서 정리되는지도 검사했다.

회사 FX의 실제 녹화와 종단 간 동작, 실제 잠금 상태에서 각 앱의 UIA 지원은 이 시험으로 확인하지 않았다. 앱이 제공하지 않는 행을 녹화 좌표만으로 있다고 판단하거나 무조건 클릭하지 않는다.

## 범용성 재검토

후속 검토에서 앱 이름이나 장비 ID를 고정한 분기는 발견하지 않았다. 다만 문장 패턴과 특정 단계 순서에 결합된 부분이 있어 다음과 같이 보완했다.

| 발견한 결합 | 공통 처리로 변경 |
|---|---|
| 호스트가 읽기 의도를 이해해도 다시 내장 문장 패턴에 맞춰야 함 | `recover --bindings`가 읽기, 현재 행 열기, 후속 창 닫기의 구조화된 의도와 실제 selector를 받음. 원문 유지 |
| 읽기 설명을 자유롭게 바꾸면 요소 단서를 잃거나 저장 오류 | 대상과 창 관계를 보존한 초안으로 저장하고 해석 후 같은 실행 동작으로 연결 |
| 현재 행 실행이 VIEW, 조회 등 버튼 이름 목록에 의존 | 다음 단계의 동작 종류와 같은 창 여부로 판단 |
| 설명 보정 후 double-click-result가 창 열기 동작에서 빠짐 | 원시 시연과 구조화된 동작을 같은 창 열기 의미로 처리 |
| 로컬 확인 후 재개가 읽기와 닫기 순서만 허용 | 저장된 후속 단계의 의존관계를 재연결. 대기, 값 확인, 중첩 창, 메인 창 후속 작업도 보존 |
| 첫 열이 항상 보이는 데이터 셀이라고 가정 | 같은 논리적 행에서 보이는 데이터 셀을 최대 16열 안에서 찾음. 일반 경우 첫 셀 1회 |
| 빈 결과 대기 중 매번 일반 표 탐색 | 이번 호출에서 확인한 표의 고유 식별자를 재사용 |

자연어 의미는 호스트가 해석하고, 엔진은 구조화된 동작과 요소 식별, 창 관계, 실행 결과를 검증한다. 한글 표현이나 다른 언어별 정규식 목록을 늘려 모든 의미를 해결하려는 구조가 아니다. 특정 문장이 해석되지 않으면 원문을 고치거나 설치 코드를 수정하지 않고 기존 연결 명령으로 보완한다. 새 실행 서비스나 모델 호출, 이미지 호출은 추가하지 않았다.

한국어, 스페인어, 일본어 원문을 유지한 구조화된 해석, 다른 앱 및 버튼 이름, 읽기 전용 표시 글자, 설명 편집, 창 생성 지연, 재개 후 단계 의존관계, 숨긴 첫 열을 시험했다. 이는 호스트가 제공한 해석을 받는 코드 경로의 검증이며 Claude 모델 자체의 언어 이해 정확도를 측정한 것은 아니다. 위 실제 Windows 측정은 앞 절의 기본 흐름 시험이며 이번 범용성 추가 항목은 회귀 검사로 검증했다.

여러 창 열기 후보가 남으면 마지막 동작에 임의 연결하지 않는다. 재개할 단계가 이미 지난 다른 창 열기 동작이나 재개 티켓에 없는 필수 변수에 의존하면 그 정보를 확인해야 한다. 앱이 요소를 제공하지 않을 때의 현재 화면 확인도 유지한다.

범용성 보완 후 전체 회귀 검사 1,347개가 53.749초에 통과했다. 결과는 `.build/current-result-20261123/generic-regression.log`에 보관했다. 일반적인 첫 셀 경로 1회, 숨긴 첫 열의 제한된 탐색, 대기 중 표 식별자 재사용을 별도로 확인했으며 새로운 전체 화면 탐색이나 캡처 반복은 추가하지 않았다.
