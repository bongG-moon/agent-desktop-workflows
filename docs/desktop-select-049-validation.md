# Desktop Select 0.4.9 검증 기록

확인일: 2026-11-14. 0.4.0 기반 실행기와 프로젝트 저장을 유지하면서 입력 방식 표시와 선택적인 백그라운드 전용 정책을 추가했다. 실제 Windows에서 실행한 개발용 UIA 제공자 시험이며 회사 FX/FarPoint 시험은 아니다.

## 발견과 수정

기존 CUA Driver에는 UIA 외에도 대상 창으로 메시지를 보내는 background 경로가 있다. Desktop Select의 표 우클릭, 행 버튼과 Enter는 실제 입력을 사용한다. 이 차이는 별도 커서 표시나 독립 데스크톱과 구분해야 한다. [원본 비교와 출처](desktop-select-input-modes.md)에 조사 결과를 기록했다.

추가로 일반 UIA 값 설정도 창을 앞으로 가져오는 현상을 재현했다. 커서는 움직이지 않았으나 SetValue와 Invoke가 들어간 실행 중 전면 창이 대상 창으로 바뀌었다. Microsoft 문서에 따르면 UIA는 기본적으로 동작 전에 대상에 포커스를 준다. [AutoSetFocus 설명](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomation2-get_autosetfocus)

`--background-only`에서는 같은 UIA 클라이언트의 AutoSetFocus를 False로 설정하고 다시 읽어 확인한다. 기존 CUIAutomation이 IUIAutomation2를 제공하지 않으면, 대상 요소를 얻기 전에 CUIAutomation8 클라이언트와 워커를 준비하고 설정을 확인한 뒤 교체한다. 설정 실패 시 첫 입력 전에 중단한다. 시스템 전역 설정이나 고정된 브리지 파일을 수정하지 않는다.

옵션 없는 기본 실행은 기존 방식이다. `--input-plan`은 앱 조회 없이 단계별 입력 요구를 표시한다. background-only 요청에 우클릭, 행 버튼, Enter 또는 전면 확인이 필요한 위치 기반 대상이 섞여 있으면 앞부분도 입력하지 않는다. 최소화된 창을 복원하지 않으며, 실행 직전에도 창 상태를 다시 검사한다.

## 실제 Windows 시험

최종 소스의 전체 자동 테스트 704개가 통과했다. 새 정책의 사전 차단, 기본 실행 유지, 자동 포커스 설정 실패와 COM 참조 정리를 포함한다.

`tools/smoke_background.py`는 별도 시험 창을 앞에 둔 상태에서 다른 시험 앱을 조작한다. 준비 단계의 전면 배치는 측정 구간 밖이며, 동작 구간에는 10ms 간격으로 전면 창과 커서 좌표를 관찰한다. 이 샘플링만으로 모든 순간의 입력 격리를 증명한다고 주장하지 않는다.

| 항목 | 결과 |
|---|---|
| 기존 UIA 자동 포커스 상태 | 직접 SetValue와 등록된 실행안에서 전면 창 변경 관측, 커서는 불변 |
| AutoSetFocus 비활성화 후 동일 흐름 | 전면 창과 커서 좌표 모두 유지 |
| 콤보 직접 설정 | SetValue 1회, 선택값 확인 |
| 등록된 실행안 | 고정 N, 변수 Hybrid 설정 후 조회와 Excel 버튼 각각 1회 호출 |
| 실제 생성 파일 | XLSX 내부 값 N/Hybrid와 조회 세대 대조 |
| 혼합 실행안 | 뒤에 Enter 단계가 있으면 필수 변수 확인과 첫 값 입력 전에 전체 거절 |
| 최소화된 대상 | 복원 없이 거절, 값 쓰기 0회 |
| 최종 Windows ZIP | 새 정책 시험 22개, 기본 콤보/변수 흐름 20개 통과 |

최종 ZIP에서 읽기 전용 등록은 약 0.39초, 입력 계획 확인은 0.18초, 콤보 직접 설정은 0.78초, 등록된 네 단계 실행은 1.21초였다. 기본 실행의 별도 시험에서 등록된 동일 업무 흐름은 1.31초, 직접 명령 네 번은 합계 3.07초였다. 최초 조건 영역 검색은 0.37초였고 전체 트리 스냅샷과 값 읽기를 만들지 않았다. 서로 다른 출력 범위와 한 번씩 측정한 값으로, 모든 앱에 적용되는 속도 보장은 아니다.

## 한계와 배포

이번 실제 파일 생성 시험은 UIA로 호출할 수 있는 Excel 버튼을 사용한다. 우클릭을 사용자 마우스와 독립적으로 실행하도록 구현한 것이 아니다. 기본 우클릭과 Enter 경로는 계속 실제 입력을 사용하고, background-only에서는 거절한다. 앱이 자체적으로 새 대화상자를 열고 포커스를 바꾸는 동작도 격리하지 않는다.

0.4.8에서 수행한 실제 DBeaver 우클릭 내보내기 시험과 성능 측정은 [기존 검증 기록](desktop-select-048-validation.md)에 남겨 두었다. 이번 버전의 회사 FX 또는 DBeaver background-only 검증으로 재사용하지 않는다.

배포 ZIP은 Python 소스와 문서 28개다. 새 EXE, DLL, 드라이버, 외부 모델 연결이나 서비스는 포함하지 않는다. 시험용 C# 프로그램과 생성한 데이터도 ZIP에 포함하지 않는다. 핵심 `win_bridge.py`와 `recorder.py`는 기존 고정 바이트를 유지한다.
