# Desktop Select 0.4.2: 0.4.0 기반 재구성

## 0.4.6: 콤보와 일반 입력란의 변수를 Python 업무 스킬로 실행

기존 콤보 선택 변수에 보호되지 않은 일반 textfield의 고정값과 필수 변수를 추가합니다. 위치를 녹화하면 현재 읽은 문자열 또는 필수 변수 설명 초안을 만들고, 사용자가 동작을 수정한 뒤 Python 업무 스킬로 등록할 수 있습니다. 일반적인 “입력받은 변수를 … 입력란에 입력해줘” 초안의 변수 이름은 편집에서 바꿀 수 있으며 원문은 유지합니다. 문장에 `{SearchText}`처럼 변수 이름을 명시한 경우에는 그 이름과 설정이 일치해야 합니다.

원문 단계의 `fill`은 실행안의 `set-value`와 `selector.role=textfield`로 변환됩니다. 직접 명령도 `fill --target <이름> --value <문자열>`을 지원합니다. 문자열의 한글, 따옴표와 앞자리 0을 보존하며, 명시적인 빈 문자열은 입력란 지우기로 처리합니다. 콤보의 빈 값은 허용하지 않습니다. 필수 변수 누락과 잘못된 값을 첫 조작 전에 확인하므로 앞 단계부터 부분 실행하지 않습니다. 일반 입력란에는 SetValue를 한 번 전달하고 현재 대상의 ValuePattern을 다시 읽어 정확히 비교합니다. 비밀번호 입력과 콤보 내부 편집 피어는 일반 입력란 경로에서 제외합니다.

`register --task`는 콤보, 일반 입력란, 버튼, 명시적 대기로 구성된 전체 작업을 등록합니다. 원문 복사본 `source-task.json`, 실제 문자열과 변수를 담은 `workflow.json`, Python 실행기 `scripts/run.py`를 보존합니다. 등록 때 현재 대상 ID를 확인하고 이후 실행에서는 한 UIA 연결에서 ID로 찾은 현재 대상을 검증합니다. 고정값은 유지하고 `--set "Family=Hybrid" --set "SearchText=00123"`처럼 등록된 변수만 바꿉니다. `--set "SearchText="`는 해당 입력란을 비웁니다. 고정값도 바꾸어 받으려면 지시를 필수 변수로 수정한 뒤 다시 등록합니다.

실행기는 자연어를 코드로 평가하거나 외부 모델을 호출하지 않습니다. 반복적인 모델 해석과 탐색을 줄이는 구조이며 업무 앱의 서버 처리 시간 단축을 의미하지 않습니다. 행, 우클릭 메뉴, 수동 단계가 섞이면 일부 단계만 추출하지 않고 기존 전체 재생을 사용합니다. 0.4.5의 프로젝트별 저장 위치와 0.4.0의 핵심 브리지 및 저수준 녹화기는 유지합니다. 회사 FX의 실제 실행 여부는 현장 인수 시험으로 별도 확인해야 합니다.

## 0.4.5: 프로젝트별 녹화 저장소

프로젝트의 `.claude/skills/desktop-select`에 설치하면 녹화와 파생 실행안은 프로젝트의 `.desktop-select/tasks` 아래에 저장합니다. 스킬 설치 위치를 기준으로 프로젝트를 결정하므로 프로세스의 현재 작업 디렉터리가 달라져도 동일한 저장소를 사용합니다. 일반 ZIP 폴더에서 실행하면 해당 `desktop-select` 폴더 안에 저장합니다.

`DESKTOP_SELECT_TASK_DIR`의 명시적 로컬 저장 경로는 유지합니다. 사용자 홈의 전역 스킬 설치에서는 홈을 프로젝트로 추정하지 않고 이 설정을 요구합니다. `storage` 명령은 결정된 경로를 읽기 전용으로 보여 주며 폴더를 생성하지 않습니다. 저장소의 경로 검증과 원본 작업 덮어쓰기 방지는 유지합니다.

기존 사용자 공용 녹화를 자동으로 읽거나 이전하거나 삭제하지 않습니다. 새 설치는 프로젝트별 작업 목록으로 시작합니다. Python 업무 스킬의 `--out` 위치와 조작 대상 인식, 실제 입력, 결과 검증은 바꾸지 않습니다. 이 변경은 저장소 범위를 분리하는 것이며 실행 속도 개선을 의미하지 않습니다.

## 0.4.4: 설명 초안과 실행 시 대상 재탐색

녹화 편집기는 실제 확인한 라벨, 버튼 이름과 선택값으로 문장 초안을 만듭니다. 선택값이 관찰되지 않은 콤보는 필수 변수 초안을 사용하며, 건드리지 않은 초안도 저장합니다. 미인식 단계의 지원 문장은 `match=query`로 저장하고 현재 화면의 원래 직접 명령 해석기로 다시 찾습니다. 현재 대상을 찾은 뒤에는 같은 ID와 부모 범위를 재확인하는 기존 실행기를 사용합니다. 초기 녹화의 임시 식별자와 좌표는 쓰지 않습니다.

자동 해석되지 않은 문장은 `instruction_draft`로 보존합니다. 호스트 모델이 처음 한 번 의미를 해석하고 `instruct`로 구조화하기 전에는 입력하지 않습니다. 이미 찾았던 대상의 초안은 기존 대상 정보도 유지합니다. 보호된 입력과 행/우클릭 전용 단계는 이 복구 경로에 포함하지 않습니다.

미인식 단계는 재생마다 현재 화면을 살펴봅니다. `python_workflow.py register --task`로 등록하면 그 시점에 확인한 ID를 저장하여 이후 반복 실행은 ID 조회를 사용합니다. 등록의 읽기 관찰과 원문은 보존합니다. 0.4.3 대비 콤보 실행, 제공자 호환 보정, UIA 브리지와 저수준 녹화기는 바꾸지 않았습니다.

`tools/smoke_recovery_editor.py`는 실제 Tk 편집창에서 초안 저장과 다음 단계 이동을, `tools/smoke_semantic_recovery.py`는 합성 Windows UIA 창에서 미인식 녹화의 설명 기반 재생과 실제 XLSX 내용을 검사합니다. 후자는 녹화 결과를 저장 처리기에 주입하므로 실제 마우스 녹화 전체를 검증한 시험은 아닙니다. 회사 FX 현장 인수 시험과 구분합니다.

## 0.4.3: 자연어 녹화와 실행안 연결

0.4.0 기반 실행기를 유지하면서 녹화 원문, 구조화된 지시, 저장 실행안을 연결했습니다. 원문 작업은 보존하고 `execution-plans`에 파생 실행안을 저장합니다. 원본이나 변환 규칙이 달라지면 이전 실행안을 사용하지 않습니다. 원문을 임의의 실행 코드로 평가하거나 외부 모델로 전송하지 않습니다.

`record`가 호환되는 작업의 실행안을 함께 저장하며 `plan`으로 기존 작업에서도 만들 수 있습니다. `instruct --save-as`는 사용 중인 호스트 모델이 처음 한 번 해석한 자유로운 문장과 fixed/required/recorded 지시를 새 작업으로 보존합니다. 이후 `replay`는 전체 호환 작업을 한 UIA 연결에서 실행합니다. `register --task`는 원문 복사본과 Python 업무 스킬을 생성합니다.

중간 버튼에는 사용자가 정한 `wait_after`가 있어야 빠른 연속 실행을 사용합니다. 지정되지 않으면 기존 재생처럼 호출 전달에서 중단합니다. 대기는 결과 완료를 증명하지 않습니다. 행/우클릭/수동 단계가 섞이면 전체 작업에 기존 재생을 사용하고, 일부 단계만 추출하지 않습니다. 한 단계 실행, 별칭 값 지정과 이전 녹화값 기본 동작도 기존 규칙을 유지합니다.

실행안의 대기 단계가 추가되어도 `source_step`과 `source_stopped_at`이 원래 녹화 단계 번호를 알려 줍니다. SetValue가 없는 콤보는 원래의 검증된 항목 선택 엔진으로 재생하며 입력 이후 다른 방식으로 재시도하지 않습니다. 원본/실행안/변수 보존과 실제 Windows 입력은 `tools/smoke_natural_plan.py`로 검사합니다. 이하는 0.4.2 기반 재구성 기록입니다.

## 실제 기준 소스

작업 공간은 `desktop-select-v0.4.0`의 `02fa20e37bcaa66e495389859ea9d101ee619d98`에서 생성했습니다. 0.5/0.6 실행기를 수정한 배포가 아닙니다. 기존 Git 이력과 태그는 보존합니다.

0.4.0의 직접 명령, 녹화 단계 형식, 행 버튼과 결과 표 메뉴 기능을 유지합니다. `scripts/win_bridge.py`와 `scripts/recorder.py`는 원본 바이트를 유지합니다. 라벨 해석도 기존 `targeting.py`를 사용합니다. 0.5/0.6의 `intent_capture`, `intent_tasks`, `intent_replay`, `confirmed_plan`, `registered_runtime`, `registered_profile`, `registered_setup`은 포함하지 않습니다. Windows UIA의 ID 조회만 담당하는 검증된 저수준 도우미는 `control_lookup.py`로 분리해 재사용했습니다.

## 바뀐 부분

| 위치 | 보완 내용 |
|---|---|
| `provider_visibility.py` | IsOffscreen 미제공 시 현재 창 표시, 유효 좌표와 포함 관계로 판단. 최소화된 창은 실제 조작 전에 복원 |
| `provider_values.py` | 동일한 편집 피어 값은 일치 근거로 사용. 값 충돌과 여러 선택 항목은 확인 실패로 유지 |
| `live_action.py` | 쓰기 가능한 부모 콤보에 SetValue 1회, 0.35초 후 현재 대상과 값 재확인. 그 뒤 Expand/Select로 재시도하지 않음 |
| `desktop_select.py` | 직접 명령의 최초 라벨 해석 뒤 확인은 ID와 부모 범위로 수행. 주변 라벨 읽기는 해당 폼으로 제한 |
| `runtime-manifest.json` | 원본 브리지와 녹화기의 검증 정보를 코드 밖에 분리. 호환 보정은 원본을 수정하지 않고 적용 |
| `teach_capture.py`, `learned_tasks.py` | 위치만 지정한 콤보도 지시 편집 가능. 임시 정보 변경 시 지시 유지. 다음 단계 이동, 삭제, 명시적 이름 연결 |
| `python_workflow.py` | 최초 등록한 ID, 고정값, 필수 변수, 버튼과 대기를 하나의 Python 실행에서 처리. 별도 모델 실행안이나 캐시 없이 같은 실행기를 사용 |

쓰기 가능한 콤보에는 실제 입력 문자열을 줍니다. 표시 이름을 내부 코드로 바꾸는 옵션 탐색을 먼저 하지 않습니다. 현재 값이 읽히지 않더라도 요청한 값을 한 번 설정할 수 있지만, 설정 후 읽기가 일치하지 않으면 다음 단계로 진행하지 않습니다.

등록한 Python 업무는 버튼이 확실히 호출됐다는 응답 뒤 명시된 대기와 다음 버튼으로 진행할 수 있습니다. 대기는 서버 조회 완료 증거가 아닙니다. 업무 결과를 확인했다는 뜻으로 보고하지 않습니다. 콤보 불일치, 버튼 호출 실패, 전달 여부 불명은 중단합니다.

## 검증 방식

회사 FX는 이 개발 PC에 없습니다. 회사 환경의 현장 성공 기록을 근거로 문제 조건을 합성 Windows UIA 제공자에 구현해 시험했습니다. 같은 시험창에서 원본 0.4.0의 라벨 및 offscreen 차단을 먼저 재현한 뒤 수정본을 시험했습니다.

시험 조건은 IsOffscreen 미제공, 두 편집 피어의 동일 값, 옵션 좌표 0×0, 펼침 상태 미갱신, 빈 초기값, 실제 값 충돌, 호출 결과 불명, 최소화, 중복 ID, 가려진 대상입니다. 조회와 Excel 시험은 실제 생성한 XLSX를 다시 읽어 N 및 Hybrid/DRAM 값을 대조합니다. 회사 업무나 서버 조회 결과를 검증한 것은 아닙니다.

녹화 편집 시험은 실제 Tk 창에서 문장 초안, 명시적 이름 연결, 다음 단계 이동, 미인식 단계 삭제, N 고정값과 Family 필수 변수 저장을 검사합니다. 실제 UIA 지점 읽기에서도 빈 내부 편집 요소를 부모 콤보의 위치 단계로 기록하는지 검사합니다.

반복 작업의 성능 비교는 같은 합성 창, 네 조작과 동일한 0.1초 대기, 추가 노드 120개 조건에서 수행합니다. 직접 명령 네 번과 등록 실행 한 번은 모두 같은 값을 실제 XLSX까지 전달합니다. 등록 경로의 전체 화면 관찰은 0회, UIA 연결은 1회입니다. 실행을 보호하는 대기 프로세스와 실제 실행 프로세스가 있으므로 OS 프로세스 수는 2개입니다. 처음 발견할 때의 간단 목록과 전체 inspect는 출력 범위가 달라 시간 차이를 그대로 성능 향상률로 해석하지 않습니다.

재현 도구:

```powershell
python -X utf8 -B -m unittest discover -s tests -v
python -X utf8 -B tools/build_desktop_select.py
python -X utf8 -B tools/smoke_040_rebuild.py --help
python -X utf8 -B tools/smoke_040_workflow.py --help
python -X utf8 -B tools/smoke_record_editor.py --help
```

Windows 시험 제공자의 컴파일된 실행 파일은 개발 시험에만 사용하며 배포 ZIP에는 포함하지 않습니다. 최종 시험 개수와 배포 ZIP 확인 결과는 해당 릴리즈 설명에 기록합니다.

## 유지되는 한계

등록 실행의 ID는 처음 실제 창에서 확인해야 합니다. 같은 범위에 ID가 중복이면 임의의 첫 항목을 쓰지 않습니다. 자동으로 생성한 버튼 이름이 다른 명령으로 바뀌면 재확인합니다. 프로그램이나 업무 화면이 바뀌면 새로운 작업으로 등록합니다.

0.5/0.6에서 저장한 intent 작업은 이 버전에서 직접 변환하지 않습니다. 기존 파일을 보존하고 해당 버전으로 사용하거나 이 버전에서 새로 등록합니다. 0.4 형식 녹화는 유지됩니다. 단순 Python 등록기는 고정값, 필수 변수, 버튼, 대기를 담당하며, 행/우클릭 메뉴는 기존 0.4 녹화 기능을 사용합니다. Excel 버튼과 표 우클릭 메뉴를 같은 기능으로 간주해 자동 대체하지 않습니다.

핵심 브리지의 무결성 검증은 유지합니다. 검증을 경고로 낮추거나 사내 정책을 우회하지 않습니다. 업무 스킬과 값은 회사 PC의 로컬 파일에만 저장하며 제품에 외부 모델, 로그 전송, 업데이트 서비스, CUA 드라이버를 추가하지 않았습니다.
