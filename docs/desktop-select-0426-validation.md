# Desktop Select 0.4.26: 실제 Claude Code 호출 검증

검증일: 2026-11-18. 대상은 Windows 시험 앱과 실제 Claude Code CLI 2.1.306입니다. 모델 대신 스크립트가 도구 순서를 결정하는 시험과 구분합니다.

## 수정 범위

- 새 녹화는 기존 `recorder --app` 진입점을 유지합니다. 앱 이름 확인과 녹화창 표시는 한 명령으로 처리합니다.
- 저장 응답은 준비된 작업의 `effective_task`, `preparation`, `next_action`을 제공합니다. 이미 끝낸 준비를 다시 `recover`, `plan`, `inspect`로 확인하지 않도록 호스트 지침도 함께 수정했습니다.
- `register --run`은 기존 등록 검사와 실행기를 한 호출로 연결합니다. 필수 변수와 실제 입력 허용 여부를 확인한 뒤 등록하고, 실행은 한 번만 합니다. 등록만 요청한 기존 명령은 입력을 보내지 않습니다.
- `--auto-repair-frame --allow-physical`을 사용하면 메뉴 입력 전 위치 검사에서 막혔을 때 현재 프레임과 이어갈 명령을 같은 응답에 제공합니다. 호스트는 이미 받은 이미지를 읽고 지점만 보정합니다. 완료된 조회는 반복하지 않습니다.
- `recorder --session ... --wait 8`은 저장 후 처리 중일 때 짧게 기다립니다. 사용자가 녹화 중이면 바로 반환합니다.

기존 UIA 실행기, 프로젝트별 저장, 변수, 메뉴 입력 순서와 동시 실행 조정은 유지했습니다. 추가 모델 서버나 상시 프로세스는 없습니다.

## 시험 조건과 해석

실제 로그인된 Claude Code의 기본 모델과 개인 설정, 플러그인, 후크 및 전체 도구 목록을 유지했습니다. 시험 자료는 별도 프로젝트에 만들었습니다. stdio의 도구별 승인 응답은 시험 앱을 대상으로 하는 지정 공개 CLI 명령만 허용하며, 개인 설정이나 다른 프로그램을 바꾸는 명령은 허용하지 않습니다. 권한 우회 옵션은 사용하지 않았습니다.

녹화창 시험은 실제 네이티브 창 표시와 `recorder_ready` 파일을 확인했습니다. 저장 후 시험은 UIA에서 관찰한 시험 앱의 대상을 사용해 녹화 형식 데이터를 생성한 경우입니다. **사람이 처음부터 시연한 녹화는 아닙니다.** 이후의 등록, 값 설정, 조회, 화면 읽기, 위치 보정과 내보내기는 실제 모델이 선택한 공개 CLI 명령으로 수행했습니다. 시험 하네스는 업무를 대신 실행하지 않았습니다.

각 시간은 단일 로컬 실측이며 회사 FX 및 AX Workspace 서버의 응답 시간을 의미하지 않습니다. 모델 추론, 네트워크, 도구 전달과 기존 후크 시간이 포함됩니다. 기존 사용자 설정 파일은 전후 해시가 같았습니다. 네트워크 제한이나 시험 승인 문법 때문에 입력 전에 끝난 예비 실행은 성공 시간 비교에서 제외했습니다.

## 저장 후 첫 시험과 위치 보정

두 버전에 같은 자연어 요청과 같은 시험 앱을 사용했습니다. MES Setup은 N, Family는 실행 시 Hybrid를 전달하고, 조회 후 결과 표에서 `Export to excel → Active sheet`를 실행하는 작업입니다. 처음 녹화한 지점만 다른 패널이 덮도록 만들어, 실제 모델이 현재 이미지를 읽어 다른 데이터 셀을 골라야 했습니다.

| 항목 | 0.4.25 | 최종 0.4.26 후보 |
|---|---:|---:|
| 첫 실제 값 변경까지 | 19.673초 | 12.312초 |
| 보정 후 내보내기 검증 응답까지 | 46.235초 | 26.865초 |
| 모델 최종 응답까지 | 59.883초 | 42.485초 |
| 업무 관련 도구 호출 | 6회 | 4회 |
| 그중 공개 Python CLI 호출 | 4회 | 2회 |

0.4.25의 실제 모델 순서는 `Skill → register → run → repair-frame → Read → resume`였습니다. 수정본은 `Skill → register --run --auto-repair-frame → Read → resume`으로 진행했습니다. 초기 후보에서는 모델이 재개 명령 앞에 불필요한 도움말을 붙이는 일이 있어, 최종 후보의 보정 응답에 `resume_script`도 추가했습니다. 위 최종 후보에서는 도움말이나 추가 프레임 조회 없이 제공된 명령을 사용했습니다.

양쪽 모두 고정값과 실행 변수, 조회 1회, 우클릭 1회, 메뉴 끝 항목 1회, 잘못된 지점과 다른 메뉴 실행 0회를 확인했습니다. 통합 문서의 `A2=N`, `B2=Hybrid`, `C2=1`을 별도로 읽어 확인했고 원본 녹화 해시는 유지됐습니다. 보정한 상대 지점은 등록본의 `workflow.json`에 반영됐습니다. 모델의 메뉴나 파일 검증 응답 외에 시험 앱 카운터와 XLSX 셀을 독립적으로 대조했습니다.

각 모델 세션에는 별도로 기존 Company Agent 후크의 개인 검증 기록 시도가 1회 있었으며 시험 범위 밖으로 거절했습니다. 위 업무 도구 수에서는 제외했지만 최종 시간에는 포함했습니다. 원본 설정을 바꾸어 후크를 제거하거나 빠르게 보이도록 도구 목록을 줄이지 않았습니다. 모델 속도 및 캐시 차이가 있으므로 이 단일 실측을 일정한 개선율로 일반화하지 않습니다.

로컬 증거: `.build/host-recorded-0425-baseline03/`와 `.build/host-recorded-0426-candidate02/`의 `summary.json`, `phases.json`, `verification.json`, `model-frame-*.png`.

### 보정한 업무를 새 대화에서 다시 실행

시험 앱도 다시 시작하고 실제 모델의 새 세션에서 같은 등록 업무를 실행했습니다. 모델은 `Skill → Bash run.py`로 업무 도구 2회, 공개 CLI 1회만 사용했습니다. 첫 실제 값 변경은 CLI 시작 후 9.739초, 통합 문서 검증 응답은 13.670초, 모델 최종 응답은 25.038초였습니다. 추가 프레임 조회나 보정 재개 명령은 없었습니다.

고정값 N과 변수 Hybrid, 조회와 메뉴 끝 항목 각각 1회, 다른 지점 입력 0회 및 XLSX 셀 값이 다시 일치했습니다. 기존 등록본의 보정 위치가 재시작 후에도 사용됐고 원본 녹화도 보존됐습니다. 이 시험의 앞선 두 예비 실행은 시험 승인 처리기가 등록 폴더로 이동하는 PowerShell/Bash 표기를 허용하지 않아 입력 전에 종료됐습니다. 정확한 시험 폴더 이동만 허용하도록 시험기를 보완한 뒤 실행했으며, 제품 코드는 바꾸지 않았습니다.

로컬 증거: `.build/host-recorded-0426-candidate02/repeat-restarted02/summary.json`, `phases.json`, `verification.json`.

## 회귀 검사

전체 1,071개 중 1,070개 통과, 1개는 기존 조건으로 건너뛰었습니다. 샌드박스 임시 폴더의 하드링크 생성 권한 때문에 실행되지 않은 한 테스트는 일반 임시 폴더에서 해당 테스트만 다시 실행해 통과했습니다. 신규 등록과 첫 실행, 자동 보정 프레임, 후속 명령 안내, 상태 대기의 관련 검사도 통과했습니다.

## 0.4.26에서 Claude Code 준비 시간 재측정

Claude Code는 호출된 스킬의 `SKILL.md`를 읽습니다. 기본 명령은 이 파일에 두고 녹화 편집과 복구, 표 내보내기, 반복 행과 여러 창 연결은 각각의 문서로 옮겼습니다. 첫 파일은 4,743자에서 2,830자가 됐습니다. 등록 업무의 첫 파일에는 해당 업무의 실행 명령과 필수 변수, 실제 입력을 쓸 창을 넣었습니다. 기존 등록본은 `refresh-guide`로 같은 안내를 적용할 수 있습니다. [Claude Code 스킬 작성 안내](https://code.claude.com/docs/en/skills#add-supporting-files)

아래 시간은 새 CLI 프로세스에 **자연어 요청을 보낸 시점**부터입니다. 같은 모델 `claude-sonnet-5-5`가 설치한 스킬과 Windows 시험 창을 사용했습니다. 각 셀은 한 번의 관측값입니다. 네이티브 창 표시, 시험 앱에서 실제로 값이 바뀐 시점, 새 XLSX를 검증한 실행 영수증 도착 시점을 구분했습니다. 첫 시험에는 보정이 필요하도록 저장된 준비 완료 녹화의 표 지점을 가렸습니다.

| 측정 구간 | 기존 0.4.26 | 안내 분리 후 |
|---|---:|---:|
| 녹화창 표시 | 8.422초 | 8.079초 |
| 녹화창이 열렸다는 첫 채팅 안내 | 15.215초 | 11.063초 |
| 저장 후 첫 시험에서 첫 값 변경 | 11.180초 | 9.902초 |
| 위치 보정과 XLSX 검증 완료 | 25.730초 | 23.549초 |
| 등록 업무를 새 대화에서 실행해 첫 값 변경 | 8.470초 | 8.118초 |
| 등록 업무의 XLSX 검증 완료 | 12.371초 | 12.048초 |

녹화 시작에는 언어 모델의 `Skill` 호출과 셸 명령 한 번이 필요했습니다. 첫 시험은 등록과 실행 명령, 현재 표 이미지 읽기, 보정 지점에서 재개하는 명령으로 끝났습니다. 등록 업무 재실행에서는 프로젝트 문서를 다시 읽는 호출이 빠졌고, 실행기 한 번으로 XLSX를 검증했습니다. 시험 앱의 조회와 메뉴 선택은 각 한 번이었고 `A2=N`, `B2=Hybrid`, `C2=1`을 별도로 확인했습니다. 실제 사업장이나 AX Workspace의 지연은 이 표에 포함되지 않습니다. 로컬 측정 파일은 `.build/host-0427-final-comparison.json`입니다.

준비되기 전의 기존 6단계 초안도 별도 Windows 시험 창에서 확인했습니다. 최종 ZIP의 공개 Python 명령으로 원본을 보존하며 한 번의 창 탐색으로 준비하는 데 0.570초, 등록에 0.650초가 걸렸습니다. 첫 시험에서 가려진 지점을 확인한 뒤 재개했고, 다음 프로세스에서는 고친 지점을 이용해 재보정 없이 두 번째 XLSX를 생성했습니다. 이 수치는 Python 실행 시간입니다.

직접 `/업무명`을 호출하는 경우도 따로 시험했습니다. 안내를 분리한 첫 후보에서 Company Agent의 `PreToolUse` 후크는 Claude가 첫 셸 명령을 내렸을 때 이번 요청에서 해당 `Skill` 도구가 성공한 기록을 요구했습니다. 셸 입력 전에 거절돼 모델이 스킬을 호출한 뒤 명령을 다시 내렸습니다. 첫 값 변경까지 12.019초, XLSX 검증까지 15.965초가 걸렸습니다. 이에 등록 업무의 안내에 이 후크가 적용되는 직접 호출 절차를 한 문장으로 추가했습니다. 조건 판단에 화면이 필요한 업무에는 대상 창도 표시합니다.
