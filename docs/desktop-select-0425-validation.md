# Desktop Select 0.4.25 녹화 시작 검증

검증일: 2026-11-18. 요청한 앱 이름으로 녹화창을 여는 경로를 추가했다. 기존 녹화 데이터, 자연어 보정과 Python 업무 실행 경로는 유지한다.

## 제공 로그에서 확인한 병목

AX Workspace 로그의 요청은 13:11:27, 실제 `recorder --request` 호출은 13:14:40이다. 실행 명령을 보내기 전에 193초가 들었다. 도움말, 소스 검색과 읽기, 두 번의 프로세스 조회, 요청 JSON 작성이 이 구간에 포함됐다. 전체 응답은 약 258초였다.

이 로그로는 마지막 PowerShell 호출 대기 시간을 Python 내부 처리 시간과 구분할 수 없다. 소스에서는 창 표시 전 UIA 세션을 만들지 않는다. UIA 및 녹화 훅은 사용자가 시작을 누른 뒤 준비한다.

## 변경

- `recorder --app "FXMENUAGNET"`처럼 앱 이름만 전달한다. Win32 창 메타데이터를 한 번 조회하며 같은 PID의 신원 정보는 재사용한다. 긴 이름의 한 글자 오타와 인접 문자 순서 바뀜을 후보 검색에 반영한다.
- 후보가 하나면 원본 창 제목과 프로세스 수명을 확인하고 기존 편집기를 연다. 복수 또는 미일치일 때는 제목과 실행 파일명이 있는 선택창을 표시한다. 자동으로 업무 입력을 보내지는 않는다.
- 짧은 부모 명령은 실제 창 표시 이벤트를 받아 반환한다. 편집기 프로세스는 저장과 취소까지 유지하며, `recorder --session <id>`로 최종 결과를 받는다. 별도의 상시 서비스는 없다.
- 저장 후 자동 보정 중에는 `recorder_processing`을 보고한다. 호스트가 다시 저장하거나 녹화하라고 요청하는 혼동을 방지한다.
- 기존 `recorder --request`, 직접 `record`, 검토와 보완 시연은 같은 인터페이스로 사용할 수 있다. 새 모듈은 새 녹화 시작 경로에서만 가져온다.

## Windows 설치 ZIP 시험

`tools/smoke_recorder_startup.py`로 공개 0.4.24 ZIP과 0.4.25 ZIP을 각각 별도 폴더에 설치했다. 업무 서버가 없는 별도 WinForms 시험 앱을 사용했다. 창 제목에는 `FxMenuAgent`와 연속 공백, 따옴표, 끝 공백을 넣었다. 회사의 실제 MenuAgent는 아니다.

| 측정 | 0.4.24 | 0.4.25 |
| --- | ---: | ---: |
| 명령 시작부터 실제 녹화창 표시까지, 3회 중앙값 | 0.425초 | 0.747초 |
| 녹화창을 연 상태에서 명령 반환, 3회 중앙값 | 저장까지 명령 유지 | 0.758초 |

이 세 번의 비교 후 200% 화면 배율에서 선택창 행 높이와 하단 버튼 배치를 보완했다. 최종 ZIP 추가 표본 한 건에서는 녹화창 표시 0.714초, 부모 명령 반환 0.722초였다.

기존 프로그램 자체도 빠르게 창을 표시했다. 새 경로에는 자식 프로세스를 분리하는 비용이 조금 더 있지만, 실행 파일명을 얻기 위한 여러 호스트 호출을 없애는 것이 이번 개선의 목적이다. 회사 PC에서 AX Workspace나 Claude Code의 모델 처리와 도구 대기를 포함한 전체 시간은 아직 재측정하지 않았다.

원본 ZIP 프로세스로 녹화창 표시 7건(버전별 3회와 정확한 제목 1회), 선택창 표시 2건(복수 후보와 미일치)을 확인했다. 자기 소유 창만 닫은 뒤 취소 결과를 다시 조회했다. 별도로 합성 녹화 데이터를 실제 Tk 검토/저장 콜백에 넣어 두 버전의 작업 JSON과 검토 결과가 동일하고, 새 세션 조회에 저장 결과와 실행안이 유지되는지 확인했다. 이 저장 시험은 사용자의 실제 마우스 시연 시험과 구분한다.

최종 시험 ZIP SHA-256: `c0939b1ba9240f796c2cd31d8500dc56d22e57543d8df5e6a181cbb6050b3032`.

상세 로컬 결과: 3회 비교 `.build/startup-0425/final02/summary.json`, 최종 ZIP 확인 `.build/startup-0425/final04/summary.json`. 최종 선택창은 항목을 선택한 상태에서도 전체 제목과 프로그램, 하단 버튼이 표시되는지 확인했다. 실행 예:

```powershell
python -X utf8 -B tools/smoke_recorder_startup.py --candidate .build/startup-0425-final/desktop-select-0.4.25-windows-x64.zip --baseline .build/concurrency-0424/desktop-select-0.4.24-windows-x64.zip --work .build/startup-0425/recheck
```

## 호스트 동작과 회귀 범위

수정된 SKILL.md만 읽는 독립적인 모의 호스트에 같은 녹화 요청을 주었다. 첫 호출로 `recorder --app "FXMENUAGNET"`을 선택했고, 도움말이나 소스 탐색을 선행하지 않았다. 이는 실제 AX Workspace 또는 Claude Code 세션에서의 실측이 아니다.

전용 테스트는 프로세스 수명 재검증, 오타와 중복 후보, 준비 이벤트 시점, 종료/저장 경합, 저장 후 보정 상태, 경로와 인자 보존을 검증한다. 실제 업무 실행기의 창별 순차 처리와 다른 창 백그라운드 병행 처리 코드는 이번 변경에 포함되지 않는다.

전체 회귀 검사 1,043건을 실행했다. 1,041건 통과, 1건 건너뜀, 1건은 Windows 샌드박스의 임시 하드링크 생성 제한으로 실행되지 못했다. 해당 하드링크 보호 테스트를 일반 권한에서 별도로 실행해 통과했다. 최종적으로 실패가 남은 검사는 없으며, 건너뛴 한 건을 통과로 계산하지 않는다. 원본 녹화 요청과 저장, 실행안, 일반 업무 실행 및 동시 실행 관련 기존 테스트를 포함한다.
