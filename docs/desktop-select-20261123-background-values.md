# Desktop Select 0.4.27 백그라운드 실행과 현재 입력값 검증

2026-11-23, Windows x64 테스트 프로그램에서 검증했습니다. 회사 SmartFX 실행 결과나 Claude Code/AX Workspace의 모델 응답 시간을 측정한 자료는 아닙니다. 0.4.26에서 검증한 수정 내용을 0.4.27로 배포합니다.

## 수정 내용

일반 UIA 실행은 기존 설치본도 백그라운드로 동작했습니다. 문제는 뒤에 우클릭이나 Enter가 있는 혼합 업무에서 앞선 UIA 동작까지 자동 포커스 억제 대상에서 빠지는 조건과, 이름 없는 입력란의 위치 확인이 전면 창을 요구하는 경로였습니다.

- UIA 세션을 시작할 때 한 번 자동 포커스를 억제합니다. 혼합 업무도 앞선 UIA 단계는 같은 설정을 사용합니다.
- 위치 기반 입력란은 고유한 상위 영역 안의 UIA 요소와 상대 위치로 식별합니다. 다른 앱의 창이 위에 있어도 전면화하지 않습니다. 탐색은 해당 영역에서 깊이 8, 자식 확인 150개로 제한합니다. 역할, 클래스, 소속, 보호 여부, 위치 변경과 모호성 검사는 유지합니다.
- 실제 마우스와 Enter 단계는 기존 전면화 및 입력 잠금을 유지합니다. 우클릭부터 메뉴 선택까지의 잠금은 변경하지 않았습니다.
- 과거 이미지 클릭으로 저장한 비교 설명을 실행안 생성 때 다시 해석합니다. 지원하지 않는 복합 비교 문장은 원문과 위치 단서를 호스트에 넘깁니다.
- 비교값은 현재 실행 변수 또는 명시한 고정값입니다. 같은 입력란의 최근 대입값을 사용하며, 새 창은 자신을 연 단계의 범위에서 입력값을 연결합니다. 관계없는 창의 입력은 가져오지 않습니다.

값 연결은 로컬 실행안 변환에서 처리하므로 UI 조회나 대기가 추가되지 않습니다. 이미 이미지 동작으로 등록한 독립 `workflow.json`은 원본 녹화에서 한 번 다시 생성해야 합니다. 원본 녹화는 변경하지 않습니다. 기존 `verify-value`와 `parameter` 업무는 그대로 현재 입력값을 사용합니다.

## 실제 Windows 검증

수정본 전체 회귀 테스트 1,236개가 35.624초에 통과했고, 버전을 0.4.27로 올린 최종 배포본도 1,236개가 37.714초에 통과했습니다. 위치 기반 대상은 최소화 후 제공자에 오래된 좌표가 남는 경우도 입력 전에 중단하는 테스트를 포함합니다. 로그는 `.build/bg-value-20261123/unittest-final.log`와 `.build/release-0427/unittest.log`입니다.

`tools/smoke_background.py`의 45개 확인 항목을 모두 통과했습니다. 전면 창과 마우스 위치를 10ms 간격으로 관찰하고 테스트 앱의 실제 호출 기록과 대조했습니다.

- 가려진 이름 없는 입력란은 기본 실행과 `--background-only`에서 각각 값을 한 번 설정했습니다. 전면 창과 마우스 위치는 유지됐습니다.
- 혼합 업무의 UIA 동작 4회 동안 다른 창이 전면을 유지했습니다. 마지막 Enter 단계에서만 대상 창이 전면으로 바뀌었고 Enter는 한 번 전달됐습니다.
- `--background-only`는 물리 입력이 포함된 업무와 최소화된 창을 입력 전에 차단했습니다.
- 등록한 표 검증 업무에 `LAB-42`, `LAB-73`, `PART-A`를 차례로 제공했습니다. 행과 열 위치가 바뀌어도 현재 값과 지정한 열로 비교했고, 매번 조회 1회와 이미지 호출 0회를 확인했습니다.
- 표 비교는 최초 0.0818초, 요소 정보를 재사용한 후 0.0515초와 0.0446초였습니다. 값이 없는 경우 기존 제한 대기 후 5.768초에 중단했고, 중복 값은 0.720초에 중단했습니다. 이 경우 이미지 확인이나 상세창 열기로 진행하지 않았습니다.

표 검증 시험은 `tools/smoke_registered_result.py --provider-grid --verify-only --repeat 3` 경로입니다. 상세창 더블클릭까지 수행한 실측으로 해석하지 않습니다. 현재 값에 맞는 행이 더블클릭에 전달되는지는 별도 컴파일부터 실행까지의 회귀 테스트에서 검증했습니다.

## 기존 경로의 시간 비교

기존 `test_cua` 설치본과 수정본을 같은 테스트 앱에서 각각 3회 실행한 중앙값입니다. Python 프로세스 시작과 결과 반환까지의 시간이며 호스트 모델과 도구 호출 대기는 포함하지 않습니다.

| 동작 | 기존 | 수정 |
|---|---:|---:|
| 콤보 설정 | 0.5085초 | 0.4526초 |
| 일반 입력 | 0.4939초 | 0.4557초 |
| 버튼 호출 | 0.4266초 | 0.4417초 |
| 등록 업무 4단계 | 0.6287초 | 0.6150초 |
| 등록 업무 엔진 내부 | 0.1430초 | 0.1395초 |

각 실행의 UIA 속성, 탐색, 패턴, 좌표 읽기 횟수는 기존과 수정본이 동일했습니다. 이 시험에서 추가 탐색으로 인한 지연은 관찰되지 않았습니다. 표본이 작으므로 수치 차이를 일반적인 속도 향상으로 단정하지 않습니다.

기본 실행은 최소화된 창을 복원할 수 있습니다. 앱이 스스로 새 창을 띄우거나 포커스를 바꾸는 동작은 별개입니다. UIA 요소를 제공하지 않는 앱까지 백그라운드 실행을 보장하는 변경은 아닙니다.

최종 ZIP의 63개 파일을 `test_cua` 설치본과 대조했고, 기존 녹화는 유지했습니다. 설치본으로 같은 백그라운드 시험을 다시 실행해 45개 확인 항목을 통과했습니다.

재현 로그는 `.build/background-candidate-20261123-a/`, `.build/background-installed-final-20261123/`, `.build/background-timing-20261123.json`, `.build/provider-currentvalue-20261123/`에 남겼습니다.
