# Desktop Select 0.4.28

## 2026-11-24 갱신

기존 0.4.28 사용자는 이번 Windows ZIP을 다시 내려받아 프로젝트의 `.claude/skills/desktop-select`를 교체하세요. 기존에 등록한 업무에도 새 실행 안내를 적용하려면 `python_workflow.py refresh-guide --skill <업무 스킬 폴더>`를 실행하세요. 기존 녹화로 계속 작업할 수 있습니다.

- **녹화 시작과 저장**. 앱 이름이나 창 제목의 일부를 말하면 한 번의 명령으로 녹화를 시작합니다. 앱을 생략하면 창 선택 화면이 열립니다. 저장 직후 시험은 같은 녹화 세션에서 준비한 내용을 이어받습니다.
- **키보드 동작**. Enter와 지원하는 탐색 키, 단축키는 녹화한 창과 입력 대상을 확인한 뒤 한 번씩 전달합니다. 키 앞뒤의 기본 간격은 0.8초이며 연속 키 사이에서는 이 간격을 공유합니다. 고정값이나 변수값을 입력하는 단계에는 이 대기를 추가하지 않습니다.
- **첫 시험과 보정**. 조회한 표 후보를 한 번 읽어 열을 구분합니다. 메뉴 위치를 보정할 때도 `--summary`를 유지하며 앞선 조회를 반복하지 않고 이어갑니다. 완료된 첫 시험의 요약은 긴 필드 값을 `observations`에 한 번 담습니다.
- **등록 업무 재실행**. 이번 요청에서 실제 입력을 허용한 경우 실행 안내에 그 옵션을 포함한 첫 명령을 제공합니다. 요약 모드에서 마지막 단계의 Excel 파일 생성까지 검증되면 첫 시험과 등록 실행 모두 종료 코드 0을 반환합니다.

Windows 회귀 테스트 1,447개가 통과했습니다. 로컬 Claude Code와 Windows 시험 앱에서는 녹화의 첫 시험, 메뉴 보정, Python 업무 스킬 등록과 재실행을 확인했습니다. 상세 조회 시험에서는 녹화 때와 다른 ID를 넣어 6단계를 한 번에 실행하고 상세 창의 Comment와 닫힘을 확인했습니다. 4,096바이트 메모를 읽는 별도 시험에서 요약 응답은 8,830바이트에서 4,721바이트로 줄었습니다. 이 수치는 UTF-8 응답 크기입니다.

11월 24일에는 설치된 Claude Code의 별도 세션 두 개에서 Windows 시험 앱의 합성 녹화를 자연어로 실행했다. 첫 요청에서 Excel 출력까지 26.42초가 걸렸고 공개 명령 3회와 화면 읽기 1회로 위치 보정 및 등록을 마쳤다. 반복 요청에서는 공개 명령 1회로 14.79초 만에 Excel이 생성됐고 화면을 다시 읽는 횟수는 0회였다. 반복 실행기 내부 처리 시간은 2.81초였다. 두 Excel 파일에서 시험 조건과 실행 순번을 확인했다. 이 시간에는 각 요청을 전달한 뒤의 로컬 모델 응답 시간이 포함된다.

## 2026-11-23 최초 배포

저장한 녹화의 첫 시험에서 메뉴 위치가 맞지 않을 때 같은 조회 결과에서 보정해 이어가고, 현재 결과 행과 상세 창을 명시한 의도에 따라 실행하도록 개선했다. 0.4.27 기반으로 검증한 변경을 0.4.28 배포에 포함한다.

## 변경 내용

- **첫 시험의 메뉴 보정과 재개**: `try-recording`의 메뉴 위치 실패에도 `inspect-menu-trial`과 `resume-menu-trial`을 제공한다. 이미 완료한 조회를 반복하지 않고 같은 시험에서 이어간다. 보정 위치는 원본을 보존한 실행용 사본과 등록 업무에 반영한다. 입력 전달이 불확실한 실패는 재개 대상으로 만들지 않는다.
- **현재 결과 행 열기**: 명시적인 `result_row: single|first`로 현재 유일한 행 또는 첫 행을 연다. UIA가 제공하는 현재 행을 사용하며 과거 셀 이미지나 입력값 일치를 조건으로 추가하지 않는다. 행이 없거나 선택이 모호하면 입력 전에 중단하고, UIA가 행을 제공하지 않으면 현재 표 확인 후 재개한다. 값 일치를 요청한 업무는 기존 `verify-value`를 사용한다.
- **상세 창의 읽기와 닫기 연결**: 클릭만 한 읽기 대상의 필드 ID와 상위 영역, 더블클릭의 표 식별자를 설명 편집과 저장 후에도 유지한다. 조회, 더블클릭과 관련 창의 관계로 후속 읽기와 닫기를 연결한다. 여러 창 열기 후보가 남으면 임의로 연결하지 않는다.
- **구조화한 의도 연결**: `recover --bindings`가 호스트가 해석한 읽기, 현재 행 열기와 후속 창 닫기 의도를 실제 대상 정보와 함께 받는다. 원문을 유지하며 특정 앱 이름, 버튼 이름이나 언어별 문장 목록에 의존하지 않도록 했다. 엔진은 대상과 창 관계, 실행 결과를 검증한다.
- **등록과 모델 입력의 중복 감소**: 원본 녹화와 실행안의 값, 동작, 창, 대상 및 필요한 이름 증거가 일치하면 등록 전 전체 읽기 검사를 반복하지 않는다. 이 조건의 `register --task --run`은 등록 전용 프로세스 없이 실행 프로세스 한 번을 사용한다. 실제 실행의 현재 요소 확인은 유지한다. 기본 안내는 9,189에서 6,223 UTF-8바이트로 줄였다.
- **현재 화면 확인과 이미지 재사용**: 현재 행만 확인하는 화면은 열 제목 드래그나 글자 재입력을 요구하지 않는다. 이미지 해시와 동일 여부를 반환해 이미 본 동일 이미지를 모델이 다시 읽지 않도록 안내한다. 현재 화면의 로컬 캡처와 프레임, 표 경계, 대상 소속, 일회성 재개 검사는 유지한다.
- **잠금 상태의 입력 차단과 재시도**: 물리 입력이 필요한 업무는 첫 입력 전에 입력 가능한 데스크톱인지 확인한다. UIA만 사용하는 업무에는 이 검사를 추가하지 않는다. 잠금으로 입력 없이 중단한 첫 시험은 사용자가 잠금을 해제한 뒤 같은 요청으로 다시 시작할 수 있다. 데스크톱 전환이나 잠금 해제는 수행하지 않는다.
- **캡처 보관 위치 안내**: `storage` 응답에 임시 PNG의 경로와 정리 시점, 녹화 및 등록 업무 JSON에 포함되는 작은 이미지 표식의 보관 정책을 추가했다. 이 조회는 캡처, 파일 검색이나 삭제를 하지 않는다.

## 검증 결과

전체 Windows 회귀 검사 **1,381개가 44.601초에 통과**했다. 명령은 `python -X utf8 -B -m unittest discover -s tests -q`이며 로그는 `.build/time-budget-20261123/regression-final.log`다. 아래 실제 Claude Code 시험 이후 보완한 잠금 거절 후 재시도와 이름 증거 없는 빠른 등록 경로는 별도 회귀 검사에 포함했다.

현재 행과 상세 창은 실제 Windows 시험 앱에서 `single`과 `first` 정책에 각각 세 입력값을 적용해 확인했다. 6회 모두 조회, 상세 열기와 닫기 각 1회, 화면 캡처와 잘못된 클릭 0회였다. 실행 시간은 1.067~1.276초였다. 빈 표와 여러 행의 `single` 요청은 상세 창을 열지 않고 중단했다. 이 시간은 Python과 시험 앱의 시간이며 모델 대기를 포함하지 않는다.

실제 설치된 Claude Code에서도 합성 녹화의 첫 시험, 위치 보정, 등록과 등록 업무 재실행을 확인했다. 현재 Windows 요소로 준비한 합성 기록이며 **사람의 실제 시연을 새로 녹화하거나 회사 FX를 시험한 결과는 아니다.** 모델이 공개 실행 명령과 보정 지점을 선택했고 하네스는 시험 앱 상태와 출력 통합 문서를 별도로 확인했다.

| 사용자 요청에서 측정한 구간 | 첫 시험, 보정, 등록 | 등록 업무 재실행 |
|---|---:|---:|
| 첫 입력까지 | 11.546초 | 9.780초 |
| 파일 생성 검증 응답까지 | 27.195초 | 13.173초 |
| 스킬 등록 응답까지 | 32.272초 | 해당 없음 |
| 공개 실행 명령 | 3회 | 1회 |
| 모델의 이미지 확인 | 1회 | 0회 |
| 조회 / 우클릭 / 내보내기 | 1 / 1 / 1 | 1 / 1 / 1 |
| 잘못된 지점 클릭 | 0회 | 0회 |

재실행은 **같은 입력 조건**에서 보정 지점을 재사용했고 새로운 이미지나 위치 보정이 필요하지 않았다. 재실행의 엔진 준비는 0.0999초, 엔진 전체 실행은 2.9668초였다. 위 표는 모델과 도구 대기를 포함한 요청 기준 시간이며 엔진 시간과 구분한다. 사용자 설정, 모델 선택, 플러그인과 기존 후크는 변경하지 않았다.

안내의 바이트 감소율 32.3%는 토큰 감소율이 아니다. 모델 시험은 단일 환경의 관측값이며 녹화 시작 속도의 개선은 확인하지 못했다. 변경 전 첫 시험은 중간에 실패하고 변경 후는 등록까지 완료했으므로 전체 시간이나 누적 토큰 차이로 절감률을 계산하지 않는다. 회사 환경의 성능, 실제 잠금 상태에서 각 앱의 UIA 지원, 모든 언어의 모델 해석 정확도는 이 검증으로 보장하지 않는다.

## 업데이트와 증거

설치한 `desktop-select` 스킬 폴더를 0.4.28 배포본으로 교체한다. 프로젝트의 `.desktop-select` 녹화와 기존 등록 업무는 유지한다. 첫 시험에서 수정한 메뉴 위치를 이후에도 사용하려면 완료 응답의 `effective_task`와 `register_args`가 가리키는 실행용 사본으로 등록한다. 설치와 실행 절차는 [사용가이드](../skills/desktop-select/사용가이드.md)를 따른다.

- [상세 창 연결과 현재 결과 행 검증](desktop-select-20261123-detail-results.md): 실제 Windows 행 실행과 범용 의도, 재개 범위.
- [대기 시간과 모델 입력량 검증](desktop-select-20261123-time-budget.md): 녹화 시작 비교, 첫 시험 보정, 실제 Claude Code 재실행과 측정 한계.
- 로컬 모델 시험 증거: `.build/time-budget-20261123/workflow-host-fixed/recorded-benchmark.json`, `phases.json`, `repeat/phases.json`, `verification.json`.

모델 로그, 시험 녹화, 화면과 통합 문서는 로컬 검증 자료다. 배포 ZIP에는 실행 코드와 안내를 포함하며 이 시험 자료는 포함하지 않는다.
