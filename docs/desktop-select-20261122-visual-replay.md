# 화면에 그린 버튼의 녹화와 재생

Windows에서 Desktop Select ZIP을 프로젝트별로 새로 설치하고, 실제 Claude Code에서 녹화창 열기, 저장한 녹화 시험, 업무 스킬 등록, 새 세션에서 등록본 실행을 확인했다. 녹화창에서 시작과 저장은 검증자가 조작했다. 시험 앱의 시연은 실제 마우스 입력 한 번으로 진행했다.

이 PC의 최종 검증 ZIP은 **desktop-select-0.4.26-windows-x64.zip**이다. SHA-256은 `d3c364174616894854f7dad6076c1a2e83254de7cce901fdbdf57c6a8f2b39ba`다. 아래 링크는 이 작업 폴더에 보관한 설치본과 측정 기록을 연다. [검증한 ZIP](../.build/visual-multi-verified-20261122/package/desktop-select-0.4.26-windows-x64.zip) [체크섬](../.build/visual-multi-verified-20261122/package/desktop-select-0.4.26-windows-x64.zip.sha256)

게시용 패키지는 같은 버전 0.4.26으로 다시 묶었다. 사용가이드의 예전 Enter 안내 한 곳을 실제 동작인 Ctrl+Enter로 맞췄으며, 위 실기 검증본과 실행 코드 및 나머지 파일의 내용은 같다. 게시 ZIP의 SHA-256은 `926c88cded2bd8d2b663cd541187aaf491c3793b9fa3652cfbb5752c66bbf503`이다. ## 위치가 바뀌는 버튼

| Windows 시험 앱 | Windows가 알려준 대상 | 확인한 효과 |
| --- | --- | --- |
| Windows Forms | 이름과 실행 기능이 없는 개별 아이콘 대신 도구 모음 한 개 | 다색 버튼을 녹화했다. 버튼을 옆으로 옮겨 시험하고 다시 옮겨 등록본을 실행했다. 시연을 포함한 클릭 횟수는 1 → 2 → 3이었고 빗나간 클릭은 0회였다. |
| WPF | 자식 요소와 실행 기능이 없는 도구 모음 한 개 | 단색 아이콘을 가리키면 바탕색이 달라진다. 다른 위치에서 일반 배경색으로 돌아온 버튼을 찾아 재생했다. 클릭 횟수는 1 → 2 → 3이었고 빗나간 클릭은 0회였다. |

두 앱 모두 시험용으로 만들었다. 각 앱이 독립적으로 기록하는 클릭 횟수와 화면상 버튼 위치를 사용했다. 별도 시험에서는 동일한 버튼을 두 곳에 그리자 재생기가 입력 전에 멈췄다.

최종 ZIP으로 Windows Forms에서 버튼 가로 좌표를 175 → 357 → 175로, WPF에서는 279 → 811 → 279로 옮겼다. 두 앱 모두 시연, 시험 재생, 등록본 실행에서 각각 한 번씩 눌렸다. 같은 모양이 두 개일 때 멈추는 시험도 최종 ZIP에서 재실행했다. [두 앱의 실제 Claude Code 검증 기록](../.build/visual-multi-verified-20261122/evidence-forms-wpf.json) [같은 모양 버튼 검사](../.build/visual-multi-verified-20261122/duplicate-icon/summary.json)

## 설치된 Notepad++에서 확인한 차이

시험 문서를 별도 설정으로 연 Notepad++에서는 ‘확대’ 버튼에 마우스를 올리면 이름이 나타났다. 마우스를 치우자 Windows 도구 모음의 자식 32개 모두 이름과 ID가 비어 있었다. 이름으로 저장한 초기 녹화의 시험 재생은 대상을 찾지 못했고, 이때 확대값은 1에 머물렀다.

수정본은 이런 표준 Windows 도구 모음에서 버튼 중앙 25×25픽셀을 녹화한다. 재생 시 같은 창의 도구 모음 안에서 현재 활성화된 버튼과 대조한다. 그림이 같은 버튼이 여러 개면 멈춘다. 이름만 담긴 예전 녹화에 이 기능을 적용하려면 해당 버튼을 한 번 다시 시연해야 한다.

최종 ZIP으로 새 프로젝트에서 녹화해 `editor-button-demo`로 등록했다. 화면 확대값은 같은 시험 문서의 편집기에서 독립적으로 읽었다. [Claude Code 실행 및 확대값 기록](../.build/visual-multi-verified-20261122/evidence-npp.json) [등록된 스킬](../.build/visual-multi-verified-20261122/npp/project/.claude/skills/editor-button-demo/SKILL.md)

| 동작 | 시작 | 시연 후 | 첫 시험 중단 후 | 새 시험 재생 후 | 등록 후 | 새 Claude Code 대화에서 등록본 실행 후 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Notepad++ 확대값 | 0 | 1 | 1 | 2 | 2 | 3 |

첫 시험은 클릭 직전 전경 창 또는 입력 상태가 달라져 `foreground_or_input_changed`로 멈췄다. 입력 전송은 `false`였고 확대값도 1로 유지됐다. 같은 시험을 두 번 요청하자 동일한 시험 ID의 결과가 반환됐다. 이후 검증자가 새 시험 ID를 명시해 다시 실행했을 때 확대값이 2가 됐다. 등록은 입력 없이 끝났고, 별도 대화에서 등록본을 실행하자 한 번 더 확대됐다. [첫 중단](../.build/visual-multi-verified-20261122/npp/final/summary.json) [새 시험과 등록](../.build/visual-multi-verified-20261122/npp/final-4/summary.json)

이 PC에서 등록된 확대 동작 한 번의 **실행기 시간은 0.4186초**, **Claude Code 전체 시간은 26.52초**였다. 전자는 창 확인부터 실행 결과 반환까지이며, 후자는 CLI 시작과 모델 응답, 도구 호출, 대화 마무리를 포함한다. 호스트에서 관찰한 도구 호출 구간은 3.02초였다. [등록본 실행 영수증](../.build/visual-multi-verified-20261122/npp/run/summary.json)

## 메뉴와 여러 단계의 실행

등록한 업무의 실행기는 한 번 호출되어 순서대로 단계를 처리한다. Windows 시험 앱에서 조건 설정, 검색값 입력, 조회, 명시한 대기, 내보내기를 실행했다. 한 번의 접근성 연결을 사용했고 전체 창 트리를 다시 훑은 횟수는 0회였다. 독립 카운터와 출력 Excel 파일에서 입력값, 조회와 내보내기가 각각 한 번 반영된 것을 확인했다. 사내 MenuAgent 운영 서버는 이 시험에 포함되지 않았다.

별도로 진행한 설명 기반 등록 경로 시험에서 **5단계 Python 실행 명령 전체는 0.809173초**였다. 조건 설정 109ms, 검색값 입력 107ms, 조회 15ms, 업무에 지정된 대기 101ms, 내보내기 17ms가 걸렸다. 전체 시간에는 실행기를 시작하고 창을 확인해 종료하는 시간도 포함한다. 이 검사는 합성 업무 앱을 대상으로 실행했으며 Claude 응답 시간은 측정 범위에서 제외했다. [등록 전후 단계별 시간과 출력 검증](../.build/visual-generic-20261121-semantic-recovery-a/results.json)

콤보에 이미 원하는 값이 있으면 다시 쓰지 않는다. 쓰기 직후 값을 확인할 수 있으면 기존의 350ms 대기를 생략한다. 선택 전용 목록에 없는 값은 입력 전에 멈추고, 자유 입력란에서 앱이 쓰기 중 오류를 반환하면 재전송하지 않는다. Windows 메뉴와 콤보 16건, 설명으로 복원한 업무의 재생과 등록 19건을 확인했다.

최종 소스의 비대화형 검사 1,162건과 녹화 및 저장창 검사 50건이 모두 통과했다. 게시 전에는 전체 1,212건을 한 프로세스에서 다시 실행해 모두 통과했다. 배포 파일 63개의 내용도 소스, ZIP, 세 프로젝트의 설치본에서 일치했다. ## 사용 범위

서로 다른 두 버튼의 모양이 같거나, 창이 가려지거나, 보호된 입력란과 겹치면 근거를 확인할 때까지 클릭하지 않는다. 시연 직전의 화면을 확보하지 못해 수동 검토 단계가 남은 사례도 있었다. 앱이 입력을 받았다는 영수증만으로 업무 결과를 확인할 수 없는 경우에는 앱 상태나 산출물을 별도로 확인한다.
