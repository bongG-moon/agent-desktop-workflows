# 결과 표 위치 자동 보정 검증

대상: Desktop Select 0.4.27 기반 수정본. 회사 FX에 접근하지 않고 보고된 경계 조건을 단위 테스트와 별도 Windows 시험 앱에서 재현했다. 이 문서는 로컬 수정본의 검증이며 공개 릴리즈 반영 여부와 구분한다.

## 원인과 변경

보고된 캡처는 1296 × 839이고 표 상대 경계는 `[10, 197, 1393, 562]`였다. 표 오른쪽은 1403으로 이미지 밖이지만 아래쪽 759는 이미지 안이다. 이 수치만으로 DPI 오류나 양쪽 107px 오차를 확정할 수 없다.

기존 확인창은 원본 표 경계 전체가 PNG에 포함되어야 했다. 재개 시 픽셀 비교도 같은 조건을 요구해, 확인창만 잘라 표시해도 다음 검사에서 실패할 수 있었다. `IsOffscreen=None`인 큰 표는 그보다 앞선 컨테이너 검사에서도 중단됐다.

수정본은 다음과 같이 처리한다.

- 원본 표 요소와 원본 경계는 보존하고 현재 HWND 캡처와의 교집합만 표시한다. 위 사례는 `[10, 197, 1286, 562]`로 표시한다.
- PNG 크기와 캡처 크기를 확인한다. 열과 셀 선택은 잘린 화면 좌표를 전체 PNG 좌표로 되돌린다.
- 읽기용 표 컨테이너에 한해, `IsOffscreen=None`이면 실제 창과 겹치는지 확인한다. 다른 앱 요소, 보호 요소, 최소화, 명시적 화면 밖 상태와 겹치지 않는 영역은 허용하지 않는다. 셀 읽기와 클릭 검사는 별도로 유지한다.
- 사용자가 현재 열과 셀을 확인하면 같은 글자가 다른 열에도 있다는 이유로 전체 이미지에서 다시 찾지 않는다. 이 경로는 해당 확인 프레임과 원본 표 경계가 인증된 일회성 재개에만 사용한다. 일반 저장 이미지의 모호성 검사는 유지한다.
- 클릭 직전 원본 창, 표 경계, 가시 표 전체 픽셀, 실제 지점의 소속과 입력 상태를 다시 확인한다. 확인 중 창이나 표가 바뀌면 재조회나 클릭 없이 중단한다.
- 확인창이 떠 있는 동안 물리 입력 잠금을 잡지 않는다. 사용자 확인 후 전면화와 지점 검사를 수행하고, 더블클릭 실행기는 물리 입력 잠금 안에서 다시 검증한다.
- 기존 조회를 재실행하지 않는다. 실패 시 `result_geometry`에 숫자로 된 경계 진단을 남긴다. 표 요소 힌트는 재사용하지만 장비ID와 이번 셀 이미지를 다음 실행의 고정값으로 저장하지 않는다.

## 검증 범위

시험 앱은 실제 WPF 창에서 입력, VIEW, 그려진 결과 표, 상세 Comment, Exit를 제공한다. 표의 UIA 경계만 창 오른쪽보다 107px 크게 보고하도록 했다. 표 문자는 UIA에 노출되지 않는다. 입력값마다 행과 열 위치를 바꿨다.

WPF의 기본 Offscreen 속성은 Boolean이므로 `None` 조건은 시험 작업자의 해당 표 ID에만 주입했다. 회사 FX 제공자를 직접 시험한 것으로 보지 않는다. 확인창 조작은 시험 드라이버가 수행하므로 시간에 사람의 판단과 입력 대기 시간은 포함되지 않는다.

기존 0.4.27에서는 첫 VIEW 이후 `result_review_unavailable`로 멈추는 것을 재현했다. 상세 창 열기와 Exit는 0회였다. 수정본의 네이티브 큰 경계 시험과 별도 프로세스 재개 시험은 서로 다른 값 3개에서 VIEW, 상세 창 열기, Comment 읽기와 Exit를 각각 한 번 수행했다.

최종 통합 시험은 큰 표 경계, `IsOffscreen=None` 주입, 다른 열의 동일 값 조건을 동시에 적용했다. 첫 실행은 확인창을 마치기 직전에 시험용 다른 창을 앞으로 올려 실제 대상이 가려진 상태에서도 검증과 더블클릭 전에 전면화되는 것을 확인했다.

| 실행 입력 | 일치 행 / 열 | 전체 | 결과 확인 준비 | 재개 | 결과 |
|---|---|---:|---:|---:|---|
| LAB-42 | 2 / 1 | 7.826초 | 5.0395초 | 1.978초 | 완료 |
| LAB-73 | 1 / 0 | 2.972초 | 0.0319초 | 2.188초 | 완료 |
| PART-A | 2 / 1 | 3.019초 | 0.0325초 | 2.187초 | 완료 |

행과 열은 시험 fixture 인덱스다. 전체 시간에는 별도 실행 프로세스 시작과 시험 드라이버의 로컬 확인창 조작이 포함된다. 결과 확인 준비 시간은 `result_observation.elapsed_seconds`이며 전체 조회 단계나 사용자의 확인 대기 시간과 다르다. 처음은 UIA 결과 대기 약 5초를 포함한다. 다음 실행은 기존 표 요소 힌트로 바로 연결한다. 모두 `prior_steps_replayed: false`였고 VIEW, 상세 창 열기와 Exit는 각 1회였다. 잘못된 행이나 열, 업무 실행 버튼 클릭은 0회였다.

근거: `.build/partial-grid-20261123/candidate-combined-resume-b/measurements.json`, `query-*.json`, `resume-*.json`, `ui-*.json`. 별도 실행 없이 같은 호출에서 이어가는 경로도 3개 값으로 완료했으며, 큰 경계를 사용하지 않는 기존 fixture에서도 완료했다.

재현 명령:

```powershell
python -X utf8 -B tools/smoke_registered_result.py <수정본-ZIP> <별도-시험-폴더> --drive-review --separate-review --oversized-grid --unknown-offscreen --duplicate-column-value --cover-during-review --repeat 3
```

테스트는 원본 표 경계 변경, 겹침 없음, PNG 크기 불일치, 가시 표 픽셀 변경, 최소화, 다른 창과 보호 요소, 확인값과 열 불일치, 잘못된 재개 지점, 확인 콜백 없는 물리 입력을 거부하는 경우도 포함한다.

전체 Windows 회귀 검사: `python -X utf8 -B -m unittest discover -s tests -v` — **1,259개 통과, 37.639초**. 기록: `.build/partial-grid-20261123/full-regression.log`.

## 운영 적용 시 구분

이 수정은 UIA에 없는 문자를 새로 제공하거나 녹화 당시 이미지를 다른 장비ID의 증거로 바꾸지 않는다. UIA로 읽히는 표는 현재 입력값으로 자동 비교하고, 읽히지 않는 표는 현재 열과 셀을 확인한 뒤 이어간다. 회사 FX의 실제 조회부터 Exit까지 완료 여부는 회사 PC에서 수정본으로 별도 확인해야 한다.
