# Desktop Select 0.4.8 검증 기록

2026-11-14에 실제 DBeaver와 별도 Windows 시험 앱에서 확인한 기록입니다. 회사 FX와 FarPoint 제공자에서 직접 시험한 결과가 아닙니다.

## 시험 환경

- Windows의 실제 DBeaver Community 26.2.4와 공식 Office 확장을 사용했습니다.
- 별도 작업 공간의 SQLite에 만든 가상 데이터 10행만 사용했습니다. 기존 업무 DB에 연결하지 않았습니다.
- DBeaver의 조건 입력란은 텍스트 필터입니다. FX처럼 콤보 두 개를 선택하는 화면과는 다릅니다. 콤보 호환성은 별도 Windows 시험 앱으로 검사합니다.
- 실제 앱의 메뉴는 `Export data` 다음 XLSX 내보내기 마법사입니다. FX의 중첩 `EXPORT → EXPORT TO EXCEL`과 구분합니다.

## 재현해서 수정한 부분

| 문제 | 변경 |
|---|---|
| 웹 화면이 섞인 데스크톱 트리의 다른 프로세스 때문에 전체 관찰 실패 | 다른 프로세스의 내용은 읽지 않고 경계를 남기며 호스트의 관찰을 계속합니다. 관찰 깊이는 32, 노드 수 제한은 그대로 유지합니다. |
| SWT 입력란에 이름이 없고 숫자 ID만 존재 | 현재 이름 있는 영역과 상대 위치, 요소 종류와 클래스로 다시 찾는 selector를 추가했습니다. 위치는 요소를 찾는 힌트이며 임의 좌표 입력 명령이 아닙니다. |
| 숫자 ID가 앱 재시작 뒤 바뀜 | 대상과 조상의 숫자 ID를 영구 식별자로 승격하지 않습니다. 고유 이름이 없으면 자연어 검색을 유지합니다. |
| 우클릭 메뉴는 열리지만 메뉴 항목을 못 찾음 | 일반 소유자 관계가 없는 표준 Win32 메뉴도 실제 GUI 스레드의 메뉴 소유자를 확인해서 찾습니다. 다른 창의 메뉴는 포함하지 않습니다. |
| 메뉴마다 전체 화면을 다시 읽음 | 주 창의 메뉴 항목은 native 검색을 사용합니다. 팝업의 범위 및 최종 입력 대상 검사는 유지합니다. |
| 이름 없는 입력란을 같은 동작 안에서 반복 검색 | 한 동작의 최초 검색에서 확인한 UIA 요소를 유지하고 이후에는 그 요소의 현재 소속, 보호 상태, 위치와 실제 hit를 검사합니다. 다음 동작이나 실행에는 다시 찾습니다. |
| 조회 필터는 값을 넣어도 Enter를 눌러야 적용됨 | 지정한 편집란의 포커스를 확인한 후 Enter 한 쌍만 보내는 `submit`을 추가했습니다. 임의 키나 실패 후 재입력은 지원하지 않습니다. |
| 내보내기 설정창이 나중에 열려 사전 등록할 수 없음 | 미래의 소유 팝업 단계를 등록 시 미확인으로 보존하고 실행 때 정확한 제목과 소유 관계를 확인합니다. |

## 현재 확인한 결과

- 전체 단위 시험 655개 통과.
- 배포 ZIP을 새 폴더에 설치한 Windows 콤보/입력 변수 시험 20개 통과. 고정 콤보값, 실행 시 받는 콤보값과 일반 문자열, 조회/내보내기 호출 후 실제 XLSX 셀까지 확인했습니다. 회사 FX나 물리 녹화 시험은 아닙니다.
- 최종 ZIP의 같은 Windows 시험 앱에서 최초 등록은 0.4561초, 생성한 Python 스킬의 두 차례 실행은 각각 1.8107초와 1.7507초였습니다. 두 실행 모두 전체 화면 관찰 0회, UIA 연결 1회였습니다. 이 수치는 DBeaver의 우클릭 마법사 흐름 시간이 아닙니다.
- 실제 DBeaver에서 배포 ZIP을 새 프로젝트에 설치하고 `register --recipe`에 해당하는 읽기 전용 등록으로 Python 업무 스킬을 만들었습니다. 등록은 2.7614초, 입력 전송은 없었습니다. 아직 닫혀 있는 내보내기 창의 단계는 미확인으로 보존됐으며 실행 중 실제 소유 창에서 확인했습니다.
- 생성된 `scripts/run.py`에 필터와 파일명을 전달해 전체 흐름을 세 번 실행했습니다. 세 파일 모두 별도로 읽어 헤더, 장비 이름, `Status=N`, 이번 Family, 수량 11/12/13과 데이터 3행을 확인했습니다.
- 최초 전체 관찰은 293노드, 2.9807초였습니다. 최초 폼 검색은 3.0353초였습니다. 앱 시작, 확장 설치, DB 연결 준비 시간은 포함하지 않습니다.
- 다른 앱이 전면을 가져간 첫 시도에서는 Enter 전에 멈췄고 다른 창에 키를 보내지 않았습니다. 입력 전달이 불확실한 경우 자동 재입력하지 않습니다.

## DBeaver 전체 흐름과 시간

순서는 필터 값 설정 → Enter 적용 → 명시적 1초 대기 → 결과 표 우클릭 → Export data → 내보내기 마법사 세 페이지 → 출력 폴더/파일명 설정 → Proceed → 새 XLSX 확인입니다. 처음 XLSX 형식과 `Use fetched rows`를 선택하는 앱 설정은 준비 과정에서 수행했습니다. 반복 실행에서는 이 앱 설정을 사용하며 각 실행의 결과 셀을 별도로 확인했습니다.

| 실행 | Family | 전체 경과 시간 | Excel 내용 |
|---|---|---:|---|
| 1 | DRAM | 16.2621초 | 3행과 수량 일치 |
| 2 | Hybrid | 15.2638초 | 3행과 수량 일치 |
| 3 | DRAM | 13.8279초 | 3행과 수량 일치 |

중앙값은 15.2638초입니다. 위 시간은 생성 Python 스킬의 프로세스 시작부터 결과 반환까지이며 1초 대기를 포함합니다. 앱 시작, 설치, DB 준비, 독립적인 셀 검사는 제외합니다. 필터 설정과 Enter는 각각 약 1.7~2.3초, 우클릭 메뉴는 약 4.4~5.7초였습니다. 최초 한 번의 전체 관찰과 달리 반복 실행은 저장한 영역과 요소를 사용합니다.

최적화 전 성공 실행은 50.9435초, 수정 직후 소스 실행은 15.0624초였습니다. 같은 PC의 관측값이며 앱의 준비 상태와 다른 부하도 달라질 수 있어 통제된 성능 향상률이나 회사 FX의 속도로 일반화하지 않습니다.

## 결과 해석과 범위

실행기의 전체 상태는 `completed_unverified`, 마지막 파일 확인은 `file_verified: true`입니다. 버튼과 Enter 전달만으로 조회 결과를 입증하지 않기 때문입니다. 이 시험에서는 별도 검사로 실제 셀까지 확인했지만, 일반 실행기의 파일 검사가 업무 결과 전체를 증명하는 것은 아닙니다.

물리 녹화 UI에서 모든 단계를 사람이 시연해 등록하는 시험은 이번 DBeaver 검증에 포함하지 않았습니다. 실제 관찰에서 만든 실행안을 등록하고 생성된 Python 스킬의 실행을 시험했습니다. 기존 `result-menu` 녹화의 자동 변환 범위도 이번 literal recipe의 지원 범위와 다릅니다.

초기 DBeaverc 기동 오류는 테스트용으로 풀린 앱 파일이 원본 ZIP과 일치하지 않아 발생했습니다. 원본 ZIP 해시와 재추출한 파일 내용을 확인한 뒤 정상 실행했습니다. DBeaver와 Office 확장은 시험용 앱이며 Desktop Select ZIP에 포함하지 않습니다. Desktop Select ZIP은 27개의 소스/문서 파일이며 EXE, DLL, SYS 또는 CUA 드라이버를 추가하지 않습니다.

최종 ZIP으로 Windows 조회/중첩 메뉴 시험 12개가 통과했습니다. 정상 결과, 픽셀 완료 표시, 조회 미완료, 이전 결과 잔존, 파일 미생성 상황을 확인했습니다. 별도 WinForms 시험에서도 없는 메뉴 경로는 내보내지 않고 멈추며, 창을 옮긴 뒤에는 현재 표 위치에서 우클릭과 내보내기를 각각 한 번만 실행했습니다.

## 배포 구성

[Desktop Select 0.4.8 릴리즈](https://github.com/bongG-moon/agent-desktop-workflows/releases/tag/desktop-select-v0.4.8)에 Windows ZIP, 같은 내용의 한국어 사용 가이드, `SHA256SUMS.txt`를 제공합니다. 다운로드 파일에는 시험용 DB, 업무 스킬, 실행 기록, DBeaver 또는 테스트 앱 실행 파일이 포함되지 않습니다. 핵심 브리지와 녹화기의 0.4.0 바이트 검증은 유지했습니다.

단순 대기는 조회 완료의 증거가 아닙니다. `verify-file`은 새 통합 문서의 생성을 확인하며, 조회 조건에 맞는 행인지는 앱별 결과 검증이 필요합니다. 이름 없는 입력란의 영역 배치가 바뀌면 지정 위치도 다시 확인해야 합니다.
